# 项目定位与业务背景

## 是什么

本地单机销售/退货/拿货/退拿货开单、客户商品资料与账款系统，面向消防器材门店。
Flask + SQLite，可选 Windows PyWebView 桌面壳，**只在 Windows 运行**（WSL 只通过盘映射做可选交叉测试）。

- 正式目录 = 本仓库根（唯一真源）
- GitHub `Astyyym/simple-erp`，默认分支 `main`
- 版本以根目录 `VERSION` 为准

## 门店真实使用场景（直接影响需求判断）

- **高频用销售单、退货单；拿货/退拿货基本不开**（功能保留，但不要当主路径去优化）。
- **对账方式**：打印客户账单，与对方账目相减；周期不固定（一个月 / 20 天 / 3 个月都有），不是固定月结。
- **迁移承接口径**：旧软件的历史单据**不导入**，只把截至迁移日的**未结欠款**落到客户期初余额；欠款明细不进系统。
  - 依据：`开发短计划/2026-10-08_旧数据迁移承接与备份恢复_执行计划.md`（第 19 行）

## 已确认的业务口径（长期）

- **售价唯一来源 = 开单学习出的客户专属价**（2026-10-15 用户决策）：商品档案不再有「默认价」
  ——建档/编辑/导入/导出/列表/回收站都不再有该字段；客户对该商品有专属价则开单自动带出，
  没有则单价**留空**手输。手输价 **> 0** 就写为该客户对该商品的专属价（0 元不学）；
  换客户时按新客户重取，新客户没有专属价就**清空**（不保留上一个客户的价）。
  依据：`开发短计划/2026-10-15_商品售价来源收敛与专属价查看_执行计划.md`。
- **无库存、无成本**（2026-10-16 用户决策，schema v15 物理删除）：
  库存三表（`inventory_postings` / `inventory_initializations` / `product_inventory_state`）与 9 个成本/期初/安全库存列
  （`order_items` 三列、`products.default_price_cents` 与 `safety_stock_3dp`、`purchase_return_items` 三列、
  `purchase_return_orders.posted_once`）已删除。**老库升级不可逆**：不能再用 v3.15.0 及更早程序打开 v15 库，
  回退只能靠迁移前自动生成的整库备份。
  四类单据除「已作废」外都可编辑（编辑锁全撤）；拿货/退拿货保留为纯流水单据（单据、NH 单号、打印、
  对账并入、账款抵扣、回收站、当天历史照旧）；导入不再接受「期初数量 / 期初成本」列，含这两列的文件整表报「表头错误」。
  依据：`开发短计划/2026-10-16_删除库存系统_执行计划.md`。
- 商品管理列表「专属价」列是查看入口，「编辑」按钮文案为「查看详情」；编辑页有「客户专属价」卡片。

## 已确认的界面约定（长期）

- **列表行操作：动作全部平铺可见，不用 ⋯ 折叠菜单**（2026-11-14 用户决策）。
  - 语义：列表页每行的操作（单据：查看 / 编辑 / 打印 / 删除；商品：查看详情 / 删除）本身就是高频动作，
    收进 ⋯ 要多一次点击才能看见，且和真实页不一致。此前原型里的「收进 ⋯」是原型的臆造，非用户要求。
  - 依据：`app/erp/templates/orders/list.html:153` 与 `products/list.html:117` 的 `.action-wrap` 结构。

- **行操作按钮用无描边纯文字 + 悬停淡底，不加描边**（2026-11-14 用户决策）。
  - 理由：描边会强化视觉权重，把注意力从单号/往来对象这些正文内容上抢走。
  - 语义靠文字颜色区分：普通动作蓝色，删除红色；悬停才出现淡色底与描边。

- **行操作用密集尺寸压缩占宽，不要靠折叠省空间**（2026-11-14 实测）。
  - 实测基线（真实页 1440 视口）：`.stable-table .action-cell` 声明 380px、实际 274px（占表宽 26%）；
    每个按钮 `min-width:60px`，4×60 + 3×6 = 258px 已超出可用内容宽 246px，**本来就溢 12px**，
    仅因 `overflow:hidden` 裁在按钮右边缘而肉眼不可见。依据：`app/erp/templates/base.html:346`。
  - 采用值：按钮 45×26px、间距 2px、操作列 196px（占表宽 17.7%），1440→1100 各档视口全部不越界。
  - 关键点：**去掉的是按钮的 `min-width:60px` 硬撑**，不是减少动作数量。
