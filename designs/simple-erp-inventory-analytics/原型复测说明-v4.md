# 双向往来与分析 v4 原型复测

**阶段：待布局审查。仅虚构内存数据，不接 ERP API、SQLite、实际收付款或正式打印。刷新、切换样例可重置模型；不要录入真实私密资料。**

入口：同目录 `counterparty-layout-prototype-v4.html`，需 HTTP 服务（不要直接双击，模块脚本需要 HTTP）。本次右侧预览已打开。顶部“页面”选择器在窄预览中也能切换模块。

## 三条主要路径

1. **分析布局**：查看筛选 → 五项核心指标 → 往来对账入口 → 完整三页签分析模块 → 具体产品分析表。“销售热力图 / 产品排行 / 成本诊断”及内容整块在前，商品标题/排序/表格/口径说明整块在后。年份只影响热力图，不缩小顶部汇总的业务日期范围。不同单位不汇总数量。
2. **往来对账**：进入后选择“演示往来对象甲”并查询。初始64笔有效虚构单据，每页50笔，默认选全部结果而不是当前页；取消一笔、切到第二页再取消、返回第一页面检查。可看每单商品明细，预览只含所选整单及公开交易字段，返回保留选择。净额是四类交易方向的核对结果，不是应收/应付欠款；不会生成付款、退款或抵销记录。
3. **来源退拿货**：选“演示往来对象甲”，原单 `NH202609040001`。第一行 DN65 退量填 `1`，计算金额应为业务退款 `72.00`、预计库存出库成本 `80.00`。演示保存后该行可退量从18变17、当前库存从22变21；旧销售利润不变。再次交易会让旧对账选择失效，需重新查询。

## 拿货与边界

- 拿货使用同一对象档案；选 DN65、数量 `2`、拿货单价 `90`，正式演示仅增加内存库存。单价独立录入，不改销售价/客户价；内部货源备注不进入外部样张。
- “草稿”不入库、不扣库存、不占来源可退额度；正式演示保存会重新校验。
- 对象乙的原单 `NH202609140003` 对应零库存商品，尝试正式退 `1` 应拒绝库存不足，不能部分过账。
- 不自动从历史货源备注推断对象；未关联拿货不纳入对象对账。
- 顶部可切浅/深/跟随系统及成本缺失、空数据、历史计件小数样例；可见金额两位，内部微元与数量计算精度独立。

## 验证与剩余阶段门

模块对调后22项前端自动测试通过，其中新增完整卡片顺序回归；此前7组独立浏览器场景和1440/1100/600视口证据属于对调前基线，不冒充对调后整体验收。后端真实保存、迁移、幂等/并发、回收站/末笔作废、正式 A4 PDF、EXE和实体打印属于后续生产切片，**本原型不提供这些能力**。

人工审查只需确认本轮页面结构、交易方向、成本分列和主要操作顺序；原型状态仍 `needs-review`。确认后再进入C1拿货关联、C2退拿货生命周期、C3双向对账/PDF和C4正式分析接入。
