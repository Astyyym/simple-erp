- 日期：2026-10-14
- 状态：**已完成（源码 + 自动化测试 + 隔离实例真实浏览器几何与截图）**；未打包、未升版、未提交/推送，桌面壳（WebView2）未验

- 上游对照物：`docs/原型/档案编辑页主次与分组.html`（用户已看过并确认方向）

## 一、目标

商品/客户编辑页在 1706×898（`ui_scale=125`，即用户真实窗口）下**首屏放得下**，主次分明、按功能分组。

实测基线（真机，正式库副本 + scratch 数据根，未碰 `data/erp.db`）：

| 页面 | 内容高 | 首屏可视 | 问题 |
|---|---|---|---|
| 商品编辑（待补全态） | **1457px** | 810px | 要滚 647px；「保存」top=858px → **打开页面看不见主操作** |
| 客户编辑（待补全态） | **579px** | 810px | 不滚；表单只占内容区 48% 宽，右侧 720px 全空 |

商品页区块流水：`页头 40 → 待补全横幅 57 → 只读库存卡 193 → 表单 456 → 商品图片 141 → <hr> → 库存期初 368`。

三条根因：
1. **主次颠倒** —— 只读的「当前库存与成本」卡占首屏最贵的 193px，唯一要用户做的事（补品牌）在第 396px。
2. **一列到底 + 宽度不齐** —— 5 个字段各独占一行 ×83px；`col-6`=661px、`col-8`=881px、卡片 1321px，**三种右边缘**。
3. **低频重块常驻展开** —— 库存期初 368px（6 输入框 + 成本来源 + 备注 + 勾选），门店一年用一次。

## 三、目标布局

### 商品编辑页

```
页头：编辑商品  [chip 待补全 · 缺品牌]                        [返回商品管理]
┌────────────────────────────────┬──────────────────────┐
│ ① 基本信息（主表单）             │ ③ 当前库存与成本（只读）│
│   商品名称        [整行]         │   当前库存 / 移动平均成本│
│   品牌⚠ 单位 默认单价 安全库存    │   库存金额 / 启用状态    │
│   [保存]                         │   库存状况              │
│ ② 商品图片（独立表单）           │ ④ 库存期初 ▸ 折叠       │
└────────────────────────────────┴──────────────────────┘
```

- 左栏 `1fr`、右栏 `320px`，`align-items:start` → 页面高度取两栏较高者，不再相加。
- 字段流仍是**一列**（NN/g / Baymard / USWDS 一致反对多列表单）；组内只让**短且语义成对**的 4 个字段同行（品牌/单位/默认单价/安全库存），商品名称独占整行。
- 窄容器回落到 2 列（容器查询，按主栏实际宽度判定，不按视口）。

### 客户编辑页

只有 4 个字段、页面上没有任何可读派生数据 → **不硬塞侧栏**，改「一卡两段」：卡片铺满内容区宽度，段标题「基本信息」「账款」。

- **高度基本持平，本计划不承诺变短**：省下横幅 57px ＋ 电话/地址合行 ~80px，被分组标题与卡片内边距 ~130px 抵消。
- 这页要解决的是**空**（宽度利用率 48% → 100%）和**没有分组**，不是长度。

### 两页共用

- 「待补全」从 57px 横幅降级为**页头 chip ＋ 字段上的 ⚠ 标记**；判定口径仍走 `services/master_data_quality.py`，**一个字不改**。
- 「保存」留在主表单卡片底部右侧（商品页有 3 个独立表单，页头放单个「保存」会产生歧义）。
- 卡片同宽：不再 `col-6` / `col-8` 混用，右边缘收敛成一条。

## 七、验收标准

1. 1706×898 / `ui_scale=125`：两页内容高 **≤ 810px**（不滚动），「保存」按钮**首屏可见**。
2. 右边缘收敛：**主栏内所有卡片右边缘一致**，侧栏卡片右边缘 = 内容区右边缘。取值从原来的 **3 种**（表单 661 / 图片与期初 881 / 卡片 1321）收敛为 **2 种**（1308 / 1646），且这 2 种就是两栏的边界 —— 不再是「三种宽度各排各的」。
   （初稿把这条写成「所有卡片右边缘完全一致」，在双栏布局里不成立，已更正。）
3. 待补全记录：页头有 chip、对应字段有 ⚠；非待补全记录：两者都不渲染。
4. 期初表单的所有 `name` 与取值不变；折叠只影响可见性，不影响提交。
5. 全量 pytest 通过，`0 failed`。
6. 交付层：源码 + 隔离实例真实浏览器几何/截图。**不含**打包、发版、桌面壳（WebView2）验收。

## 八、停止条件

- 任一阶段全量 pytest 出现 `failed` 且不是本计划 §六 列出的两处 → 停下报告，不继续下一阶段。

## 九、风险

- **客户页高度不降反升的风险**：分组标题 + 卡片内边距可能吃掉省下的横幅。已在 §三 明说「不承诺变短」，验收标准只对商品页钉死 ≤810px。
- **`<details>` 折叠与提交**：原生 `<details>` 收起时内容仍在 DOM 与表单内，会随提交；但**三个表单各自独立**，期初表单折叠后用户看不到「启用期初库存」按钮 → 摘要行必须写清「点此设置」。
- **WebView2 与 Chrome 渲染差异**：本轮只在 Chrome 验，桌面壳需另验；容器查询 `@container` 在 WebView2（Chromium 105+）支持，但仍需实机确认。
- **可访问性**：chip 与 ⚠ 是视觉提示，`<details>`/`<summary>` 原生可键盘操作；⚠ 用文字而非纯色，不依赖颜色单一信号。

## 十、实测结果

环境：1706×898 CSS px、`ui_scale=125`（用户真实窗口），正式库**副本** + scratch 数据根，全程未碰 `data/erp.db`。

| 页面 | 改前内容高 | 改后内容高 | 首屏可视 | 结果 |
|---|---|---|---|---|
| 商品编辑（待补全态） | 1457px | **713px** | 810px | **不滚动**；「保存」top 858 → **438px**，首屏可见 |
| 商品编辑（期初展开） | — | 1030px | 810px | 主动展开低频表单后才需滚 220px，可接受 |
| 客户编辑（待补全态） | 579px | **709px** | 810px | 不滚动；**高度 +130px**，见下 |

其余实测项：

- **右边缘收敛**：主栏两张卡片右边缘均 **1308**，侧栏卡片 **1646** → 取值 3 种（661/881/1321）收敛为 2 种，且这 2 种就是两栏边界。
- **字段网格**：主栏 983px 时 4 列（224.25px × 4；品牌/单位/默认单价/安全库存 等宽，左边缘 344/584/825/1065）；视口 1000px 时经 `@media(max-width:1100px)` 回落单栏；1200 / 1706 横向溢出均为 **0**。
- **待补全提示**：商品页 chip「待补全 · 缺品牌」+ 品牌字段 1 个 ⚠；客户页 chip「待补全 · 缺联系方式」+ 电话/地址 2 个 ⚠；非待补全记录两者都不渲染（`origin` 为 `manual` 时）。
- **期初折叠**：摘要「库存期初　未启用 · 点此设置」，默认收起；折叠内容仍在 DOM 与所属表单内，提交的 `name`/取值与原版一致。
- **深色主题**：chip `rgb(251,191,36)` on `rgb(58,47,20)`、边框 `rgb(107,82,23)`；只读值 `rgb(222,226,230)`；页面底 `rgb(15,20,29)` —— 无浅底浅字。
- **自动化测试**：全量 pytest **1006 passed / 16 skipped / 0 failed**（基线 1005，+1 为新增的客户编辑页提示测试）。

**一处证伪留痕**：视觉复核时曾报「品牌输入框比右侧三个窄、有缩进」，逐元素量测证伪 —— 四个输入框均 224px、左边缘 344/584/825/1065，等宽对齐。以量测为准，未按视觉结论改代码。

**客户编辑页高度 +130px 的说明（不掩饰）**：这一页原本就不滚动，问题是「空」（表单只占内容区 48% 宽）。改造换来分组与满宽，代价是分组标题与卡片内边距。期间试过「一卡两段」（688px）与「一卡两组」（709px）两版，取后者与商品页「一卡一组」的范式一致。若要求这一页也必须比原来短，唯一有效的手段是砍掉分组本身 —— 与本次目标冲突，故未做，留作可选项。

**分层状态**：源码 ✅ / 自动化测试 ✅ / 隔离实例真实浏览器几何与截图 ✅ / 打包 ❌ / 发版 ❌ / 桌面壳 WebView2 ❌（未验）
