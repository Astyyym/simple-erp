# 2026-10-15 开单取价随客户走 + 退货来源候选放开成本门槛 执行计划

## 目标（用户 2026-10-15 两项指令）

1. 「检查一下，现在四类开单页的商品输入，没有当前客户的历史价格？」——查证后修复：同一商品 A 客户 80 元、B 客户 85 元要能自动带到单价栏。
2. 「而且我也不能关联以往的销售单据了」——查证后放开：无成本快照的销售单**也进退货来源候选**，标注「无成本，仅追溯」，关联后按手输退货保存。

非目标：不改打印纸型与计价口径；不动库存/成本算法本身。
（注：本计划落盘时范围只到代码修复；用户随后明确要求升版 v3.14.0、一次出三种产物并 commit / push / 建 Release，那部分执行证据记在根目录 `CHANGELOG.md` 的 v3.14.0 条目。）

## 查证结论（先取证再改，隔离库 + headless Chrome 实测）

种数据：商品「干粉灭火器4kg」档案默认价 100，甲成交 80，乙成交 85。

修复前实测：

| 场景 | 结果 |
|---|---|
| 先选客户 → 点商品 | 80 ✅（功能本就存在） |
| 先点商品 → 再选客户 | 100 ❌ 不刷新 |
| 已填行/编辑页后换客户 | 不变 ❌ |
| 拿货页（供应商=甲） | 出现「客户价 80」❌ 语义串了 |

根因：`refineProductRow()` 只在点选商品那一刻读一次 `customer_id`，页面**没有任何**往来对象变化的重算入口（全库搜不到客户框的 change/input 监听）。
关联退货方面：候选只列「明细带成本快照」的销售单，这道门槛自 **v3.1.0**（`c912fe9`）就在、逐版本判定条件未变；v3.12.0（`b5df1ee`）只新增了「另有 N 张…」提示文案。自 2026-10-13 起关联已降级为「只作追溯」，门槛却仍按成本分摊的前置条件把关，故旧单选不到。

## 关键决策（用户逐条选定）

1. 换客户即按新客户价**重写所有已命中档案的行**，不保护手输过的值（用户明确选择「完全跟着客户走」）。
2. 先点商品后选客户的顺序问题一并修（客户一变就重算，顺序自然无关）。
3. 拿货/退拿货页**摘掉客户价**：其单价语义是入库成本，而原先借用 `/orders/api/products?customer_id=…` 取到的是「该往来对象作为**客户**时的售价」（客户与供应商共用 `customers` 档案）。
4. 无成本单进候选 + 标注「无成本，仅追溯」，保存走手输路径（本次实施）。

## 改动文件

- `app/erp/static/order-entry-common.js`：新增并导出 `onCounterpartyChanged(input, cb)`。hidden 输入框被脚本赋值时 `input`/`change` 都不触发、MutationObserver 也看不到 `value`，故采用「值指纹 + 200ms 轮询 + `erp-counterparty-change` 自定义事件立即提交」。
- `app/erp/templates/orders/new.html`（销售/退货/编辑共用）：
  - `repriceRowsForCustomer()` 订阅往来对象变化，按档案规范名重查取价；
  - `repriceSeq` WeakMap 请求序号守卫，防旧响应覆盖新结果；
  - `sourceTraceOnly` 标记：成本齐备的原单带入行**不**重算（承诺按原成交价退），仅追溯的关联**放行**重算；`hidePreview()` 复位；
  - 原单候选标注 `无成本，仅追溯`；`sourceLinkNote()` 按两种语义分别措辞，不再一律写「不影响计价规则」；
  - 既存渲染缺陷修复：`source_item_id` 为 NULL 时被 Jinja 渲染成字符串 `"None"`（前端误判为原单带入行，编辑提交还会把 `"None"` 当明细 id 送 `int()`）→ 改为 `or ''`；
  - 共享 JS 版本号 `?v=2/v=1` 统一提到 `?v=3`（防 WebView2 旧缓存）。
- `app/erp/templates/purchases/new.html`、`return_new.html`：`refineProductRow` 改为纯本地目录取价（`renderPriceQuick` + `priceYuan`），不再借用客户价接口。
- `app/erp/routes/purchases.py`：`_products()` 与 `/purchases/api/products` 的 SQL 补 `p.default_price_cents`（漏加会 500）。
- `app/erp/routes/orders.py`：新增单一口径 `RETURN_SOURCE_COST_READY_SQL` + `_source_order_cost_ready()`；候选不再过滤、附 `cost_ready`；创建与编辑两条路径按成本是否齐备分流（不齐备强制走手输，`source_order_id` 仍记在单上）；详情预览接口 `cost_ready` 转真布尔。
- 测试：新增 `tests/test_order_entry_customer_reprice.py`（3）、`tests/frontend/order_customer_reprice.test.mjs`（5）；改写 `test_return_source_linkage.py`（候选放行、缺成本可存、成本齐备仍分摊、缺成本草稿可再编辑并正式保存）、`test_purchase_entry_unified.py`（拿货页无客户价）、`test_cost_backfill.py`（补录语义改为「从仅追溯升级为可分摊」）。

## 风险与回退

- 换客户重写单价会覆盖用户手输值（用户已知并选定）。回退点：把 `repriceRowsForCustomer` 改为仅提示不写入，或在重写前比对手输标记。
- 候选放开后，缺成本单的退货成本口径改为「当前移动平均」，与逐行分摊不同；页面已用 `sourceLinkNote()` 明示，避免误认为按原单成本。
- 200ms 轮询常驻开单页（单次仅比一个字符串），如后续介意可改为在 `bindAutocomplete` 的三处赋值点显式派发事件。
