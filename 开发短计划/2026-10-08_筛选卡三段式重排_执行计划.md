# 2026-10-08 筛选卡三段式重排（单据管理 / 数据分析）— 执行计划

> 状态：`已完成（源码 + 自动化测试 + 隔离页面验收层）`。桌面 EXE、实体打印、深色矩阵不在本轮范围。
> 目标：把两页顶部筛选卡从「一个 4 等分平铺网格」改为**三段式**（先出静态原型 `docs/原型/单据与分析筛选排列.html`，用户确认「就按照这个改」后再落地）。
> 范围：只改筛选卡的**结构与呈现**，未改任何筛选口径、路由参数语义、导出端点、打印版式、数据库或版本号。

## 背景与已确认方向

用户反馈单据管理、数据分析两页顶部筛选条件多、排列不够清楚。原型采用成熟产品（SAP Fiori FilterBar / Stripe / GitHub Issues）共同原则：**时间单独成组常驻、低频条件降权、已选条件 chip 化可见可删**。

## 最终三段式结构（两页共用同一套 `.filter-card`）

```
① 查询三要素（常驻）
   时间范围 = 模式按钮 + 对应日期输入【同一组合控件 .filter-field-composite】 | 客户/商品/型号
② 条件多选（降权，虚线分隔）
   订单类型：标签 + 四类复选框 + 清空       单据状态：标签 + 四态复选框 + 清空
③ 已选条件 chip 行（可单独 × 移除）+ 动作条（主操作在左，导出/重置贴右）
```

## 实际改动

- `app/erp/utils/filter_chips.py`（新增）：`removal_url()` + `order_filter_chips()` + `analytics_filter_chips()`。
  - 时间不生成 chip；「不勾选=全部」与「全选=全部」等价 → 四类全勾 / 无选择都不生成 chip。
  - 商品 chip 移除时同时清 `spec`（型号从属商品）。
- `app/erp/templates/base.html`：`.filter-card` 由 4 列网格改为 flex 三段（`.filter-tier-query` / `.filter-tier-conditions` / `.filter-chips` / `.filter-actions`）；新增 `.filter-field-composite` / `.filter-field-plain`。
- `app/erp/templates/orders/list.html`：改三段式；时间模式与日期面板合成一个组合控件；删除类型/状态两组「全选」按钮与对应 JS。
- `app/erp/templates/analytics/index.html`：同上；字段沿用（客户 / 商品 / 型号）。
- `app/erp/routes/orders.py`：`render_template` 传 `filter_chips=order_filter_chips(...)`。
- `app/erp/routes/analytics.py`：传 `filter_chips=analytics_filter_chips(...)`；新增 `_customer_name()` 供客户 chip 显示名称。
- 测试：更新 `test_order_list_filter_layout.py` / `test_ui_layout_reflow.py` / `test_analytics_v4_behavior.py` / `test_orders_type_filter.py` / `test_analytics_center.py` 中编码旧 4 列网格与「全选」的断言；新增 `tests/test_filter_chips.py`。
