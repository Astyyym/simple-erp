## 一、背景与结论

用户使用的打印机为 **Nantian PR2 Plus**，Windows 驱动显示为 `NantianPR-LQ`，驱动仅公开 A4 纸型。实体二联纸约为 **241×140mm**，打印时 **241mm 长边先进**。

对秒账原始打印预览 `XS202607140002.pdf` 与其“Microsoft Print to PDF”纵向/横向输出实测后确认：

| 现象/数据 | 结论 |
|-----------|------|
| 秒账原始 PDF MediaBox | **612×396pt** |
| 秒账原始 PDF 毫米尺寸 | **215.9×139.7mm（8.5×5.5 英寸）** |
| 秒账原始 PDF 旋转标记 | `Rotate=0`，源文件未旋转 |
| 秒账内容实际宽度 | 约 **201.37mm** |
| 秒账 PDF 内部左右边距 | 约 **7.3mm** |
| Microsoft Print to PDF 横向输出 | A4 横向 297×210，源页面按原尺寸居中 |
| Nantian 驱动 | 只公开 A4；不能把实体纸尺寸直接当作驱动纸型 |

**关键修正：实体纸尺寸不等于销售单 PDF 逻辑页面尺寸。**

秒账的物理对齐关系约为：

```text
实体纸宽 241mm
  - 逻辑 PDF 宽 215.9mm，打印机居中后两侧各留约 12.55mm
  - PDF 内部两侧各留约 7.3mm
  - 实体纸到正文两侧总留白约 19.85mm

正文宽约 201.3mm
```

此前 v0.7.0 将销售单 PDF 直接设为 241×140mm，虽然 PDF 预览中的正文宽度正确，但与 `NantianPR-LQ` 的 A4 打印映射不一致，是“PDF预览正常、系统打印预览/实打异常”的主要原因。

**本轮拍板：**

| 项 | 值 |
|----|-----|
| 实体纸 | **241×140mm**，241mm 长边先进 |
| 销售单 PDF 逻辑页面 | **215.9×139.7mm** |
| PDF 内部左/右边距 | **7.3mm** |
| PDF 正文宽度 | 约 **201.3mm** |
| 打印方式 | A4 横向、实际大小/100%、页面居中 |
| 页面旋转 | PDF 源文件不旋转，`Rotate=0` |
| 校准 | 保留 `print_offset_x_mm`、`print_offset_y_mm`、`print_scale` |

## 二、实现原则

1. **区分实体纸与逻辑 PDF 页面。**
   - `printer_paper_width_mm=241`、`printer_paper_height_mm=140` 继续表达实体纸。
   - 新增销售单 PDF 逻辑页面配置，默认 `215.9×139.7`。
2. 销售单 `@page` 与 `.page` 使用逻辑页面尺寸，不再直接使用实体纸尺寸。
3. 版心左右改为约 `7.3mm`，正文宽度保持约 `201.3mm`，避免为了改纸型重新压缩列宽。
4. 设置页明确写出：实体纸241×140、PDF逻辑页215.9×139.7、A4横向、100%、居中、长边先进。
5. 保留现有偏移/缩放校准，但默认仍为 `0 / 0 / 1.0`，不得用大偏移掩盖纸型错误。
6. 设置预览与正式订单 PDF 继续共用 `orders/print_template.html`。
7. 本轮先验证“模仿秒账逻辑纸型”路径；不同时引入 Windows GDI 原生打印，避免两个变量一起变化。

## 四、验收标准

1. 配置同时存在：
   - 实体纸 `241×140mm`
   - 销售单 PDF 逻辑页 `215.9×139.7mm`
2. 设置预览与正式订单 PDF 的 MediaBox 均约为 `215.9×139.7mm`，`Rotate=0`。
3. PDF 内部正文左右边距约 `7.3mm`，正文/表格宽度约 `201.3mm`。
4. 渲染 PNG 目视检查：标题、表格、合计、页脚无裁切、重叠或乱码。
5. 相关打印与设置测试通过，完整 pytest 通过。
6. 项目文档不再把“实体纸241×140”写成“销售单 PDF 必须241×140”。
7. 用户真机验收：A4横向、实际大小/100%、居中，241mm长边先进；打印结果与秒账位置接近。
