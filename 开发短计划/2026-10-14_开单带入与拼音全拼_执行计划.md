> 用户诉求来源：2026-10-14 两张退拿货页截图 + 三条文字反馈；决策答复见 §二。
> 前置计划：[2026-10-13 开单四项体验修复](./2026-10-13_开单四项体验修复_执行计划.md)（关联框可检索、`openOnClick`、单位控件即在该批落地，本计划在其成果上继续，不推翻）。

## 一、来源与目标

| # | 用户诉求 | 实测根因（已取证） | 批次 |
|---|---|---|---|
| 1 | 点「按预览带入商品行」多次会插入多次 | `previewApply` 点击处理无状态：每次点击都「写 `tbody.rows[0]` + 追加 N-1 行」→ 点两次插两套重复行；且无条件复用第 0 行会**静默覆盖用户已手输的那一行** | **P1** |
| 2 | 选完原单后点输入框，只列出已选那一张；换单后下方预览不消失 | ① 打开候选有两条路径、规则不一致：`focus` 按输入框当前值（=已选标签）查询 → 只命中它自己；「刚选过 → 空查询」只写在 `click` 分支且带 `if (isOpen()) return` 早退 → **第一次点击的结果取决于接口快慢**；② 来源框没有 `onInputChange`：改了字只要没从候选里选，隐藏域与预览仍是旧单 | **P2** |
| 3 | 拼音只匹配首字母，中文只有打出汉字才匹配 | `utils/pinyin.py` 用 `Style.FIRST_LETTER`，库里只有首字母：`xf`/`XFS` 命中，`xiaofang`/`shuiqiang` 命中不了（实测见 §三） | **P3** |

**目标**：三项各自可独立验收。P1/P2 必须有「真实页面 + 真实事件顺序」证据；P3 必须有「真实 HTTP 入口 → 真的能搜到」证据 + 老库回填证据。

## 四、改动清单

### P1 带入一次性
- `app/erp/static/order-entry-common.js`：新增共享 `createPreviewApply({tbody, addRow, isRowEmpty, fillRow})` —— 只复用空行、`applied` 后拒绝再次带入、`reset()` 放开；并导出。
- `app/erp/templates/purchases/return_new.html`、`orders/new.html`：改用共享函数；按钮 `disabled` + 文案；**只在「原单真的换了」时 `reset()`**（重复选同一张不再放开）；清除关联时 `reset()`。

### P2 关联框改选 + 输入即解除
- `order-entry-common.js`：把「当前值 == 刚选过的标签 → 空查询」提成 `queryOnOpen()`，`focus` 与 `click` **共用**（仍只对 `options.openOnClick` 的字段生效，客户/商品框行为不变）。
- 两页模板：来源框接 `onInputChange` —— 输入内容 ≠ 当前已选单号 → 走同一个 `clearSource()`（清隐藏域 + 收起预览 + 清行上来源明细），消除「框里是 A、关联是 B」的脏状态。

### P3 拼音全拼
- `app/erp/utils/pinyin.py`：新增 `pinyin_full()`（整串小写全拼，上限 96）、`pinyin_fields()`（一次算两串）、`name_match_clause(prefix)` / `name_match_params(q)`（三列同参）。
- `app/erp/db.py`：`products`/`customers` 加 `pinyin_full TEXT DEFAULT ''`（SCHEMA_SQL + 幂等 `ensure_pinyin_full_fields`），`backfill_*_pinyin_full`（只补空值），`init_db` 调用；**不升 schema 版本**。
- 写入点 10 处：`services/accounting.py`（create_customer / create_product / update_product_record ×2 / 开单自动建档）、`routes/products.py`（导入 add / 导入 update / 手工新建）、`routes/customers.py`（导入 add / 编辑改名）、`routes/orders.py`（开单自动建档客户）、`routes/purchases.py`（拿货自动建档客户）。
- 匹配点 17 处全部改走 `name_match_clause`：`routes/products.py:84/103/293`、`routes/customers.py:66/80/223`、`routes/orders.py:231/352/363/638/753/1393/1414`、`routes/purchases.py:599/618/667`、`utils/pdf.py:347`。其中 `orders.py` 两处 `customer_name` 快照筛选用 `EXISTS` 回查客户档案。

## 五、验收标准

1. **P1**：node 前端测试（新增 `tests/frontend/order_preview_apply.test.mjs`）——连点两次只插一次、第 0 行非空时新增行不覆盖、`reset()` 后可再插；真实页面点两次明细行数不变。
2. **P2**：`tests/frontend/order_source_picker.test.mjs` 新增「真人点击顺序（focus 请求先回）」用例 —— 第一次点击即按空查询列全部；真实页面：选完原单后点一次输入框 → 列最近 30 张；改选 → 预览随之更新；输入改字 → 关联与预览立即解除。
3. **P3**：新增 `tests/test_pinyin_full_match.py`（真实入口逐项：商品/客户列表、建议 API、开单联想、拿货对象、原单候选、单据筛选、货款汇总）+ 老库回填与幂等；改 `tests/test_customer_pinyin_match.py` 的筛选口径断言。
4. 全量 `pytest` + 前端 Node 测试通过；四页内联 JS `node --check` 通过。
5. 打印/PDF 不在本次范围，无需实打。

## 六、风险与不做

- 拼音回填会在 `init_db` 对空值全表扫一遍（门店量级几百~几千行，可接受）；缺 `pypinyin` 时退化为空串，不阻断启动。
- 不做：数量/单位换算、拼音多音字纠正、模糊匹配打分排序、`pinyin_full` 加索引（`LIKE %…%` 用不上）。
- 不升 schema 版本、不动打印与 PDF、不打包不发版（未授权）。
