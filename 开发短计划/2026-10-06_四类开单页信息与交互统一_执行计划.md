## 本轮用户拍板

1. 客户/对象字段（拿货、退拿货）：改为**自由输入 + 自动补全**（与销售单同机制，新对象自动建档）。
2. 明细列：四页统一为 **序号 / 产品名称 / 单位 / 数量 / 单价 / 金额 / 成本 / 操作**。
3. 拿货/退拿货补齐：**单号显示、状态选择、当天历史、保存成功面板 + 查看 PDF**。
4. 拿货/退拿货：**常规价 / 客户价 一键带入**（单价手输，可选一键带入）。
5. 深色按三步：`data-bs-theme` 同步 → 清残留硬编码色 → 对比度审计回归。

## 现状事实（改前基线，来自源码/测试）

- 销售单 `orders/new.html` 已是目标八列骨架（序号/产品名称两级/单位下拉+自定义/数量/单价/金额/成本只读/操作），含自由输入+自动补全客户、单号预览、状态选择、当天历史、异步保存成功面板。**本计划不改销售页。**
- 拿货 `purchases/new.html`、退拿货 `purchases/return_new.html`：对象为 `<select>` 下拉；明细列 `具体商品/数量/单价/操作`（缺 序号·单位·金额·成本）；对象/日期/备注，无单号、无状态、无当天历史；保存后 `302 → 详情页`。后端 `routes/purchases.py` 已有 `/purchases|return/<id>/pdf`。
- 商品行 unit 存在但由**商品档案**决定（`purchase_order_items.unit` / `purchase_return_items.unit` 由 `products.unit` 写入）。
- 深色：`base.html` 有 `--erp-*` 深色 token，但 `<html>` **未设 `data-bs-theme`**（实测各页 `bs_theme=None`），未覆盖的 Bootstrap 默认色在深色下不可读；另有硬编码色。
- 基线测试：定向 `71 passed`（purchase_inventory / purchase_returns / async_save_print / order_entry_cost_columns / order_entry_accessibility）。

## 设计决策（本轮自定，供纠偏）

- **单位列（拿货/退拿货）取只读显示**，值为商品档案单位：库存/成本按商品单位计量，逐行改单位会与库存商品单位脱节。列位置与销售一致，仅不可编辑。若需可编辑再单独一轮。
- **成本列（拿货/退拿货）= 当前移动平均成本只读**（来自商品目录 `avg_cost_micro`），与销售/退货“系统成本”语义一致；退拿货该值即出库将结算的成本。
- 拿货/退拿货**单价不自动回填**（“单价手输”），仅提供“常规价/客户价”一键带入按钮。

## 分阶段与验收

- **P1｜对象自由输入+自动补全**：两页对象字段为 combobox，可用上下键/回车/ESC；新对象自动建档；`pytest` 定向不回归。
- **P2｜明细列统一 8 列**：两页出现 `序号/产品名称/单位/数量/单价/金额/成本/操作`，金额/成本只读、随输入联动；单位只读显示。
- **P3｜单号/状态/当天历史/成功面板+查看PDF**：新建拿货/退拿货显示只读单号与状态选择；当天历史按业务日期列出有效单；异步保存后面板出现“打开打印预览/查看单据/继续开单”。

每阶段：`.venv-win\Scripts\python.exe -m pytest tests\ -q`（隔离临时库）+ 对应隔离页面/浏览器验收；分批实测后继续。

## 停止条件

- 任一阶段销售/退货既有开单或账务被改崩 → 停在该阶段先修。
- 拿货/退拿货库存/成本口径变化或旧单不可读 → 停。
- 自动测试与真实页面结论冲突 → 以真实页面为准，暂停报告。

## 风险

1. 拿货页从“下拉对象”改为“自由输入”会新增自动建档路径，需与销售一致并防止孤儿对象。
2. 新增 `/api/*` 与 fetch JSON 分支，须保持非 fetch 的既有 `302` 路径不变（既有测试依赖）。
3. 深色改动触及全局 `base.html`，需逐页回归避免浅色回归。
4. 两页仍以内联脚本各自实现，存在一定重复；本轮以低风险为先，暂不强行抽共享。
