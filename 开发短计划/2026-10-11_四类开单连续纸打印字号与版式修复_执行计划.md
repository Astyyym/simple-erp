## 一、问题与根因

用户拿门店旧软件（秒账）打出的销售单与简单ERP 打出的销售清单实拍对比：**简单ERP 的字明显偏小，远距离/快速核对看不清**。

对照片（同一卷 241mm 两侧走纸孔连续纸、同一次拍摄）做连通域测量：

| 项 | 秒账（上） | 简单ERP（下） | 比值 |
|---|---|---|---|
| 正文字高中位数 | 21 px | 16 px | **0.76** |

即我们的字比秒账小约 1/4。再对 `app/erp/templates/orders/print_template.html` 做 WeasyPrint 真实排版测量，确认根因是**模板自身把字号定小、且没有字号层级**：

| 元素 | 当前 CSS | 实测字框高 |
|---|---|---|
| h1 公司名 | 16px | 5.59mm |
| .subtitle 单据名 | 12px | 4.19mm |
| .meta 单号/日期/客户 | 11px | 3.84mm |
| **table.items 表头+正文** | **11px** | **3.84mm** |
| **.total-row 合计** | **11px** | **3.84mm** |
| .bottom / footer-grid | 10px | 3.49mm |
| footer-sign | 11px | 3.84mm |
| **.legal-note 备注** | **9.5px** | **3.32mm** |

次要根因：2026-09-25「A4 竖版打印改造」把**四类开单**一并改成 A4 竖版（210×297、版心 186mm），而实体纸是 241mm 连续纸 —— 内容只占纸宽约 78%，左右各空约 30mm，字又小又挤在中间，进一步放大「看不清」的观感。

> **依据修正**：2026-09-25 那次改造确立的「销售/退货也走 A4 竖版」这一条，是本次缺陷的来源之一，属**错误依据**，本计划予以推翻并回写。更早的 [2026-07-14 南天 PR2 纸型适配](./2026-07-14_南天PR2秒账逻辑纸型适配_执行计划.md) 已实测出秒账的真实几何（逻辑页 215.9×139.7mm、左右边距 7.3mm、正文约 201.3mm），那才是四类开单应遵循的模型。

| 元素 | 现在 | 改为 | 实测字框高 |
|---|---|---|---|
| h1 公司名 | 16px | **24px** | 5.59 → 8.38mm |
| .subtitle | 12px | **16px** | 4.19 → 5.59mm |
| .meta | 11px | **14px** | 3.84 → 4.89mm |

2. **PDF 实测**：生成真实销售/退货/拿货/退拿货 PDF，量逻辑页框、正文墨迹左右边距（要求 L≈R）、无右溢、无裁切；渲染 PNG 目视标题/表头/正文/合计/备注。
3. **真机实打**：目标打印机上打四类各一张，确认字迹可辨、位置正确、左右对称。**自动化与 PDF 预览都不代替实打**。
4. **A4 未回归**：汇总/流水/对账 PDF 页框仍为 210×297mm。

## 八、停止条件与风险

- **风险 1（纸型未定）**：逻辑页尺寸未确认就改 `@page` → 停，先按 §六 确认。禁止用大 offset 掩盖页高错误（2026-07-14 试过，用户要求恢复 0）。
- **风险 2（分页）**：一联逻辑页高 139.7mm，商品行较多的单会自然进下一联。**用户已确认可接受自动进下一联，且实际场景中长单由用户拆成两次开单打印**，故不设「压在一联内」约束；仍需实测单联可容纳行数并记入计划（供参考，不作为压缩字号的理由）。
- **风险 3（两套模型串味）**：改 `order_pdf_page_*` 时误伤 `printer_paper_*`（汇总用）→ 用 §七.4 的 A4 回归断言兜住。
- **风险 4（被推翻的测试）**：`test_purchase_printing.py::test_purchase_a4_ignores_legacy_paper_configuration` 等断言把 A4 写死为契约，需改断言而非删测试；改前先确认它保护的**真实意图**（旧配置不得影响当前输出）仍然成立。
- **风险 5（长单历史方案）**：`references/print-offset-calibration.md` 记载「整单一块、自然跨页」「`<col>` 底色会崩」等 WeasyPrint 坑，版式改动必须保留这些结论。
