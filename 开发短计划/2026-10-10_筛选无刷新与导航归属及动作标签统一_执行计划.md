# 2026-10-10 筛选无刷新、侧栏导航归属与动作标签统一 — 执行计划

> 状态：`已完成（源码 + 自动化测试 + 隔离页面验收层）`。桌面 EXE、实体打印、深色主题矩阵不在本轮范围。
> 来源：2026-10-10 用户反馈（两张截图 + 文字），本轮共 4 项。

## 一、问题与根因（实测证据）

### P1 侧栏高亮归属错位

- 现象：账款管理页点「往来对账」后，左侧高亮从「账款管理」跳到「数据分析」。
- 根因：`app/erp/templates/base.html:577-579` 用 `request.path.startswith(...)` 判定高亮；往来对账的真实路由是
  `/analytics/reconciliation`（`app/erp/routes/analytics.py:440`），挂在 `/analytics` 命名空间下，前缀必然命中「数据分析」。
  链接携带的 `from=accounts` 目前**只用于返回按钮文案**（`analytics.py:474-481`），未参与高亮 → 返回键说「返回账款管理」、侧栏说「数据分析」。
- 实测：`/accounts/?customer_id=1` → active=账款管理；点往来对账后 → active=数据分析。

### P2 侧栏双高亮（顺带发现，用户确认一起收）

- `base.html:571` 给「工作台」加了 `current` 类，条件含 `/orders/` 与 `/accounts`；`.nav-section.current` 复用选中项文字色（`base.html:151`）。
- 实测计算样式：单据管理页、账款管理页「工作台」文字同为 `rgb(30,79,174)`（与 active 同色、无底色）→ 同页两项看着像选中。

### P3 筛选提交闪烁刷新并回到最上方

- 现象：单据管理 / 数据分析 / 账款管理 / 往来对账 / 客户管理 / 商品管理，页面已下滚时点主查询按钮，页面整块闪烁并回顶。
- 根因：筛选均为 `method="get"` 普通表单 → 整页重载；滚动容器是内层 `.page-body`（`base.html:180-183`），浏览器 `history.scrollRestoration` 对内部滚动容器无效。
- 实测（先滚到 300~500 再点主按钮，读回 `scrollTop`）：

  | 页面 | 滚动前 | 滚动后 |
  |---|---|---|
  | 单据管理·筛选 | 400 | 0 |
  | 数据分析·查询 | 400 | 0 |
  | 账款管理·查询流水 | 500 | 0 |
  | 账款管理·单据类型勾选 | 450 | 0 |
  | 往来对账·查询 | 300 | 0 |
  | 客户管理·查找客户 | 300 | 0 |
  | 商品管理·查找商品 | 300 | 0 |

- 关键：数据分析页**已有**就地刷新基建 `refreshInPlace()`（`app/erp/static/analytics-controls.mjs:79`），已用于热力图点日期、排行切换、每组显示、成本视图切换；
  **主筛选卡与页内其余 GET 表单未接入** → 同页「有的操作闪、有的不闪」。

### P4 同一动作跨页面叫法不一致

|---|---|---|
| 查看 | 回看 | `orders/list.html:124`、`orders/new.html:175`、`purchases/new.html:140`、`purchases/return_new.html:166`、两个 JS 重建分支 |
| 查看 | 查看 | `index.html:141`（工作台，已一致） |

| 打印 | 打印 | `orders/list.html:129/131/133` |
| 打印 | 查看PDF | `orders/detail.html:7`、`purchases/detail.html:5`、`purchases/return_detail.html:3` |

## 二、本轮用户决策（已确认，不重复追问）

1. **动作标签统一为「查看 / 编辑 / 打印」**（用户 2026-10-10 明确）。
2. **筛选无刷新范围＝所有筛选页**（用户选择「所有筛选页都改成无刷新」）。

## 四、分阶段与验收

### Phase 1｜侧栏导航归属（P1 + P2）

- 改动：侧栏高亮改为按 `request.endpoint` 映射 owner（`orders.*`→单据管理、`accounts.*`→账款管理、`analytics.*`→数据分析、`products.*`/`customers.*`/`recycle.*`/`settings.*` 各自、`index`→工作台）；
  `analytics.reconciliation` 在 `recon_source == 'accounts'` 时归属覆盖为账款管理。删除 `.nav-section.current` 与模板里的 `current` 类。
- 验收：逐路由读**计算色**，断言每页**恰好一项**高亮且归属正确（含 `/analytics/reconciliation?...&from=accounts` → 账款管理）。
- 脚本：`skills/.../erp-ui-extension/scripts/audit-nav-and-scroll.mjs`（需本地 `ws`，见风险）。

### Phase 2｜共享就地刷新基建

- 新增 `app/erp/static/page-refresh.mjs`：`scrollAnchor`、`refreshInPlace`（按 `data-refresh-fragment` 换块）、`wireInPlaceForm`（submit 拦截 → fetch → 换块 → `pushState` → 恢复滚动）、`popstate` 重新拉取并换块、失败回落 `location.assign`。
- `analytics-controls.mjs` 改为 re-export，既有 `tests/frontend/analytics_controls.test.mjs` 的 import 与断言保持不变。
- 验收：`node --test tests/frontend/`；新增单测覆盖「换块成功 / 无块则抛错 / 恢复滚动 / 失败回落」。

### Phase 3｜逐页接入（每页一次最小改动，过测再进下一页）

顺序（自包含优先）：数据分析主筛选卡 → 单据管理 → 账款管理（主筛选 + 类型勾选）→ 往来对账 → 客户管理 → 商品管理。
- 每页：给结果区加 `data-refresh-fragment` + 稳定 `id`；表单接线；**保留**单据管理导出链接与表单值的实时同步（`orders/list.html:244-264`）。
- 分页链接：**决策点**（见 §六），本轮按「就地换块 + 结果区对齐」处理，不整页重载。
- 验收（每页实测，不用截图判断）：滚到非 0 → 点主按钮 → `scrollTop` 保持、URL 同步、DOM 已换新、无整页导航（`performance.getEntriesByType('navigation').length` 不增加）；浏览器后退能回到上一组筛选。

### Phase 4｜动作标签统一（P4）

- 统一为：查看 / 编辑 / 打印。`orders/list.html`、`orders/new.html`（服务端 + JS 两处）、`purchases/new.html`、`purchases/return_new.html`、`orders/detail.html`、`purchases/detail.html`、`purchases/return_detail.html`。
- 不动：回收站「恢复 / 确认删除」、设置页「下载回看」（不同类动作）。
- 验收：模板测试断言新词存在、旧词在动作列消失（按元素 hook 断言，不用可见文案 substring）。

### Phase 5｜收口

- 全量 `pytest tests\ -q` + `node --test tests/frontend/`；跑 `audit-nav-and-scroll.mjs`。
- 真实页面验收：浅色默认下逐页走一遍，记录每页 `scrollTop` 前后与侧栏高亮。

## 五、停止条件与风险

- 同一文件同类修复连续 3 次失败 → 停下汇报，不硬试。
- 就地刷新若破坏既有 JS（导出链接同步、类型勾选 `onchange` 提交、`beforeunload` 防丢）→ 立即停该页并报告，不继续铺开。
- 涉及导出/PDF/打印口径时停下确认，不在本轮顺手改。
- `audit-nav-and-scroll.mjs` 依赖 `ws`，当前环境未安装；Phase 1 先用自写探针完成验收，脚本可另装 `ws` 后再跑（不因装依赖阻塞交付）。
- 工作区已有未提交改动（analytics 生长动画、环形/成本缺失两轮），本轮只在其之上叠加，**不回退、不清理**。
- 未授权：不 commit、不 push、不升版、不打包、不发布。
