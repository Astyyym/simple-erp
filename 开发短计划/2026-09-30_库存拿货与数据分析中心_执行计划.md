## 1. 目标

把现有系统扩展为一条可追溯的库存与经营分析链路：

> 商品建档/期初库存 → 拿货入库 → 销售出库 → 客户退货入库 → 移动加权平均成本 → 历史毛利润 → 热力图与排行 → 客户对账单

在冻结的页面框架中补充业务能力；保留旧客户采购统计兼容入口，明确旧销售口径与新净销售口径，不借业务扩展重做导航、热力图视觉或 PDF 预览。

### 1.1 本次完成后应具备的能力

1. 商品以“商品名称 + 型号”作为具体产品的唯一业务识别组合；具体产品独立维护库存、成本和利润。
2. 新商品及存量商品都可以一次性初始化期初库存和成本，不伪造历史拿货单；首笔后续库存流水后锁定。
3. 新增“拿货单”：沿用销售单的多行开单结构，记录数量与拿货单价，保存后增加库存并参与移动加权平均成本。
4. 销售单减少库存，并在保存时固定该次销售使用的历史成本与毛利润。
5. 退货单关联原销售单，支持部分退货；按原销售时成本冲回库存、销售金额和毛利润。
6. 开单页面可显示成本、预计毛利润等内部信息；客户签字的打印预览和 PDF 不显示成本、利润、库存、货源等内部信息。
7. 数据分析中心提供统一时间、客户、商品名称、型号和单据条件筛选。
8. 提供类似 GitHub 提交图的按日销售热力图，可按具体商品名称、可选型号、时间、销售数量或销售金额筛选；热力图下方显示利润汇总与具体产品明细。
9. 提供热销、低销量/未销售、毛利润和库存告急等具体产品分析。
10. 按客户和时间筛选单据，查询结果默认全选，支持取消选择并打印对账单；对账单只包含客户核对所需的业务信息，不等于已完成收款。
11. 账款继续承担客户余额、收款与调整，不引入逐单核销或自动现金退款；对账打印不产生资金记录。

## 2. 已确认的业务规则

### 2.1 商品身份

- 不建立商品分类体系，不增加“商品类别”作为本次功能的筛选层级。
- 具体产品由“商品名称 + 型号”识别。
- 同名不同型号是不同产品，分别计算库存、移动平均成本、销售数量、销售金额和毛利润。
- 型号可以为空，但同一商品名称下“空型号”只能对应一个具体产品。
- 现有 `spec` 统一为型号；名称/型号仅去首尾空白，唯一性覆盖软删除商品，引用使用稳定 ID。有库存流水后单位锁定；新增库存单据只选已建档商品，不按文本偷偷创建。旧数据冲突报告后停止，不猜测合并。
- 开单必须选择到具体产品；数据分析允许只选商品名称而不选型号。
- 分析筛选关系：
  - 不选商品名称：统计全部具体产品；
  - 只选商品名称：汇总该名称下全部型号，并在明细中按名称 + 型号展开；
  - 同时选商品名称和型号：只统计该具体产品。

### 2.2 商品资料与期初库存

商品资料负责维护和展示商品本身及当前状态，至少包括：

- 商品照片
- 商品名称
- 型号
- 尺寸等补充说明使用备注，不新增第二套型号/规格识别字段
- 默认销售价
- 安全库存
- 备注
- 当前库存（系统计算）
- 当前移动平均成本（系统计算）
- 当前库存金额（系统计算）

新商品及已有商品的一次性期初初始化允许录入：

- 期初库存数量
- 期初成本价
- 期初库存日期或系统上线起点所需的日期信息

期初库存代表业务启用时已有库存，不生成虚假的供应商或拿货历史。零期初必须明确确认，未知成本阻止启用；首笔后续流水前可带原因修正并留痕，之后锁定。自由库存调整不在首版。商品图片的上传校验、相对存储、备份及数据根迁移按业务契约执行。

### 2.3 单据与库存

| 单据 | 业务含义 | 库存变化 | 成本/利润影响 |
|---|---|---:|---|
| 期初库存 | 系统上线前已经存在的库存 | 增加 | 作为移动平均成本起点 |
| 拿货单 | 从临时、不固定的货源拿到商品 | 增加 | 记录拿货成本并重算移动平均成本 |
| 销售单 | 商品对外售出 | 减少 | 固定销售时成本并产生毛利润 |
| 客户退货单 | 原销售商品退回 | 增加 | 按原销售时成本冲回原销售金额和毛利润 |
| 单据末笔作废 | 仅无后续商品流水、无有效退货依赖且填写原因时允许 | 精确反向原流水 | 不重算后续历史成本；不等于自由库存修正 |

拿货单不建立固定供应商模块。可以保留可选的货源备注，例如“老张”“市场”“同行”，但货源不是必填的供应商档案，也不参与供应商结算。

拿货采用独立存储与 `NH` 日期日流水，不进入客户账款、客户售价学习及对账，首版不打印。销售/退货继续共用 `MD` 流水；编号事务内分配且不复用，达到四位流水上限时明确阻止。

生命周期以业务契约第 5 节的状态表为准：草稿无库存效力，正式保存原子生效，正式经济字段锁定，打印无库存效果，生效单据先满足末笔条件作废才可删除，恢复仅恢复可见性。七天自动清理和手动永久删除不得破坏任何生效历史或来源引用。旧单据按契约第 3 节单独兼容。

### 2.4 移动加权平均成本

每个具体产品维护数量和库存成本金额，拿货或期初库存进入后按移动加权平均计算：

`新平均成本 =（原库存成本总额 + 本次实际入库成本额）÷ 新库存数量`

计价按不可变过账顺序，报表按业务日期；补录不重算既有销售成本。数量精度 3 位小数，交易金额为分，内部库存成本精度为百万分之一元；不使用显示均价倒算。清空库存、部分退货累计分摊和末次尾差按契约第 4 节执行。零库存时总成本归零、当前均价不适用，负库存禁止。

注意：

- 期初库存必须参与第一次平均成本计算；
- 销售发生时读取并保存当时成本；
- 后续拿货改变当前平均成本时，历史销售利润不得变化；
- 统计利润使用销售单保存的历史成本，不能用商品当前成本倒算；
- 统计展示“毛利润/毛利率”，不把房租、人工、水电等费用纳入“净利润”。

### 2.5 退货与部分退货

- 一张客户退货单只关联一张有效原销售单，每行引用稳定原销售明细 ID；有成本缺口的旧销售不直接走新库存退货。
- 退货页面显示原销售数量、已退数量、本次可退数量、本次退货数量、原销售价格和原销售时成本。
- 支持只退部分数量，累计退货数量不能超过原销售数量。
- 原销售实际行金额按累计退货量分摊，最后一次退货吸收尾差；首版不支持自定义退款价/退款差额，不自动产生现金退款。
- 退货增加库存，并按原销售时成本冲回销售成本和毛利润。
- 重复退货、超数量退货和找不到原销售单时必须被阻止并给出可理解的错误。

### 2.6 内部页面与对外打印

开单及内部详情页面可以显示：

- 当前库存
- 当前成本
- 销售时成本
- 预计毛利润/已固定毛利润
- 毛利率
- 库存变化
- 货源备注

客户签字打印预览、PDF 和对账单不得显示：

- 成本价、拿货价
- 毛利润、毛利率
- 当前库存、库存金额
- 货源备注
- 其他内部经营字段

打印模板必须从模板数据边界上排除这些字段，不仅依赖 CSS 隐藏；内部备注独立于客户备注。首次引入内部字段即运行白名单与敏感哨兵值测试，Phase 4 是专项复验而非首次加隔离。

## 3. 新版页面职责

### 3.1 工作台

只负责“当前经营概览”和快捷入口，不承载完整分析：

- 今日/本月净销售额
- 今日/本月毛利润
- 当前库存金额
- 库存告急数量
- 热销、低销量/未销售、毛利润较高、库存告急的具体产品提醒
- 新建销售单、拿货单、退货单、客户对账等快捷入口

点击提醒后跳转数据分析中心并带入对应筛选，不在工作台复制一套查询逻辑。

### 3.2 开单

统一入口下分为：

- 销售单
- 拿货单
- 退货单

销售单与拿货单共用多行商品明细结构，但业务含义、库存方向和金额字段不同。退货单通过原销售单选择具体商品和可退数量。

### 3.3 基础资料

- 商品：维护名称、型号、图片、默认售价、安全库存、期初信息及备注中的尺寸说明；展示当前库存和成本，不另起尺寸/规格身份体系。
- 客户：继续维护客户档案和客户价格规则；本计划不新增供应商档案。
- 商品资料不直接作为正常库存流水编辑入口。

### 3.4 单据管理

负责历史单据检索和追溯：

- 按单号、日期、单据类型、客户、商品查询
- 查看销售、拿货、退货详情
- 查看库存变化、历史成本和关联退货
- 草稿编辑、正式经济字段锁定、末笔作废及回收站按新契约实现；销售/退货打印保留，拿货仅内部详情
- 保留已有客户采购统计及其销售口径，不重复建设另一套新净值热力图；新经营分析放在分析中心

### 3.5 数据分析中心

统一承载：

- 经营概览
- GitHub 风格销售热力图
- 商品销售与利润分析
- 库存告急分析
- 客户对账查询和对账单打印

### 3.6 账款

只负责实际结算：

- 应收余额
- 收款流水
- 客户余额及账款流水；负余额明确为预收/应退余额
- 不新增逐单部分结算/已结清标记，也不凭对账打印推断结算

数据分析中心生成的是交易对账单，不因为打印对账单就自动写入“已收款”。

## 4. 数据分析中心设计

### 4.1 统一筛选栏

筛选项：

- 时间范围：今天、本周、本月、本季度、本年度、自定义
- 商品名称：首版单选，支持“全部”
- 型号：单选，区分“全部型号”与具体的“未填写型号”；未选名称时禁用
- 客户：可选
- 单据类型：净值图表固定销售+退货；拿货清单可筛拿货，对账可筛销售/退货/全部，不用类型切换破坏净值定义
- 指标：销售数量或销售金额

统计时间使用单据业务日期 `order_date`，不是创建时间。筛选起止日期颠倒、非法日期、无结果和跨年范围均需有明确行为。

日期含首尾，倒序/非法日期阻止查询；本周从周一开始，快捷期间截止当天。客户筛选使用唯一 ID；选客户后拿货金额不适用。历史统计和当前库存分开标识；缺成本报告覆盖范围，不把旧单成本当零。

### 4.2 GitHub 风格热力图

- 按日显示，横向按周排列，纵向按星期排列，提供月份/年度识别。
- 每个格子代表一天，颜色深浅表示当天筛选范围内的销售活跃度。
- 指标切换：
  - 净销售数量；
  - 净销售金额。
- 净销售口径默认扣除客户退货：
  - `净销售数量 = 销售数量 - 客户退货数量`
  - `净销售金额 = 销售金额 - 客户退货金额`
- 不选商品显示全部具体产品合计；只选商品名称显示该名称下全部型号合计；选择型号显示具体产品。
- 热力图不承担商品之间的全部比较，商品比较放在下方明细/排行。
- 悬停或点击某一天显示日期、销售数量、退货数量、净销售数量、销售金额、退货金额、净销售金额和毛利润。
- 热力图下方沿用同一筛选条件显示利润汇总，避免图表和表格统计口径不一致。
- 退货额展示为绝对值；退货按自身业务日期计入，跨期可出现负净值。负值有明确符号/提示而非截零。多单位范围禁用净数量合计；跨年按年度切换图，完整区间汇总不被截断。

### 4.3 热力图下方利润区

显示：

- 销售金额
- 退货金额
- 净销售额
- 销售成本
- 毛利润
- 毛利率
- 净销售数量
- 拿货金额（单独标识为入库成本，不并入销售利润）

公式：

- `净销售额 = 销售金额 - 退货金额`
- `净销售成本 = 销售实际成本快照 - 退货冲回成本`
- `毛利润 = 净销售额 - 净销售成本`
- `毛利率 = 毛利润 ÷ 净销售额`；净销售额小于等于零或成本不完整时全范围毛利率不适用；已知成本部分单列，不能混用分母

下方明细按“商品名称 + 型号”展开，即使上方只选择商品名称，也要显示各型号数据：

- 净销售数量
- 净销售额
- 销售成本
- 毛利润
- 毛利率
- 当前库存

支持按净销售数量、净销售额、总毛利润、单件利润、毛利率排序。

### 4.4 商品分析

按具体产品提供：

- 热销商品：按单位分组后按净销售数量排序
- 低销量商品：期间有有效销售、净数量大于零的升序结果；净数量非正单列退货抵销/净退货
- 未销售商品：期末前建档、当前未删除/停用且区间没有有效销售；先售后全退不算未销售
- 毛利润最高/最低商品
- 单件利润和毛利率排行
- 库存告急商品

库存告急按当前状态判断：

- 当前库存为 0：缺货
- 当前库存小于等于商品安全库存：库存告急
- 当前库存高于安全库存：正常

库存状态不因查看历史时间段而回溯为历史库存；历史筛选数据和当前库存状态必须在界面上分开标识。

缺货优先判定，不与告急列表重复；告急汇总包含缺货。排行每组首屏前 10 项、可查看完整分页，并列按稳定商品 ID；未知成本不进入利润名次且提示排除范围。

### 4.5 客户对账

筛选条件：

- 单个明确客户（必选）
- 时间范围
- 单据类型可选销售/退货/全部；状态固定有效单据，不启用商品筛选

查询结果：

- 默认全选完整筛选结果中的有效销售、客户退货单据，包含其他分页
- 支持跨页全选、取消全选、逐单选择，显示已选数与总数
- 选择结果显示日期、单号、类型、商品数量、销售金额、退货金额和影响金额
- 只按完整单据选择，可展开明细但不逐明细勾选
- 取消选择的条目不进入打印结果

对账金额默认：

`选中销售金额 - 选中退货金额`

对账单显示：客户、对账期间、单号、日期、单据类型、商品、数量、业务金额、合计、签字区域。不得显示成本、利润、毛利率、库存和货源信息。打印不等于收款完成。

展示退货额取绝对值，合计等于选中订单有符号总额之和，不能按每条明细重复加订单总额。翻页保留选择、改变筛选重置并提示；服务端记录结果快照/版本，打印前重验，拒绝其他客户、失效/变化单据和空选择。新增订单不悄悄加入旧快照。合计标为“交易对账净额”，不含期初/收款/调整，不冒充当前欠款。

## 6. 分阶段执行顺序

### Phase 0 — 现状盘点、数据模型和原型边界

**目标**：确认当前商品、订单、库存、账款、打印和统计实现，避免叠加已有功能或破坏其他会话正在进行的改动。

**步骤**：

1. 重新检查工作区、当前分支和现有未提交改动；不覆盖、不清理其他会话文件。
2. 读取并记录现有商品、订单明细、退货关联、金额和账款表结构；确认是否已有库存字段或历史统计能力。
3. 建立需求条目到现有路由、服务、模板和测试的对照表：保留、扩展、替换或不做。
4. 明确期初库存、库存流水、移动加权平均成本、销售时成本快照和部分退货的数据存储方案。
5. 明确当前 PDF/打印链路，确认客户打印模板与内部页面数据边界。
6. 建立可运行原型并提交哥哥验收，不写业务代码。

**必须交付的设计证据**：

1. 旧字段、旧符号、旧退货/导入及所有删除恢复入口对照；明确稳定行 ID 与目前删明细重建的冲突。
2. 状态转换/业务不变量表，涵盖旧账只读、末笔撤销、打印不生效、回收站可见性及自动清理。
3. 独立拿货存储、统一库存服务、编号、过账序号、幂等键、版本校验及事务边界的准确设计；列出表/索引/服务接口候选并核对现有定义。
4. 结构迁移与存量商品业务启用方案；旧成本缺失、重复商品、旧草稿、备份恢复、失败与重复执行测试设计。
5. 指标/符号/单位/时间与跨页选择契约到服务查询的映射，固定场景矩阵见第 6.1 节。
6. 将当前可修改字段与未来锁定字段、旧统计兼容和新必要交互在原型中表达，不重新讨论已确认的保守业务取舍。

**阶段门**：

- 六项设计证据齐备，迁移和恢复方案可以在构造的旧库上验证；不得仅列风险而没有处理路径；
- 原型覆盖关键路径且哥哥确认；
- 未确认的成本、退货、对账和打印口径全部停留在本阶段；
- 正式业务数据库未被测试污染。

### Phase 1 — 商品身份与期初库存

**进入条件**：Phase 0 数据模型和原型通过。

**统一切换门**：Phase 1–3 各阶段仅在隔离环境验证，不单独向真实业务开放库存启用/拿货。库存、销售、退货及全部生命周期共同通过后，才具备申请实际切换的业务前提；实际切换另需授权、备份、停止旧写实例并统一封闭旧写路径，且正式投用仍需对应页面、打印和目标交付层级验收。

**范围**：

- 商品名称 + 型号的唯一业务识别；
- 新/存量商品的一次性期初启用、修订留痕、旧账只读与未知成本状态；
- 商品图片及数据根备份/迁移，型号导入兼容和客户价 ID 保持；
- 商品资料展示当前库存、当前移动平均成本、库存金额和安全库存；未启用显示未知、不计缺货/告急，汇总标明已启用覆盖范围与未启用商品数；
- 同名不同型号独立选择、编辑和查询。

**测试重点**：

- 同名不同型号不能串库存；
- 重复名称 + 型号被阻止；
- 型号为空的唯一性；
- 期初库存正确形成成本起点；
- 重复迁移/初始化、迁移中断恢复、旧账金额余额不变、缺成本标识、图片失败保留与相对路径安全；

**阶段门**：定向测试先红后绿，商品建档与现有客户、商品管理路径无明显回归。

**测试重点**：

## 8. 关键风险与处理

| 风险 | 处理方式 |
|---|---|
| 现有数据库没有库存流水或历史成本字段 | Phase 0 先确认迁移方案；涉及正式历史数据重建时暂停，不能猜着迁移 |
| 其他会话正在修改相同路由/模板 | 每阶段开工前检查 Git 状态和文件最新内容；冲突时停在阶段门，不覆盖他人改动 |
| 期初库存成本不完整 | 允许录入估算期初平均成本，并明确它是系统起点，不伪造历史拿货记录 |
| 后续拿货改变历史利润 | 销售保存成本快照，统计只读历史快照 |
| 退货没有原销售或发生部分退货 | 强制关联原销售，显示已退和可退数量，阻止超量退货 |
| 页面内部字段误进入打印 | 打印模板使用白名单数据，不仅靠 CSS 隐藏，并做 PDF 文本断言 |
| 热力图好看但统计口径不清 | 指标和净值口径写在控件/提示中，热力图与明细共用服务端聚合结果 |
| 当前库存和历史筛选数据混淆 | 页面分成“筛选范围内统计”和“当前库存状态”两个区域 |
| 对账单被误认为已收款 | 打印流程不写入收款流水，账款模块单独记录结算 |
| PDF 页面尺寸或偏移回归 | 按 A4 竖版要求做 PDF 预览、页面尺寸和设置偏移验证；无打印机时保留 `unverified` |

## 9. 停止条件

出现下列任一情况，停在当前阶段并报告，不扩大范围：

1. 需要覆盖、删除或重写其他会话尚未交付的修改。
2. 需要改变现有历史订单金额、单号、业务日期或账款口径但未重新确认。
3. 需要重建正式数据库、批量改写真实库存或猜测历史成本。
4. 移动平均成本、部分退货、对账金额或打印字段边界仍存在未决分歧。
5. 阶段专项测试、隔离真实页面或浏览器路径未通过。
6. 发现数据库迁移不可逆、正式数据可能被污染或库存无法回滚。
7. 必要新增交互原型未获哥哥确认却需要进入正式页面实现；纯后端设计不强行等待全站原型。
8. 需要新增供应商模块、商品分类、FIFO、采购结算等本计划外能力。
