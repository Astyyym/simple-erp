# 2026-10-15 设置页三版面样张预览 执行计划

## 目标（用户 2026-10-15 指令）

设置页原来只有**四类开单**的样张预览；用户要求「在设置里也添加上另外两个版面的打印预览」。本计划把三个版面的样张并到同一张表里，每个版面都能看网页效果和真实 PDF：

| 版面 | 纸型 | 模板 |
|---|---|---|
| 销售单 / 退货单 / 拿货单 / 退拿货单 | 241mm 连续纸（逻辑页 215.9×139.7mm） | `orders/print_template.html` |
| 客户货款汇总表 | A4 竖版（210×297mm） | `accounts/summary_pdf.html` |
| 往来交易对账单 | A4 竖版（210×297mm） | `accounts/reconciliation_pdf.html` |

非目标：不做可视化版式编辑器（用户当日决定「先记下，当前不搞」，见文末候选）；不改三个版面本身；不动纸型与偏移口径；不升 VERSION、不打包、不提交。

## 关键决策

1. **样张一律用固定示例数据，绝不读业务库** —— 与四类开单样张同一原则。新增 `settings_summary_preview_context` / `settings_reconciliation_preview_context`（`app/erp/utils/pdf.py`）：形状对齐真实上下文；货款汇总的行分组元数据复用真实导出用的 `_account_summary_table_rows`/`_account_summary_totals`，**不自己另写一套口径**，避免样张与线上漂移。
2. **同一件事只留一个入口**：三个版面收进同一张「打印版面预览」表（版面 / 纸型 / 预览），删掉底部动作条里原来的两个预览按钮。`settingsPrintPreview` / `settingsPrintPreviewPdf` 两个 id **保留在四类开单那一行**，既有断言与用户习惯不断。
3. 未保存修改的确认提示从「只挂四类开单那两个链接」扩到**全部六个链接**（`data-print-preview` 批量挂载）。
4. 桌面壳「生成预览 PDF」沿用统一预览页（保存 / 打印 / 返回上一级），且**预览页不预渲染 PDF**（已有契约，四类开单样张同款）。
5. 对账单样张的数字必须自洽：四类总额相加 = 流水总额，加资金流水合计 = 汇总（281.00 − 200.00 = 81.00）。

## 改动文件

- `app/erp/utils/pdf.py`：两个样张上下文 + 两个生成器；抽出 `_write_sample_pdf` 共用渲染/写盘尾部（三个样张共用）。
- `app/erp/routes/settings.py`：新增 4 条路由 —— `/settings/print-preview/summary(.pdf)`、`/settings/print-preview/reconciliation(.pdf)`；HTML 直出模板，PDF 走 `send_pdf_for_preview`。
- `app/erp/templates/settings/index.html`：「打印版面预览」卡片（3 行 × 2 入口），动作条只剩「保存设置」；JS 改按 `data-print-preview` 批量挂载确认提示。
- 测试：`test_desktop_pdf_save.py`（桌面预览四条路径 / A4 页框 / 设置页入口与六个链接）、`test_pdf_render_once.py`（三个样张预览页都不预渲染）、`test_desktop_print_auth.py`（新增四条免登录路径）、`test_settings.py`（样张不读业务库 + 数字自洽 + 内部字段哨兵）。
- 文档：需求文档 §3 设置行；项目 reference `settings-page-and-data-root.md`。

## 验收（实测证据）

- 设置页：三行各 2 个入口（共 6 个）、`data-print-preview href=` 6 处、页面不含真实客户/商品。
- 三个 HTML 样张：`预览客户（示例）` 在纸；真实客户名/商品名与 `unit_cost` / 毛利润 / 货源 / 成本价均不在纸。
- 三个 PDF：四类开单仍是 215.9×139.7mm 连续纸逻辑页；两张 A4 样张是 210×297mm 竖版。
- 桌面预览：三个 `.pdf?desktop_preview=1` 都是工具栏页（`savePdf` + 「返回上一级」+ 正确 `return_to`），且生成器调用次数 **0**；浏览器直连才渲染 1 次。
- 真实页面（隔离数据根）：三张样张都是真模板渲染的真 PDF，可下载可打印。

## 停止条件

- 样张若必须读业务库才能出内容 → 停，改为不做该版面预览。
- 入口/URL 改动若破坏既有打印契约（预览页不预渲染、对外白名单）→ 停并报告。

## 风险

- 样张数字是固定的，用户可能误当真实数据 → 卡片文案与测试都写明「固定示例数据，不含真实单据」。
- 打印面端点数量增加 4 条，白名单不放松：样张上下文只给对外字段（类型/数量/单价/金额/客户名）。
- 设置页动作条按钮变少，用户可能一时找不到预览入口 → 同屏可见的「打印版面预览」卡片就是唯一入口。

## 已记下的后续候选（未承诺、当前不做）

**可视化打印版面调整（用户 2026-10-15 提出，当日决定「先记下，当前不搞」）**：在设置里做可拖拽、可增删文本框、可改颜色字号的版面编辑器。当日评估结论：

- **不建议做自由画布**。理由：① 四类开单是「数据驱动的重复表格 + 分联续打」，自由画布没有重复区概念，行数一变位置全废；② 纸面位置只能靠目标打印机实打验收，自由度换来的是每次改版都要重打；③ 门店用户要的是「列宽、字号、加字段」，不是排版自由度；④ 对外打印白名单会被自由文本框侵蚀。
- 可做档位：**档 1** 参数化版式 + 真实预览（把已有行数/偏移/文案集中，新增列宽、字号档、块显示开关），拖拽只用于拉列宽与移块；**档 2** 块级编辑器（列增删改序 + 块内样式，仍是表格驱动）。
- 若重启：先做档 1 的第一阶段（真渲染的只读预览），并按项目规矩先做一轮开源先验调研，再给「采用 / 改造 / 自建」判断。
- **与对账单版面定稿无关，不阻塞当前交付。**
