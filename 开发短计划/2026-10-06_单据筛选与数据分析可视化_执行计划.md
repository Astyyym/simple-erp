## 本轮用户决策（已确认，不重复追问）

1. **退拿货单号改 NH**：拿货/退拿货**共用 `NH` + 8 位日期 + 4 位日流水**，对齐「销售+退货共用 MD」的规则，不撞号。历史库中已有 TN 单号**不追溯重写**。
2. **热力图点日期的范围**：点击某天只在**日历下方显示当日明细面板**，**不改变**下方「产品排行 / 具体产品分析」的统计范围。
3. **成本诊断可视化**：采用「成本覆盖堆叠条 + 毛利构成条 + 成本缺失 TOP 条形」三层，不追求所有指标都图形化（纯数字项保留文字）。
4. **产品排行条形图**：条形末端**显示数值标签**。
5. **数据分析筛选以顶部日期为准**：下方**所有**分析数据都以顶部时间范围与订单类型筛选为基准；顶部筛选扩展为**按年 / 按月到月 / 按日到日 + 订单类型多选**。
6. **订单类型对指标的作用域**：利润类（净销售额 / 销售金额 / 退货金额 / 毛利润 / 毛利率 / 产品排行 / 具体产品分析）**只算销售 + 退货**；勾选拿货/退拿货时，只影响**流水热力图**与**新增「单据流水」卡片**（拿货金额 / 退拿货金额 / 流水净额），并在页面明确标注「不参与利润口径」。

## 现状事实（改前基线，来自源码/测试）

- 单据管理筛选（`orders/list.html`）：4 列 grid（客户 / 时间模式 / 日期 / 类型），类型块仅 170–370px 宽；`全选`、`清空` 与四类复选框同处一个 `flex-wrap`，窄屏会乱折行。
- 数据分析（`analytics/index.html` + `analytics-v4.css`）：`heat-grid` 是 7 列流式网格，每格三行（日期 / 金额 / 有交易·无交易），不是月历；负值格用 `--erp-danger` 实底。排行是 `<ol>` 文字列表 + 「查看完整/上/下一页」分页。成本诊断是 8 行 `profit-line` 纯文字。
- 热力图有独立 `heat_year` 下拉，可脱离顶部日期范围单独看某一年 —— 与决策 5 冲突。
- 顶部筛选只有 `start_date` / `end_date`，没有时间模式与订单类型。
- 退货页 `orders/new.html` 的原销售单块在**第二个 `order-meta mt-3` 卡片**内（自带玻璃卡，浮在明细卡上）；退拿货页 `purchases/return_new.html` 的原拿货单块在**同一 `order-meta` 的 `row g-3 mt-0`** 内（同层）。两页层级不一致。
- 单号前缀：拿货 `NH`（`routes/purchases.py:next_purchase_no`）、退拿货 `TN`（`routes/purchases.py:next_return_no`、`services/purchase_returns.py:191`），两条独立流水。

## 需求分解

- **① 单据管理订单类型块两行排版**：第一行 `全选` `清空`，第二行四类复选框；类型块跨整行；整个筛选卡重新排布。
- **② 退拿货单号 NH**：拿货/退拿货共用 `NH` 日流水，三处前缀 + 页面文案 + 相关断言。
- **③ 四类开单页原单关联**：原销售单 / 原拿货单**放在单据信息卡第一行最上面**，选中后在明细卡之前展开**原单预览**（同层级，不浮层），预览后再带入商品行。
- **④ 流水热力图改月历**：7 列星期固定、补前置空格、格内只留**日期数字 + 底色深浅**；悬停给完整信息；移除 `heat_year`，改为渲染顶部范围内**全部月份**。
- **⑤ 产品排行条形图**：6 种模式全部改横向条形 + 数值标签；每组显示数量可调（10/20/50/全部），默认 10，替换分页。
- **⑥ 成本诊断可视化**：覆盖堆叠条 + 毛利构成条 + 缺失 TOP 条形。
- **⑦ 数据分析顶部筛选扩展**：时间模式（按年 / 按月到月 / 按日到日）+ 订单类型多选；下方全部数据跟随。
