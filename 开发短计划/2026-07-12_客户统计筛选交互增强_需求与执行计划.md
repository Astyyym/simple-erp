## 一、背景（为何还要改）

上一版客户采购统计已具备：

- 精确客户名可出热力图 / 排行
- 订单类型筛选
- 商品/客户导入

用户验收后反馈核心体验问题：

1. 正常点「筛选」时，客户输入模糊字（如 `中建`）能出单据列表，但**不会自动出统计图**；必须依赖完整客户名链接才看得到图。
2. 热力图不应只是几天紧凑小方块的「短条」；时间范围与布局要符合业务筛选习惯。
3. 需要更清晰的时间筛选方式：按年 / 按月 / 按日到日。
4. 客户为空、只按日期时，也要有**全店**拿货金额热力 + 货物销量排行。

本文件记录**本次新增/修订规则**与**开发计划**；实现以本文为准，与旧文档冲突时以本文为新规则。

## 二、已确认的业务规则

### 2.1 何时显示统计区

| 场景 | 行为 |
|------|------|
| 筛选后能唯一确定 **1 个**未删除客户 | **自动显示**该客户采购统计（热力图 + 商品排行） |
| 客户输入为模糊字，但库内 **唯一**模糊命中 1 个客户 | **出图**，按命中的完整客户名统计 |
| 客户输入模糊命中 **多个**客户 | **不出图**，只显示单据列表；在筛选区旁给出**中文提示**（如：匹配到多个客户，请再精确筛选） |
| 客户输入命中 **0 个**客户 | 不出客户画像；列表按现有逻辑；可提示未匹配到客户 |
| 客户框**为空**，仅靠日期（及订单类型等）筛选 | **要出图**：热力=该时段全店拿货总金额（按天）；排行=该时段全店商品销售数量前5/前10 |

说明：

- 「筛选出一个客户 → 当然要做该客户统计」是默认目标。
- 多客户时用户会自行再筛，系统不替用户猜某一个客户。

### 2.2 客户输入与自动匹配

- 输入过程中提供**自动匹配/建议**：从库中提示完整客户名称，便于选准。
- 提交筛选后服务端再做唯一性判定（精确优先，其次唯一模糊命中）。
- 模糊多命中：列表 + 提示，无统计区。

### 2.3 统计口径（颜色 / 排行 / 拿货）

仅统计 **有效销售单**：

- `order_type = 'sale'`
- `status IN ('saved', 'printed')`
- `deleted_at IS NULL`

**不计入**：退货单、草稿、作废/删除。

- 热力图颜色：**只由当天拿货总金额**决定；档位按当前统计范围内金额分布动态分级。
- 商品排行：**按累计销售数量降序**；金额并列展示；数量相同可再按金额、品名稳定排序。
- 前 5 / 前 10 切换同步更新表与图。
- 客户为空时：同样按**商品销售数量**前 5 / 前 10。

### 2.4 时间筛选模式（三选一）

筛选区增加 **时间模式** 单选切换：

| 模式 | 含义 | 控件 |
|------|------|------|
| **按年** | 自然年，如 2026-01-01～2026-12-31 | 年份选择（默认当前年或筛选上下文合理默认） |
| **按月** | 某年某整月 | 年 + 月 |
| **按日到日** | 起止日期（最细） | 开始日期 + 结束日期 |

规则：

- 三种模式 **单选**；切换后只显示对应控件。
- 列表过滤与热力图格子范围，均以当前模式解析出的 `start_date`～`end_date` 为准。
- 非法日期安全回退，不 500；起 > 止时归一化。
- 超大跨度保留保护上限（实现时默认不超过约 366 天一屏数据量；按年自然年允许整年）。

### 2.5 热力图布局

| 规则 | 说明 |
|------|------|
| 格子范围 | **只画当前筛选时间段内的日期**，不强制永远铺满一年 |
| 按年时 | 使用 **当年自然年**；**不要** GitHub 式全年密排、月份无间隙 |
| 月份间隙 | 按自然月分块排列；月与月之间有间隙 |
| 年视图默认排布 | **每 6 个月一横排，共两行**（1–6 上一行，7–12 下一行） |
| 自适应 | 浏览器较窄时，左侧热力可改为约 4 个月一行、3 个月一行等；**仅左侧热力换行** |
| 右侧排行 | **条形统计图不换行**，固定在右侧；窄屏时整体可为上下结构，但排行图本身不折行打碎 |

交互（沿用并适配新布局）：

- 悬停：日期、拿货总额、次数、货物（多则前几种 +「另有X种」）
- 单击：复用单据查询，带入当前客户上下文（单客户时带客户名；全店时客户可空）+ 单日起止
- 拖选：跨格后先确认「查看订单详情 / 取消选择」，再跳转
- 跳转后仍可切换全部 / 销售 / 退货，且保留客户与日期（及时间模式参数）

### 2.6 统计区标题文案

| 范围 | 建议标题 |
|------|----------|
| 单客户 | 客户采购统计 · `{完整客户名}` · `{起}` 至 `{止}` |
| 全店（客户为空） | 全店拿货统计 · `{起}` 至 `{止}` |

多客户提示文案示例：

```text
匹配到多个客户，请把客户名称再写精确一些后再筛选。当前不显示采购统计。
```

### 2.7 明确不做（本轮）

- 多客户时自动合并成「假单客户」画像（除客户为空的全店模式外）
- GitHub 密铺年视图
- 退货计入拿货颜色/排行
- 擅自 commit / push / 升版本 / 打 EXE（用户确认后再做）

## 四、技术设计要点

### 4.1 后端（`orders.py` / list 路由）

1. **解析时间模式**  
   - `date_mode`: `year` | `month` | `range`（默认 `range` 兼容旧链接）  
   - `year`, `month`, `start_date`, `end_date` → 统一算出 `effective_start` / `effective_end`

2. **解析客户作用域**  
   - `customer_q` 空 → `scope=all`（全店）  
   - 精确命中 1 名 → `scope=customer`  
   - 模糊命中 1 名 → `scope=customer`（使用完整名）  
   - 模糊命中 >1 → `scope=none`，`dashboard_notice=多客户提示`  
   - 0 命中 → `scope=none`，可选未匹配提示  

3. **聚合**  
   - 单客户：`customer_id = ?`  
   - 全店：不加客户条件  
   - 谓词固定有效销售  

4. **下发 JSON**（专用 `<script type="application/json" id="customerPurchaseData">`）  
   - `scope`, `customer`, `start_date`, `end_date`, `date_mode`, `days[]`, `ranking[]`, `order_type`  
   - 前端只渲染，不重新算业务口径  

5. **列表查询**  
   - 客户仍可用 LIKE 模糊（与现在一致），保证多客户时列表仍可见  
   - 日期、类型条件与模式解析结果一致  

### 4.2 前端（`orders/list.html`）

1. 筛选表单：客户 + datalist/建议 + 时间模式单选 + 条件控件 + 订单类型 + 筛选/清除  
2. 多客户 / 未匹配：`alert` 或表单旁提示条  
3. 热力：按月卡片网格；年视图 CSS 用 `auto-fit`/`minmax` 实现 6/4/3 月自适应列数  
4. 右侧排行 canvas + 表；resize 只重绘右侧，不把图拆到多行业务块  
5. 单击/拖选跳转时带上 `date_mode` 与对应参数、`order_type`、客户名  

### 4.3 测试（TDD / 回归）

至少覆盖：

- 模糊唯一命中 → 有 JSON，客户为全名  
- 模糊多命中 → 无 JSON，有提示文案  
- 客户为空 + 日期 → 有全店统计，排行按数量  
- 退货/草稿/删除不进金额与排行  
- `date_mode=year` → 起止为自然年首尾  
- `date_mode=month` → 该月首尾  
- 非法日期不 500  
- 页面含模式切换与月历容器标记  
- 离线图表（无 chart.js/echarts CDN）  
- 订单类型与跳转参数保留  

全量 `pytest`；正式 `data/erp.db` 哈希测前=测后。
