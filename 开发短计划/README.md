## 新计划约定

1. 文件名：`YYYY-MM-DD_主题_执行计划.md`。
2. 一份计划对应一个可交付目标，写明目标、改动文件、执行顺序、验收证据、停止条件和风险。
3. 完成后明确更新实际状态；自动测试、Windows 页面、桌面 EXE、打印机实测和 GitHub Release 必须分开记录。
4. 已确认产品规则写回 `docs/需求/`；短计划不作为长期需求文档。
5. 只有跨会话/多阶段任务才使用根目录 `task_plan.md`、`findings.md`、`progress.md`，且同一仓库只保留一套当前活动记录；详细生命周期见项目技能。
6. 开新计划前先查本索引和同主题计划；同一目标复用既有文件，确有独立验收目标或阶段才拆分，并写清前后关系。
7. 完成后将计划标成历史记录并更新索引；长期规则迁入 `docs/` 或项目技能，不把临时任务进度长期堆在根目录三件套中。不得未经检查覆盖或删除用户已有的未提交记录。
8. 未授权不自动 commit、push、升版或打包。
