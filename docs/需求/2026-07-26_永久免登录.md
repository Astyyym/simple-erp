# 永久免登录决策记录

> 决策日期：2026-07-26<br>
> 当前状态：永久免登录已实施；`v0.8.0` 是该次交付的历史版本，当前源码版本见根目录 `VERSION`。GitHub Release 资产与目标用户实机状态不由本记录推断。

## 背景与目标

原先本地单机使用仍需经过账号密码门。最终确认永久免登录：浏览器与 Windows 桌面版打开后直接进入业务页；不保留登录表单或退出登录操作；`/login`、`/logout` 作为旧入口兼容，重定向到首页；`/health` 保持公开并报告 `auth: disabled`。

## 决策范围与历史

最初确认的执行范围是源码与测试，不改版本、README、CHANGELOG、推送或打包。随后该阶段进入 `v0.8.0` 并同步当时的根 README、CHANGELOG 与版本文件。历史执行分阶段记录见 `开发短计划/2026-07-26_永久免登录_执行计划.md` 和 `开发短计划/2026-07-26_v0.8.0_永久免登录发版.md`；其发布流程的远端结果仍应单独查验。

## 风险与安全边界

本地服务端口可访问时，无账号门槛即可操作业务数据；此风险已作为产品定位接受。因此：

- 服务仅供本机单机使用，默认绑定 `127.0.0.1`；
- 不得将服务暴露到局域网或公网；
- 不要把“免登录”误写成“有权限控制”；
- 如未来业务环境改变，重新确认安全模型，不自行假设登录已重新启用。

## 当前实现证据

- `app/erp/auth.py` 中 `auth_disabled()` 与 `is_authenticated()` 表现为永久关闭鉴权；旧配置键仅用于兼容，不构成可用登录开关。
- `app/erp/routes/auth.py` 保留旧 `/login`、`/logout` 路由的首页重定向。
- `app/erp/__init__.py` 健康端点返回 `auth: disabled`；测试覆盖免登录访问。
- 2026-09-24 Windows 项目环境全量测试：`96 passed`。这一结果不等同于用户手动验收或 EXE Release 验收。
