### 退拿货补充决策（2026-10-02已确认）

- 用户已选择：**退货业务金额沿原拿货单，库存出库成本按退货时的移动平均成本扣减**。两者是不同事实，不把拿货退款价当成当前库存平均成本，不改写旧销售成本或旧利润。
- 一张退拿货关联同一往来对象的一张有效原拿货单，每行关联稳定原行ID；仅生效退拿货占额度，支持多次部分退，不超原行数量减已有效退数量。业务金额按原行实际金额累计分摊，最后一批吸收分尾差。
- 正式保存写事务内再次核对库存与额度，任一行数量不足整单拒绝；按固定行序扣除当前库存数量和精确微元成本。出清全部当前库存时扣完剩余总成本，不留零库存成本尾差；历史销售/拿货/其他退货快照不重算。
- 生效、作废、幂等、并发、版本、回收站及永久删除遵循既有库存生命周期合同；作废必须原因且满足所有商品末笔规则，冲回该退拿货自身保存的精确库存流水，不按新的均价反算。草稿不扣库存或预占可退额度。
- 采购交易金额与实际库存出库成本的差额仅作为可追溯内部事实，不伪造收款、付款、退款、账款抵销或销售毛利润。采购退款资金本轮不自动登记。
- 双向交易清单按本店视角为销售加、客户退货减、拿货减、退拿货加；显示分项与交易对账净额，仍非应收应付余额。销售/客户退货的原有账款服务和历史余额保持不变。

## 2. 商品身份、单位与资料

### 2.1 身份与选择

- 商品以稳定 `product_id` 引用；业务唯一键为规范化的名称 + 型号，型号为空仍是具体键，不等于“全部型号”。分析控件分别提供“全部型号”和“未填写型号”。
- 首版规范化只去除名称/型号首尾空白，NULL 型号转换为空字符串；保留内部空白、大小写及全半角差异，不自动合并疑似同义商品。检测疑似重复时可提示，不猜测合并。
- 唯一性覆盖软删除商品。相同键存在于回收站时提示恢复，禁止新建同键商品；已有重复数据阻止启用新约束并输出不含私人资料的定位结果，不任意选第一条。
- 新库存单据必须选定具体商品 ID，后端重新校验，不能只按自由文本名称匹配。新销售不再偷偷建商品；商品可先在基础资料建档，拿货也只选已建档商品。
- 商品重命名不改变 ID 和历史单据快照。分析按 ID 归集，展示当前名称/型号；历史单据和对外打印保留成交时快照。改名后的业务键仍检查唯一性。
- 一件商品只使用一种库存单位；存在期初或任何库存流水后不允许修改单位。不做箱/个、米/卷换算。不同单位的数量不直接相加或跨单位排名。

### 2.2 售价与拿货价

- 销售继续使用现有客户价/常规价规则，但只在成功的销售保存路径按已定规则处理；拿货、退货、打印、重试不能改变客户价。
- 拿货价格只作为入库成本，不写入商品默认售价或客户价，不更新商品单位。
- 新建商品的默认售价独立录入；零售价、零入库价允许，但缺失值不能自动等同于明确录入的零值。零成本须显式确认并有审计。

- 商品导入新模板增加可选“型号”，旧“商品名称、价格”两列模板仍可用，省略型号只映射空型号，不能任意匹配同名其他型号。重复按规范化名称+型号判断，含软删除项；保持逐行报告并跳过，不覆盖库存、成本、客户价或历史快照。
- 导入只建商品资料，不自动初始化期初，不接收库存/成本/图片路径批量覆盖；商品导出包含型号并保持库存与成本列为明确内部用途。客户导入规则不因本次商品身份改动而扩大。

### 2.3 图片

- 图片保存在数据根的专用商品图片目录，数据库保存相对路径，不保存任意本机绝对路径；纳入备份、恢复与数据目录迁移验证。
- 首版仅支持 JPEG/PNG，单文件不超过 5 MiB、解码像素总数不超过 20 百万；后端校验并重编码，使用系统生成文件名，不信任扩展名，不接收 SVG 或路径穿越输入。
- 替换图片失败不得丢失旧图；业务备份不得依赖源码目录。首版不把商品图片加入客户 PDF，不改变版式。测试只能使用虚构图片。

## 3. 数据启用与历史兼容

### 3.1 结构迁移与业务启用分离

- 结构迁移只新增必要结构/兼容标记，不自动扣减旧销售库存，不凭旧订单推测期初数量或历史成本。
- 存量商品也有“一次性期初初始化”入口，不限定必须重新建档。每个商品分别记录初始化时间、期初业务日期、数量、总成本及成本来源（已知/用户确认估算/明确零成本）。
- 首版数量非负；有数量时必须明确成本，未知成本阻止该商品启用。零数量的期初总成本必须为零。
- 初始化是唯一、可审计的事件，重复提交只返回原结果。首笔后续库存事件前允许带原因修正期初，保留修订记录；此后锁定，不能从商品资料直接改库存或成本。
- 未初始化商品可以浏览历史与保存草稿，但不能正式过账新销售、拿货、退货。新商品可显式以零期初初始化，不自动猜测。
- 未初始化商品的库存、均价、库存金额显示“未启用/未知”，不能当零计入缺货/告急。库存金额汇总只覆盖已启用商品，同时显示未启用商品数；存在未启用商品时不称为完整全店库存金额。
- Phase 1–3 的库存、销售、退货和全部生命周期闭环未共同通过前，只能在隔离环境验证，不对真实业务开放期初启用或拿货入口。实际切换需另行授权，先停止旧写实例并完成一致性备份，再统一切换所有销售/退货/删除恢复写路径；不得让新入库和旧的不扣库存销售路径同时写同一业务库。正式投用还需满足对应页面、打印和目标交付层级验收，不以 Phase 3 自动替代最终交付。

### 3.2 旧单据

- 迁移前已保存/已打印及其他历史订单标记为旧账业务；金额、单号、业务日期、客户余额、历史快照保持原样，不生成虚构库存流水。
- 库存启用后的旧正式单据只读其经济字段，不再允许改变金额、明细、客户、状态或通过删除改变账款。原有软删除旧单据仍可追溯，但不恢复其财务生效状态；旧账纠错继续通过有原因的账务调整处理，不把它解释为库存调整。
- 旧草稿没有业务效力；以后正式保存时必须按新规则重新选择商品、校验库存并生成新过账记录，仍保留其原单号/日期约束。日期早于所涉及任一商品的期初业务日期则不能转正式，提示新建有效日期单据，不静默改日期；与新建补录使用同一下限，不混用实际初始化时间。
- 没有可靠原销售成本快照的旧销售不允许直接生成新库存退货；给出“历史成本缺失，当前退货路径不支持”的提示。不得填零成本、当前平均成本或伪造历史销售代替；历史退货补录/库存调整另立需求。
- 旧单据继续进入销售/退货金额、客户账款和对账统计。未知成本不是零成本；利润区域显示成本可计算范围、未覆盖笔数/净销售额及“不完整”提示。
- 已知成本部分毛利润/毛利率只用已知成本部分的净销售额和净销售成本。包含未知成本时，全范围成本、毛利润和毛利率显示“不可完整计算”，不把部分毛利冒充全量毛利。

### 3.3 迁移验收

- 使用构造的旧版数据库夹具，不读写正式业务库来造测试。迁移需有版本推进、重复执行不重复迁移、约束/外键检查、失败回滚或备份恢复实测。
- 升级前必须有一致性数据库备份和图片备份；SQLite 使用备份机制获取一致性快照，不能在运行中仅复制主库文件而遗漏 WAL 数据。
- 验证旧订单金额/编号/日期、客户余额和旧打印结果不变；重复商品、断开的商品引用、超精度历史数量只报告阻塞，不擅自清洗。
- 恢复路径是停止新程序后恢复备份并使用兼容旧程序，不允许旧 EXE 在新结构上继续写入。启动版本检查拒绝不支持的数据库版本；不得把“逆向 SQL 降级”当唯一恢复方式。
- 结构迁移、业务启用和正式数据操作分别授权。本轮文档授权不包含正式库升级。

## 4. 时间、数量与成本计量

### 4.1 业务日期与过账顺序

- `order_date` 用于销售、退货、拿货报表；正式保存成功时记录不可变过账序号/时间，库存计价严格按过账顺序串行进行。同一天也不靠可重复时间戳猜顺序。
- 允许补录业务日期，但不得早于涉及商品的期初业务日期，不得晚于本地当天；退货业务日期不得早于原销售日期。补录不回写既有销售成本。
- 补录页面说明“按当前过账时库存成本计价，不追溯重算历史成本”；历史日期报表可能因补录改变交易金额，但已有销售行成本快照不会被后续拿货改变。
- 期初库存日期与业务启用时间分别保存。当前库存不是按报表日期倒推的历史库存；本轮不提供历史库存回溯。

### 4.2 精度与守恒

- 新业务数量最多 3 位小数，使用 Decimal 或精确的千分单位整数；拒绝 NaN、无穷、超精度和超范围输入，不能先转二进制浮点。单据数量必须大于零，期初/安全库存可为零。
- 对外售价、拿货录入单价及交易金额使用人民币分整数；现有行金额采用 ROUND_HALF_UP。成本内部总额使用百万分之一元整数（6 位小数），不是把平均单价截成分反复计价。
- 平均单位成本由精确库存总成本 / 库存数量计算，Decimal 中间精度至少 28 位；显示均价不作为后续计算输入。成本每次落账按 6 位小数 ROUND_HALF_UP；检查所有整数存储及中间计算支持范围，溢出整单拒绝。
- 入库成本额为该行实际拿货交易金额换算至内部精度；入库增加数量与成本额，再计算均价。销售出库按过账前库存均价分摊成本，保存实际出库成本额及单位成本参考快照。
- 出清某商品全部剩余数量时，出库成本取剩余库存成本总额，消除舍入尾差；库存归零时库存成本总额必须为零，当前平均成本显示“无库存”，最近成本可另作参考但不参与下次入库。
- 同一销售单重复商品行按固定行顺序分摊，每行保留稳定 ID 和实际出库成本。销售不足不允许负库存，不允许以稍后到货作为本次保存依据。
- 退货按原销售行实际出库成本累计比例分摊；本次冲回成本 = 按本次累计有效退货数量计算的累计成本 - 此前有效退货已冲回成本。最后一批全部退完时冲回剩余成本，累计恰好等于原行成本。
- 退货业务金额同样基于原销售行实际金额累计分摊到分，最后一批吸收尾差；不反复用显示单价相乘导致多次部分退货超出原行金额。
- 退货将原行分摊成本加入当前库存总成本，重算当前均价，不把全库均价强行改成原销售成本；原销售行不改写，负向销售/成本贡献记在退货单。
- 报表金额和成本在聚合后显示到分，毛利润由同范围内部净收入与净成本计算。行显示值的舍入可能与汇总差一分，标注“汇总按未舍入成本计算”，不得改动库存流水来凑显示数。

## 5. 单据结构、编号和生命周期

### 5.1 数据边界

- 首版采用独立拿货表及明细、统一库存流水服务；不把没有客户的拿货硬塞入现有 `orders.customer_id NOT NULL`。准确表名、字段及索引由 Phase 0 的迁移设计确定。
- 销售/退货继续共用 `MD` + 8 位业务日期 + 4 位日流水；拿货与退拿货**共用同一套** `NH` + 同格式日期 + 4 位日流水（对齐销售+退货共用 MD 的规则）。取号时必须让过同一天已有的历史 `TN` 退拿货流水，旧单号不重写。流水达到 9999 时明确阻止继续创建，不生成五位流水。
- 已分配编号保留不复用，重编辑保号保日期；事务内生成/占用编号并处理竞争，刷新预览号不占用正式编号。统一单据列表需合并两类存储，不使用会丢失无客户拿货的内连接。
- 拿货不进入客户余额、收款、客户对账和客户价学习；打印操作不产生库存效果。

### 5.2 状态转换

下表适用于新库存业务单据；旧单据按第 3 节处理。

| 动作 | 首版规则 | 库存/成本效果 |
|---|---|---|
| 新建或编辑草稿 | 可改经济字段；已有编号与日期仍保留；草稿不预占库存/可退数 | 无 |
| 草稿转正式或新建正式 | 校验所有行、客户/商品及成本状态，一次事务过账 | 销售出库、拿货入库、退货入库 |
| 正式转草稿 | 禁止 | 无 |
| 正式/已打印重编辑 | 只允许非经济备注，审计并校验版本；客户、明细、数量、价格、类型、日期、成本均锁定 | 无 |
| 打印/补打销售退货 | 仅有效正式/已打印单据进入客户打印；打印计数可变 | 无 |
| 作废 | 必须原因，满足下述末笔规则；冲销、状态、审计同事务 | 用原流水的精确数量/成本反向，不按当前均价另算 |
| 删除 | 草稿可进回收站；生效单据必须先作废，删除不额外冲库存 | 无 |
| 恢复 | 恢复草稿或作废记录的可见性，绝不从作废恢复到正式 | 无 |
| 永久删除/七天清理 | 只清理无生效历史、无引用的草稿；有过账历史的单据及明细、商品/客户关联保留 | 无 |

### 5.3 末笔撤销与引用保护

- 仅当目标单据是其所有涉及商品最后一笔尚未撤销的库存业务，且没有有效关联退货/其他业务引用时，允许作废。多行作为整单判断，任一行不满足则整单拒绝；不部分作废。
- 使用保存的前后数量、成本及来源关系反向，验证反向后非负和成本守恒。已被后续交易使用的拿货不可直接撤销；先撤销依赖交易才可能允许，不能自动级联作废或悄悄重算。
- 销售存在有效退货时不能作废；退货作废按末笔规则冲回其库存，并释放原销售行可退数量。取消草稿不影响可退数量。
- 原销售行 ID 在正式生效后永久稳定，不再执行“删除所有明细再插入”；历史追溯字段、成本快照与来源 ID 不被普通备注修改覆盖。
- 商品或客户可以停用/隐藏以阻止新普通业务；有效原销售仍允许按来源退货，明确提示资料已停用。有历史流水/引用的资料不可物理删除或清空其外键。
- 作废是错单纠正，不是客户退货；它移除原业务日期的有效统计贡献，保留实际撤销时间的审计记录，不重写历史订单日期。

### 5.4 原子性、幂等与并发

- 库存校验、退货额度校验、编号分配、订单/明细、库存流水、成本快照、状态及关键审计同一事务提交。任何失败整单回滚，不遗留孤立客户、商品或部分库存。
- 正式保存请求使用幂等键与请求内容摘要：相同键同内容返回原单据；相同键不同内容返回冲突。响应丢失后重试不再次扣库、不重学售价、不新增编号。
- 两个窗口同时销售或退货必须在写事务内重新校验，结合数据库唯一约束和版本校验，最多允许符合剩余量的请求成功。不能只依赖前端按钮禁用。
- 过期版本的编辑、作废和恢复请求明确冲突，提示刷新，不覆盖新状态。数据库忙/锁等待超时给出可重试反馈，不泄漏内部异常或绕过校验。

## 6. 客户退货与资金边界

- 来源必须是同一客户、有效的新库存销售单；每个退货行关联其原销售行，行内数量不得超过原行数量减有效退货数量。重复提交与合法的多次部分退货分开处理。
- 同一原单多行相同商品仍分别关联，不能按商品名合并额度。退货草稿不占额度，正式保存时再次检查。
- 原销售已作废、原行不存在、缺可靠历史成本均阻止新退货。来源被软删除但仍有效的旧异常状态先按迁移规则处理，不自动修复。
- 退货订单总额是负数，客户应收随之减少；它不自动代表现金退款已发生。客户余额为负时表示预收/应退余额，不直接显示“已结清”。
- 账款仍按客户期初 + 有效销售/退货 + 有效调整 - 有效收款计算；本轮不引入订单级“部分结算/已结清”或付款分配。

## 7. 分析指标与筛选契约

### 7.1 金额符号与范围

| 指标 | 定义 |
|---|---|
| 原始订单金额 | 销售总额正、退货总额负；现有明细金额是非负值，不按类型对有符号总额重复改号 |
| 展示销售额/退货额 | 分别汇总有效销售及有效退货绝对金额，均为非负展示值 |
| 净销售额 | 展示销售额 - 展示退货额，也等于同范围有符号订单金额之和 |
| 净销售成本 | 销售实际成本快照 - 退货实际冲回成本，允许区间净值为负 |
| 毛利润 | 净销售额 - 净销售成本；不包含拿货现金支出或费用 |
| 毛利率 | 净销售额大于零且成本完整时计算；净销售额小于等于零显示“不适用” |
| 单件毛利 | 单位一致、净数量大于零且成本完整时计算；否则“不适用” |
| 当前库存金额 | 当前库存内部总成本；不受历史时间、客户筛选重算 |
| 拿货金额 | 独立入库成本指标，不进入净销售额/毛利润 |

- 有效业务为正式保存/已打印、未作废、未软删除；拿货无打印状态要求。草稿和被撤销业务不计有效发生额。
- 退货使用退货单业务日期参与区间统计，不回写原销售日期。跨期退货可以导致区间净额、净成本或毛利润为负，这是结果，不归零。
- 旧采购统计继续不扣退货；工作台新增经营指标统一标“净销售额/毛利润”，不能把旧销售额标签悄悄改成另一口径。

### 7.2 筛选与展示

- 日期区间含起止两天，以本地日历为准；本周从周一开始。本月/本季/本年快捷范围截止当天。非法日期或倒序明确提示，不交换、不默认变成全量。
- 首版商品名称单选或“全部”；选名称后型号单选或“全部型号/未填写型号”。无名称时型号禁用。商品筛选按稳定商品 ID 集合解析，不把历史名称文本当唯一身份。
- 客户筛选为唯一客户 ID，不以模糊文本自动归属；不存在/不唯一明确提示。客户筛选启用时拿货金额显示“不适用”，不伪造成该客户采购成本；当前库存仍是全店对应商品库存并清楚标识。
- 净销售热力图及利润区域固定销售+客户退货，不提供会破坏净值定义的单据类型切换。拿货类型筛选只用于拿货清单；对账可以单独筛销售/退货/全部。
- 热力图金额默认净销售金额；净数量只能在同一单位范围启用。全商品多单位范围禁用净数量汇总并提示按商品或单位一致范围筛选，不新增单位换算。
- 热力图零值/无交易分别标识；正值沿用现有色阶，负值增加负号与明确负值提示，不能按正值色阶截成零；悬停/详情展示完整销售、退货、净值。仅做必要语义增补，不重做配色体系。
- 热销/低销量按同单位的净数量分组排序；低销量定义为期间有有效销售且净数量大于零的升序结果。净数量小于等于零者单列“退货抵销/净退货”，不算未销售。
- 未销售为期末前已建档、当前未删除/停用且区间没有有效销售的商品；有销售又全部退回不算未销售。其他历史销售/利润明细保留已停用商品，不静默丢单。
- 数量排行按单位分组；金额/毛利跨单位可比较。首屏排行每组前 10 项，可查看完整分页结果；并列按 product_id 稳定排序，未知成本不进入利润名次且显示排除数量。
- 缺货优先：库存为零；其次库存小于等于安全库存为告急；大于安全库存为正常。安全库存非负，库存告急总数包含缺货，但列表分类不重复计数。
- 同一聚合服务提供图、表、汇总及下钻，分页不改变汇总范围。超过一年的日期范围按年度切换热力图展示，汇总仍使用完整选区，界面标明图的当前年度，不静默截断全部统计。

## 8. 客户对账与打印

- 首版必须选一个客户，按完整订单选择，不提供明细行部分勾选。商品筛选不作用于对账，避免打印部分商品却计整单金额；需要按商品的分析去分析页。
- 默认选中当前客户、日期、单据类型条件下所有有效销售/退货单，包含其他分页；页面同时显示“已选数/符合条件总数”，全选/取消全选均针对完整结果集。
- 服务端保存或签发该次结果集合与版本信息，以选中 ID/排除 ID 表达选择，不只使用当前页 DOM。翻页保留选择；改变客户/日期/类型重新查询并重置全选，给出提示。
- 查询后新增单据不悄悄加入已选快照；打印前服务端重新验证客户、有效状态、版本和金额。发现选中单据变化则阻止并要求刷新确认；伪造其他客户 ID、失效 ID、空选择一律拒绝，不静默漏单。
- 对账合计是选中有效订单的有符号总额之和；同一单据多条明细不能重复累计订单总额。允许仅选择退货得到负合计。
- 对账单是交易核对清单，不是当前应收余额：不混入期初、收款、调整，也不自动写收款、结算或退款。标题和合计使用“交易对账净额”。
- 客户打印数据使用独立业务字段白名单：客户、日期、编号、类型、商品名称/型号/单位/数量、销售单价（退货展示原销售单价）、销售或退货业务金额、合计、客户备注和签字区；现有公司抬头、页码及打印配置文案继续按已确认模板保留。退货最终金额以累计分摊为准，不能再用显示单价乘数量覆盖尾差结果。成本、拿货价、利润、库存、货源及内部备注不能进入模板上下文或 PDF。
- 客户备注是明确对外的白名单字段，保留既有销售/退货打印用途；客户备注与内部备注分开，不得自动复制内部备注或把货源写入客户备注。对账只输出其允许的客户业务备注，不拼接商品内部备注。PDF 不加入商品图片和其他内部附件。
- 从首次引入内部字段起即运行打印数据白名单及敏感哨兵值测试，覆盖销售、退货、对账、历史汇总和桌面预览入口；数据边界断言与 PDF 文本检查同时进行，不只找“成本”标题。
- 保持 A4 竖版、现有销售/退货偏移适用范围；新对账遵循汇总类不受销售偏移影响的规则。对外字段增补不得改变已确认版式；预览、尺寸、偏移、原生保存、实打分别验收。
