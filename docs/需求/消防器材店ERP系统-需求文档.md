## 2. 产品定位与安全边界

简单ERP 是面向单机门店的本地进销存/开单工具，当前覆盖客户、商品、销售与退货单、账款、统计、导入导出、打印和设置。主要技术路线为 Flask + SQLite，Windows 版可用 PyWebView 桌面壳运行。

**当前版本永久免登录。** 服务默认只监听本机回环地址 `127.0.0.1`；`/health` 公开且返回 `auth: disabled`。携带 `Origin` 或 `Sec-Fetch-Site` 的写请求会执行同源检查，明确跨源请求被拒绝；缺少这两类头部的本地非浏览器请求仍由具体路由校验。该检查不是身份认证。免登录意味着任何能够访问服务端口的人都可能操作业务数据，因此不得把服务改为对局域网或公网开放，也不得把“本机单机使用”描述成有账号权限保护。

## 3. 当前实现范围

| 模块 | 当前行为 |
|---|---|
| 开单 | 支持销售单、退货单；新建默认日期为当天且允许选择业务日期；单号按 `MD` + `YYYYMMDD` + 四位流水生成，销售与退货共用当天流水；重编辑保留原单号和原日期。新建仅可选草稿/正式保存；已保存或已打印单据可通过独立作废动作填写原因，普通重编辑不可静默作废。退货重编辑保留退货类型和负数金额。商品可使用客户价或常规价，订单金额由后端计算；超出支持范围的单价、数量或总额会被拒绝。新建销售/退货页表单下方可快捷回看、重编辑业务日期为当天的有效单据。 |
| 单据管理 | 按客户、日期和单据类型筛选；支持按年、月区间（可跨年）和日期区间查询；列表支持销售/退货区分。三种时间模式共用固定的筛选/清除/三个导出操作区。 |
| 客户采购统计 | 统计有效销售单；可按唯一客户或全店范围查看按日金额、次数、商品排行；退货单不计入采购统计。客户匹配不唯一时提示而不将统计误归给某客户。 |
| 客户与商品 | 提供基础资料增改、查询及相应列表操作；客户价与常规价用于开单取价。客户和商品可下载模板并导入 `.xlsx` / `.csv`；列表支持 Excel 导出。导入同名项按当前规则跳过，不覆盖已有资料。 |
| 单据与报表导出 | 单据管理可导出销售单、退货单明细 Excel；货款汇总表为 PDF，支持在筛选范围内按客户分段。 |

| 系统设置 | 可设置公司名称、浅色/深色/跟随系统主题、界面缩放及字体粗细（标准/稍粗/加粗，旧配置默认标准；只影响界面、不影响打印）、打印文案及打印位置校准；可查看数据根目录，并通过设置执行数据目录迁移。桌面壳提供原生选文件夹/保存 PDF 能力。 |
| 桌面运行 | Windows PyInstaller one-folder 程序由 `简单ERP.exe` 启动，内含本地服务与桌面界面；源码运行与打包运行的数据根目录不同。 |

### 3.1 数据目录

- 源码运行默认将业务数据放在项目根目录下的 `data/`、`backups/`、`logs/`、`imports/` 等运行目录；数据库默认路径为 `data/erp.db`。
- 冻结桌面版首次运行默认使用 `%USERPROFILE%\Documents\简单ERP数据` 作为数据根目录。
- 当前数据根路径记忆文件为 `%LOCALAPPDATA%\简单ERP\data_location.json`，它只保存路径，不是业务数据库。
- `config.json` 属于程序配置；升级桌面版时先备份当前业务数据，只替换程序文件，不覆盖用户数据目录。

### 3.2 打印规格

- 销售单、退货单、客户货款汇总 PDF、设置页 HTML 样张及样张 PDF 默认统一为 **A4 竖版（210 × 297 mm）**。
- 销售/退货单内容改为正向阅读的 A4 竖版布局；旧 **241 × 140 mm** 单据版心不再作为当前版式要求。销售/退货单页面左右各留 12 mm，版心宽 186 mm。
- 设置页偏移 X/Y 默认 0 mm、缩放 1.0；这些校准值仅作用于销售/退货单及设置页样张，不作用于账款汇总 PDF。
- 打印驱动建议选择 A4 纵向、实际大小/100%，关闭“适合页面/缩放”。历史 `NantianPR-LQ` 记录及选项见 [Windows 桌面版打包/使用说明](../Windows桌面版打包说明.md)，但目标设备实打尚未验证。
- PDF 页框和自动化测试通过，不等于目标打印机纸面位置已确认；更换打印机、驱动或纸张后仍需实机校准。
- **桌面预览导航（2026-09-30 已实现并完成 fresh EXE 用户验收）**：桌面壳内的 PDF 预览页提供「返回上一级」入口，优先返回进入预览前的合法 ERP 来源页；缺少合法来源时回到工作台，不依赖浏览历史。订单、汇总和设置样张 PDF 共用预览模板，浏览器直接 PDF 行为保持不变；返回参数限制为本地内部路径。当前源码已重新构建为 fresh V1.1.0 one-folder EXE，哥哥在隔离 100 条演示数据环境中实际确认统一预览、A4 内容和返回路径正常。普通浏览器 PDF 直接预览/下载行为不变，本轮未调整 PDF 生成、纸张规格和打印偏移；目标打印机实打及桌面原生保存文件独立核对仍未完成。

### 3.3 已实现于源码：开单页当天历史与单据管理筛选区（2026-09-29 确认）

- 新建销售单与新建退货单页的表单下方增加「当天历史开单」，展示销售、退货单据；「当天」按运行机器的本地日历日与单据 `order_date`（业务日期）判断，**不按录入或修改时间判断**。今天补录或修改昨天的单只归昨天，不进入今天列表。开单表单选择其他业务日期不改变该区域的“当天”范围；重编辑页暂不展示此区域。
- 快捷列表按新单在前，显示单号、客户、类型、金额、状态，提供回看和可编辑单据的修改入口；保留独立单据管理的完整筛选能力。默认只显示未软删除的有效销售/退货单（正式保存、已打印）；作废与删除不作为可修改单据。空列表有明确空状态。异步保存成功后，当前页能看到符合当天范围的新单，补录旧业务日期时不错误混入。
- 从正在填写且未保存的新单离开前给出丢失内容的确认，成功保存后的回看/继续开单路径保持可用；不改变既有日期、单号、金额与打印语义，也不新增数据表。
- 单据管理的按年、按月、按日到日三个时间模式按钮**各自独立、有间距、完整圆角**，不能使用连体按钮组；切换时仅替换日期输入字段。五个操作始终保留为「筛选」「清除筛选条件」「导出汇总表」「导出销售单Excel」「导出退货单Excel」，布局和文案在模式切换后保持一致。日期控件和操作行分区留白，三个导出操作相邻成组，不随着模式切换漂移。切换模式本身只更换输入项，点击「筛选」才更新结果；导出链接跟随当前有效输入项。
- 导出汇总表保留当前“销售+退货、忽略列表订单类型”口径，两个 Excel 导出各自固定销售或退货，不借 UI 调整改动业务查询。可交互原型已由用户确认并按后续反馈同步调整；Windows 隔离数据库全量回归 `151 passed`，真实 Chrome 通过源码页面验证三个时间按钮相邻间距各 8px、切换选中态正常、五操作按钮仍在；此前验证三种模式五按钮位置与 24px 区间不变、当天保存立即出现、补录昨天不混入、点击回看进入对应单据；1440/1024 宽度目视检查通过。430px 桌面式窄窗仍见原有侧栏和横向布局限制，不作为本轮移动端通过依据。桌面 EXE 未重新打包或验证，打印机未实打，也未推送或发布。

### 3.8 已确认的后续业务基线：库存、成本、利润与数据分析

> 本节记录已确认的产品业务规则，不等同于当前源码已经实现。后续实现必须以本节和对应开发短计划为准，并先核对当前代码与其他会话的修改。页面框架、导航结构、现有交互布局、样式、配色、主题、打印预览、PDF 版式和打印偏移均视为已落地基线，本节不要求重做或改版。

**2026-10-01 决策收口**：用户授权按审查建议补齐未决项。完整规则集中在 [库存、成本与客户对账业务契约](./库存成本与对账业务契约.md)，包括状态转换、计价顺序、精度、旧账启用、回收站、并发和对账选择。以下仅作摘要；实现前必须读取该契约，不把旧短计划的开放选项作为并行方案。

#### 商品与期初库存

- 不建立商品分类体系；具体产品由“商品名称 + 型号”识别。
- 同名不同型号是不同产品，分别维护库存、移动平均成本、销售数量、销售金额和毛利润。
- 型号可以为空，但同一商品名称下的空型号只能对应一个具体产品。
- 商品资料承载商品照片、名称、型号、默认销售价、安全库存、备注及当前库存/成本；现有 `spec` 统一作为型号，尺寸补充说明使用备注，不另起重复识别字段。引用使用稳定商品 ID，唯一键包括软删除商品，单位有库存流水后锁定。
- 新商品与存量商品均可一次性初始化期初数量和成本，首笔后续流水后锁定；未知成本不能当零成本。图片保存在数据根并纳入备份/迁移。期初不伪造历史拿货单、供应商或货源。
- 正常使用后库存和成本不能在商品资料中随意改写；盘点或修正需另行形成带原因的库存调整规则，未确认前不擅自扩展。

#### 单据、库存与成本

- 开单业务在既有页面框架内承载销售单、拿货单和退货单；不因本节另起一套视觉页面或打印预览。
- 拿货单沿用多行录入组件，采用独立拿货存储及 `NH` 日期日流水，不进入客户账款、不学习客户售价，首版仅内部详情不打印；销售/退货继续共用 `MD` 流水。拿货记录日期、具体产品、数量、单价、金额和内部货源备注，不建立供应商档案或结算。
- 拿货单增加库存，并参与移动加权平均成本；销售单减少库存；客户退货增加库存。
- 移动加权平均成本由精确库存成本总额与数量计算，不使用显示均价倒算；数量最多 3 位小数、成本内部精度为百万分之一元，交易金额仍为分。期初参与计算，销售不足阻止保存，清空库存消除成本尾差。
- 销售发生时保存当时的成本快照和毛利润。后续拿货改变当前平均成本时，历史销售利润不得变化。
- 客户退货一单关联一张有效原销售，逐行关联稳定销售明细 ID，支持部分退货，正式提交重新校验额度；首版退款业务金额按原销售实际行金额分摊，不允许自定义退款价。
- 退货按原销售实际成本累计分摊并处理最后一次尾差，加入当前库存总成本后重算均价；退货业务日期记负向销售/成本贡献，不改原销售数据，也不自动支付现金退款。
- 计价按不可变过账顺序，报表按业务日期；允许有效日期补录但不重算已有销售成本。正式单据经济字段锁定。**（2026-10-07 更新）**：删除不再受「无后续商品流水/有效退货依赖」限制——用户确认移动均价只是内部预期参考、不据此定售价、不进对外打印，删非末笔单据时均价会按移动加权平均重算（可能漂），但库存数量、销售金额、账款余额精确；「库存不得为负」的守恒校验保留。删除、恢复、七天清理不得重复生效或破坏追溯。
- 旧账保留原金额、单号、日期和余额，不补造库存/成本；启用后旧正式单据经济字段只读。缺成本旧销售不直接走新库存退货，混合报表明确成本覆盖范围，不能用零成本冒充可计算利润。
- 统计使用毛利润/毛利率，不把房租、人工、水电、税费等经营费用纳入“净利润”。

#### 内部信息与对外打印边界

- 现有开单页面和内部详情可以显示当前成本、销售时成本、预计/已固定毛利润、毛利率、库存变化和货源备注。
- 客户签字的销售/退货打印预览、PDF 和对账单不得显示成本价、拿货价、毛利润、毛利率、库存、库存金额、货源、内部备注或图片附件；内部字段首次引入即做白名单与敏感值测试，不延后到最后一阶段。
- 该边界通过打印数据白名单或独立模板数据实现，不依赖 CSS 隐藏。A4 竖版尺寸、既有打印预览流程、样式、配色、页面布局和偏移校准保持不变；打印机实打仍按既有规则单独验收。

#### 数据分析与客户对账

- 数据分析沿用已实现的页面框架和视觉基线，首版商品名称单选/全部、型号单选/全部/未填写型号，客户精确到 ID；不新增分类。旧客户采购统计保留原有效销售口径，新中心明确使用净销售口径。
- 商品名称不选时统计全部具体产品；只选商品名称时汇总该名称下全部型号；同时选择型号时只统计对应具体产品。开单必须精确到商品名称 + 型号，分析允许只选商品名称。
- GitHub 提交图式热力图按日展示销售活跃度，可按商品名称、可选型号、时间、净销售数量或净销售金额筛选。热力图下方沿用同一筛选范围显示销售额、销售成本、毛利润、毛利率及具体产品明细。
- 展示退货额为退货绝对金额，净销售额为销售额减展示退货额，等于有符号订单总额之和；净销售成本扣除退货冲回成本。跨期退货按退货业务日期统计。不同单位不直接合计数量，净销售额小于等于零时毛利率不适用，缺成本时不展示伪造的全量毛利。
- 分析提供热销、低销量、未销售、毛利润和库存告急等具体产品结果。库存告急按当前库存与商品安全库存判断；当前库存状态不得被历史时间筛选回溯替代。
- 对账必须选一个客户，按完整单据选择，默认全选完整筛选结果（跨页），不支持明细行部分选择或商品过滤；更换筛选重置选择，打印前重新校验选择快照和版本。合计为选中有效订单有符号金额之和，不重复累计明细。
- 对账单只输出业务字段和签字区域，标题/合计明确为交易核对与交易对账净额，不含期初、收款或调整，不等于当前欠款。打印不产生收款、结算或退款；账款保持客户余额层面，不新增逐单核销。

#### 页面职责冻结说明

- 工作台继续负责当前经营概览和快捷入口；开单负责产生销售、拿货、退货业务；基础资料负责商品和客户资料；单据管理负责查询和追溯；数据分析负责筛选、热力图、排行、利润和对账单；账款负责实际收款与结算。
- 以上是业务职责边界，不是本轮 UI 改版要求。现有页面框架、导航、布局、组件结构、样式、配色、主题、间距、交互视觉和打印预览均不得因本节业务扩展而被重做。
