## 2. 产品定位与安全边界

简单ERP 是面向单机门店的本地进销存/开单工具，当前覆盖客户、商品、销售与退货单、账款、统计、导入导出、打印和设置。主要技术路线为 Flask + SQLite，Windows 版可用 PyWebView 桌面壳运行。

**当前版本永久免登录。** 服务默认只监听本机回环地址 `127.0.0.1`；`/health` 公开且返回 `auth: disabled`。携带 `Origin` 或 `Sec-Fetch-Site` 的写请求会执行同源检查，明确跨源请求被拒绝；缺少这两类头部的本地非浏览器请求仍由具体路由校验。该检查不是身份认证。免登录意味着任何能够访问服务端口的人都可能操作业务数据，因此不得把服务改为对局域网或公网开放，也不得把“本机单机使用”描述成有账号权限保护。

## 3. 当前实现范围

| 模块 | 当前行为 |
|---|---|
| 开单 | 支持销售单、退货单；新建默认日期为当天且允许选择业务日期；单号按 `MD` + `YYYYMMDD` + 四位流水生成，销售与退货共用当天流水；重编辑保留原单号和原日期。新建仅可选草稿/正式保存；已保存或已打印单据可通过独立作废动作填写原因，普通重编辑不可静默作废。退货重编辑保留退货类型和负数金额。商品可使用客户价或常规价，订单金额由后端计算；超出支持范围的单价、数量或总额会被拒绝。 |
| 单据管理 | 按客户、日期和单据类型筛选；支持按年、月区间（可跨年）和日期区间查询；列表支持销售/退货区分。 |
| 客户采购统计 | 统计有效销售单；可按唯一客户或全店范围查看按日金额、次数、商品排行；退货单不计入采购统计。客户匹配不唯一时提示而不将统计误归给某客户。 |
| 客户与商品 | 提供基础资料增改、查询及相应列表操作；客户价与常规价用于开单取价。客户和商品可下载模板并导入 `.xlsx` / `.csv`；列表支持 Excel 导出。导入同名项按当前规则跳过，不覆盖已有资料。 |
| 单据与报表导出 | 单据管理可导出销售单、退货单明细 Excel；货款汇总表为 PDF，支持在筛选范围内按客户分段。 |
| 账款 | 按客户汇总余额；实现口径为期初余额 + 有效单据金额 + 有效调整 - 有效收款。支持按客户/日期查看账款，并提供收款、账务调整及汇总 PDF 流程。 |
| 系统设置 | 可设置公司名称、浅色/深色/跟随系统主题、界面缩放、打印文案及打印位置校准；可查看数据根目录，并通过设置执行数据目录迁移。桌面壳提供原生选文件夹/保存 PDF 能力。 |
| 桌面运行 | Windows PyInstaller one-folder 程序由 `简单ERP.exe` 启动，内含本地服务与桌面界面；源码运行与打包运行的数据根目录不同。 |

### 3.1 数据目录

- 源码运行默认将业务数据放在项目根目录下的 `data/`、`backups/`、`logs/`、`imports/` 等运行目录；数据库默认路径为 `data/erp.db`。
- 冻结桌面版首次运行默认使用 `%USERPROFILE%\Documents\简单ERP数据` 作为数据根目录。
- 当前数据根路径记忆文件为 `%LOCALAPPDATA%\简单ERP\data_location.json`，它只保存路径，不是业务数据库。
- `config.json` 属于程序配置；升级桌面版时先备份当前业务数据，只替换程序文件，不覆盖用户数据目录。

### 3.2 打印规格

- 销售单、退货单、客户货款汇总 PDF、设置页 HTML 样张及样张 PDF 默认统一为 **A4 竖版（210 × 297 mm）**。
- 销售/退货单内容改为正向阅读的 A4 竖版布局；旧 **241 × 140 mm** 单据版心不再作为当前版式要求。销售/退货单页面左右各留 12 mm，版心宽 186 mm。
- 设置页偏移 X/Y 默认 0 mm、缩放 1.0；这些校准值仅作用于销售/退货单及设置页样张，不作用于账款汇总 PDF。
- 打印驱动建议选择 A4 纵向、实际大小/100%，关闭“适合页面/缩放”。历史 `NantianPR-LQ` 记录及选项见 [Windows 桌面版打包/使用说明](../Windows桌面版打包说明.md)，但目标设备实打尚未验证。
- PDF 页框和自动化测试通过，不等于目标打印机纸面位置已确认；更换打印机、驱动或纸张后仍需实机校准。

### 修复前确认、现已修复

- **退货单重编辑符号错误（P0）**：退货单新建时金额为负数，但重编辑路径按销售单正数重算，可能把客户余额从应减变为应收。
- **新建订单状态契约错误（P0）**：页面展示“已打印/已作废”，新建后端只接受 `draft` / `saved`。提交不支持的状态会返回 500，且当前路径可能先创建客户，形成孤立资料。
- **作废动作没有独立闭环（P0/P1）**：普通重编辑可以直接提交 `void`，但没有强制作废原因和清晰的作废操作路径；服务层已有原因校验不能覆盖当前页面路径。

**修复状态（2026-09-25）**：以上三项已完成 Phase 1 实现。退货新建—回看—重编辑—再次回看及余额符号、非法新建状态不产生客户/订单、作废原因/审计和表单状态选项均有隔离 SQLite 行为测试；完整测试结果见执行计划。服务层也会从原订单读取单据类型，数量必须大于 0，作废状态与审计日志在同一事务中提交，退货录入预览和回看明细也显示负数。未据此声称桌面 EXE 或打印机验收通过。

### Phase 4 工作台首版（2026-09-26 已实现并通过隔离验收）

- “今日”按运行机器的本地日历日，使用订单 `order_date` 作为业务日期。
- 今日净业务额为当天未软删除、状态为 `saved` 或 `printed` 的销售/退货订单 `total_amount_cents` 之和。销售金额为正、退货金额为负；草稿、作废和软删除订单不计入。沿用订单已保存的金额符号，不按类型二次改符号。
- 销售笔数与退货笔数分别统计，使用同一有效订单集合。
- 最近业务显示最近 5 笔有效销售/退货订单，按 `created_at` 录入时间倒序；不限订单业务日期，不包括收款或账务调整。
- 首版不展示全店应收余额，不改变账款口径，不新增数据库表；保留首页现有快捷入口和日常业务流程。
- 原型中的经营数据必须明确标注为虚构示例；该原型已获用户验收，随后完成正式页面实现。Windows 全量回归 `130 passed`；隔离页面核对了有效指标、最近业务、主题、1440/1024/430 CSS px 视口及控制台/网络结果。桌面 EXE 和目标打印机验收独立记录，不能由上述结果推断通过。

### 已确认的账款可追溯性口径（Phase 2）

以下是本轮账款流水改造的已确认产品要求。

**实现状态（2026-09-26）**：统一流水、当前余额/区间发生额、作废留痕与调整、独立账款流水 PDF 已实现；完整隔离测试 `119 passed`。用户已手动确认正确调整新增流程和浏览器 PDF 预览通过。随后在隔离 Windows EXE 中有限观察主题设置及一份销售单 PDF 保存；用户另确认 Windows 端键盘完整流程、订单列表分页与视口矩阵通过。完整主题矩阵、控制台与其他 PDF 保存路径未验收；PDF 预览页无法返回 ERP 已登记为确认问题，目标打印机仍未实打。

- 日期筛选不改变客户当前余额。账款页始终显示全历史当前余额，并另列筛选区间的发生额/净变动；期初余额不计入区间发生额。
