## 2. 产品定位与安全边界

简单ERP 是面向单机门店的本地进销存/开单工具，当前覆盖客户、商品、销售与退货单、账款、统计、导入导出、打印和设置。主要技术路线为 Flask + SQLite，Windows 版可用 PyWebView 桌面壳运行。

**当前版本永久免登录。** 服务默认只监听本机回环地址 `127.0.0.1`；`/health` 公开且返回 `auth: disabled`。携带 `Origin` 或 `Sec-Fetch-Site` 的写请求会执行同源检查，明确跨源请求被拒绝；缺少这两类头部的本地非浏览器请求仍由具体路由校验。该检查不是身份认证。免登录意味着任何能够访问服务端口的人都可能操作业务数据，因此不得把服务改为对局域网或公网开放，也不得把“本机单机使用”描述成有账号权限保护。

### 3.1 数据目录

- 源码运行默认将业务数据放在项目根目录下的 `data/`、`backups/`、`logs/`、`imports/` 等运行目录；数据库默认路径为 `data/erp.db`。
- 冻结桌面版首次运行默认使用 `%USERPROFILE%\Documents\简单ERP数据` 作为数据根目录。
- 当前数据根路径记忆文件为 `%LOCALAPPDATA%\简单ERP\data_location.json`，它只保存路径，不是业务数据库。
- `config.json` 属于程序配置；升级桌面版时先备份当前业务数据，只替换程序文件，不覆盖用户数据目录。
- 设置页「备份与恢复」列表逐份显示**备份内的库结构版本**（`schema_version`）；版本低于当前的备份标「旧版结构」，并在行内红字与恢复确认框中提示：恢复并重开程序后会自动升级到当前版本，**库存与成本数据将被永久删除、无法回退**（v15 升级不可逆，回退只能靠迁移前自动生成的整库备份）。
- 设置页提供**「清空所有数据」**：清空全部业务数据（四类单据、客户/商品、账款、对账快照、审计日志、单号序列表与 `product_images/`、`temp_pdf/`、`logs/` 内容）并把设置回出厂；**保留** `backups/`、`legacy_archive/` 与数据目录路径记忆，`data/erp.db` 文件本身不删除。执行前自动备份并要求输入确认词「清空」，且保留当天已打出的 MD/NH 单号流水高位，避免新单与纸质单撞号。

### 3.2 打印规格

- 四类开单（销售/退货/拿货/退拿货）走 **241mm 连续纸**（逻辑页 215.9×139.7mm、页内左右各 7.3mm 版心）；客户货款汇总、往来对账单走 **A4 竖版（210×297mm）**。两套模型不得混用。
- **单联容量默认 10 行，可在设置页选 6 / 8 / 10 / 12**（2026-10-14 起由常量改为配置项；第 N+1 行起自动进下一联）。每张纸末尾给合计：非末张为**本张合计**（该张小计之和）并附续打提示行「本张已满 N 行；因行数限制，以下内容续打在第 N 张」，末张为**本单合计**；页脚（订货电话/地址/签字/备注）只落在最后一联。容量靠压单元格内边距换来（≤10 行 0.9mm、12 行 0.4mm），**字号层级不变**；逐档行几何与「满档位仍容得下一行品名折行」有契约测试（`tests/test_slip_geometry_tiers.py`），纸面位置仍须目标打印机实打验收。
- 设置页偏移 X/Y 默认 0 mm、缩放 1.0；这些校准值仅作用于四类开单及设置页样张，不作用于账款汇总/对账 PDF。
- 打印驱动建议选择 A4 横向、实际大小/100%，关闭“适合页面/缩放”（连续纸由驱动居中映射）。历史 `NantianPR-LQ` 记录及选项见 [Windows 桌面版打包/使用说明](../Windows桌面版打包说明.md)，但目标设备实打尚未验证。
- PDF 页框和自动化测试通过，不等于目标打印机纸面位置已确认；更换打印机、驱动或纸张后仍需实机校准。
- **桌面预览导航（2026-09-30 已实现并完成 fresh EXE 用户验收）**：桌面壳内的 PDF 预览页提供「返回上一级」入口，优先返回进入预览前的合法 ERP 来源页；缺少合法来源时回到工作台，不依赖浏览历史。订单、汇总和设置样张 PDF 共用预览模板，浏览器直接 PDF 行为保持不变；返回参数限制为本地内部路径。当前源码已重新构建为 fresh V1.1.0 one-folder EXE，哥哥在隔离 100 条演示数据环境中实际确认统一预览、A4 内容和返回路径正常。普通浏览器 PDF 直接预览/下载行为不变，本轮未调整 PDF 生成、纸张规格和打印偏移；目标打印机实打及桌面原生保存文件独立核对仍未完成。
- **打印用店铺信息引导（2026-10-09 已实现，E-5）**：打印件上的「订货电话 / 订货地址」没有出厂默认值，迁移用户不填就会印成空白。工作台在**这两项为空**时显示一条引导卡（标题「打印单上还有空白」，含缺哪些字段、一条通往「系统设置 → 打印单信息」的链接、以及「不再提示」），补全后自动消失。设置页「打印单信息」卡片同步显示缺失告警，并提供「不再提示 / 重新打开提示」的对称开关。**「主营业务」与「备注（法律句）」有出厂文案，不算缺失**——把它们计入会让提示永远挂着、退化成噪声。关闭开关只写一个布尔配置，不改任何打印字段。口径集中在 `config.missing_print_info_fields`，页面与路由共用一处，避免漂移。

#### 单据与账款

- 开单业务在既有页面框架内承载四类单据（销售 / 退货 / 拿货 / 退拿货）；不因本节另起一套视觉页面或打印预览。
- 单号：销售/退货共用 `MD` + 8 位业务日期 + 四位日流水；拿货/退拿货共用 `NH` 同一日号池（2026-10-06 起；历史 `TN` 单号不重写）。新建日期可改，重编辑保号保日期。
- **拿货 / 退拿货是纯流水单据**（决策 ①）：登记业务金额，进入对账并入与账款抵扣，有打印、回收站与当天历史；**不再影响库存、不产生成本**。拿货单价（`purchase_order_items.unit_cost_cents`）是买卖双方的业务单价，保留。（原 §3.8 写的「拿货不进入客户账款、不学习客户售价、首版不打印」已被 2026-10-06 起的增量覆盖。）

- 旧账保留原金额、单号、日期和余额。删除仍走「作废（自动冲回账款）→ 软删除 → 回收站」，七天清理与「恢复只恢复可见性、不回滚作废」的规则不变；只是不再有库存冲回与守恒校验。
