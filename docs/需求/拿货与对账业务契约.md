## 2. 商品身份、单位与资料

### 2.1 身份与选择

- 商品以稳定 `product_id` 引用；业务唯一键为**规范化名称**（2026-10-13 起型号并入名称、直接拼接，如 `闸阀DN50`）。分析控件不再有型号维度（「全部型号 / 未填写型号」已删除）。
- 规范化只去除名称首尾空白；迁移合并时对名称与型号**各自去空白后拼接**（`TRIM(name) || TRIM(spec)`），保留内部空白、大小写及全半角差异，不自动合并疑似同义商品。检测疑似重复时可提示，不猜测合并。
- 唯一性覆盖软删除商品。相同键存在于回收站时提示恢复，禁止新建同键商品；已有重复数据阻止启用新约束并输出不含私人资料的定位结果，不任意选第一条。
- 开单商品来源分两条路径（2026-10-09「零建档起步」已确认，2026-10-12 回填本契约核对）：
  - **销售 / 退货**：允许在开单页**手输商品名**。命中已有商品则绑定其 ID；未命中则**自动建档**（`origin='order'`，写审计留痕，可在商品页按来源「开单攒出」识别）。这是用户明确要求的第二条起步路径（「别拦我开单」），不是「偷偷建商品」。
  - **拿货 / 退拿货**：**必须选定已建档商品 ID**，后端重新校验，不能只按自由文本名称匹配。
  - 两条路径都允许先在基础资料正规建档后再出单。
- 商品重命名不改变 ID 和历史单据快照。分析按 ID 归集，展示当前名称；历史单据和对外打印保留成交时快照。改名后的业务键仍检查唯一性。
- 一件商品只使用一种单位；不做箱/个、米/卷换算。**单位修改分两个入口，行为不同（2026-10-12 用户拍板，均为有意设计）**：
  - **商品编辑页**：修改即同步商品档案单位；单位修改不再受库存因素影响。
  - **开单页（销售 / 退货）**：允许**顺手改**并同步商品档案单位——门店效率优先，刻意不在此处加锁定校验。
  - **拿货 / 退拿货页**：单位可编辑但**只作用于本单明细**，**不回写商品档案**；跨单记忆由单位候选池承担（默认三项 ∪ 商品档案 ∪ 四张明细表）。
  - **来源带入的默认值（2026-10-13 用户拍板）**：退货单从销售单带入时，明细单位**优先沿用源销售单的快照单位**；退拿货从拿货单带入时，**优先沿用源拿货单的快照单位**。两者都**允许用户修改**，仅改本单明细。
- **单位变更不做任何数量换算**：不同单位的数量不直接相加或跨单位排名。

### 2.2 售价与拿货单价

- 销售取价唯一来源 = **该客户的专属价**（2026-10-15 起：商品档案已无售价字段、开单行上的「常规价」勾选项已删除；有专属价才带出，没有则留空手输，手输价大于 0 才学成专属价）。只在成功的销售保存路径按已定规则处理；拿货、退货、打印、重试不能改变客户价。
- 拿货单价不写入客户专属价，不更新商品单位（拿货页可编辑的单位只作用于本单明细，见 §2.1）。
- 商品档案不再有默认售价（2026-10-15 起）；开单单价无专属价时**留空手输**，手输价大于 0 才学成该客户的专属价。

- 商品导入模板只含**商品名称**（2026-10-13 起不再有「型号」列：含「型号」的旧文件按整表头精确校验直接报「表头错误，应为：…」，明确报错而不是静默丢数据；请把型号写进商品名称，如 `闸阀DN50`）。重复按规范化名称判断，含软删除项；保持逐行报告并跳过，不覆盖客户价或历史快照。
- 导入只建商品资料，不接收图片路径批量覆盖；商品导出不再含型号列。客户导入规则不因本次商品身份改动而扩大。

### 2.3 图片

- 图片保存在数据根的专用商品图片目录，数据库保存相对路径，不保存任意本机绝对路径；纳入备份、恢复与数据目录迁移验证。
- 首版仅支持 JPEG/PNG，单文件不超过 5 MiB、解码像素总数不超过 20 百万；后端校验并重编码，使用系统生成文件名，不信任扩展名，不接收 SVG 或路径穿越输入。
- 替换图片失败不得丢失旧图；业务备份不得依赖源码目录。首版不把商品图片加入客户 PDF，不改变版式。测试只能使用虚构图片。

## 3. 历史兼容与迁移验收

### 3.1 旧单据

- 迁移前已保存/已打印及其他历史订单标记为旧账业务；金额、单号、业务日期、客户余额、历史快照保持原样。
- 原有软删除旧单据仍可追溯，但不恢复其财务生效状态；旧账纠错继续通过有原因的账务调整处理。
- 旧草稿没有业务效力；以后正式保存时必须按新规则重新选择商品，仍保留其原单号/日期约束。
- 旧单据继续进入销售/退货金额、客户账款和对账统计。

### 3.2 迁移验收

- 结构迁移只新增必要结构/兼容标记，不自动扣减旧销售，不凭旧订单推测。
- 使用构造的旧版数据库夹具，不读写正式业务库来造测试。迁移需有版本推进、重复执行不重复迁移、约束/外键检查、失败回滚或备份恢复实测。
- 升级前必须有一致性数据库备份和图片备份；SQLite 使用备份机制获取一致性快照，不能在运行中仅复制主库文件而遗漏 WAL 数据。
- 验证旧订单金额/编号/日期、客户余额和旧打印结果不变；重复商品、断开的商品引用、超精度历史数量只报告阻塞，不擅自清洗。
- 恢复路径是停止新程序后恢复备份并使用兼容旧程序，不允许旧 EXE 在新结构上继续写入。启动版本检查拒绝不支持的数据库版本；不得把“逆向 SQL 降级”当唯一恢复方式。
- 结构迁移、业务启用和正式数据操作分别授权。本轮文档授权不包含正式库升级。
- 销售、退货、拿货全链路闭环未共同通过前，只能在隔离环境验证；实际切换需另行授权，先停止旧写实例并完成一致性备份，不得让新旧写路径同时写同一业务库。

## 4. 时间与数量计量

### 4.1 业务日期

- `order_date` 用于销售、退货、拿货报表。
- 允许补录业务日期，但不得晚于本地当天；退货业务日期不得早于原销售日期。

### 4.2 精度

- 新业务数量最多 3 位小数，使用 Decimal 或精确的千分单位整数；拒绝 NaN、无穷、超精度和超范围输入，不能先转二进制浮点。单据数量必须大于零。
- 对外售价、拿货录入单价及交易金额使用人民币分整数；现有行金额采用 ROUND_HALF_UP。
- 退货业务金额同样基于原销售行实际金额累计分摊到分，最后一批吸收尾差；不反复用显示单价相乘导致多次部分退货超出原行金额。
- 报表金额在聚合后显示到分。行显示值的舍入可能与汇总差一分，标注“汇总按未舍入金额计算”。

## 5. 单据结构、编号和生命周期

### 5.1 数据边界

- 拿货 / 退拿货采用独立单据表及明细，并与销售 / 退货共用统一「往来对象」（2026-10-02 起按每笔实际买卖定义角色，见本文开头的覆盖说明）。
- 销售/退货继续共用 `MD` + 8 位业务日期 + 4 位日流水；拿货与退拿货**共用同一套** `NH` + 同格式日期 + 4 位日流水（对齐销售+退货共用 MD 的规则）。取号时必须让过同一天已有的历史 `TN` 退拿货流水，旧单号不重写。流水达到 9999 时明确阻止继续创建，不生成五位流水。
- 已分配编号保留不复用，重编辑保号保日期；事务内生成/占用编号并处理竞争，刷新预览号不占用正式编号。统一单据列表需合并两类存储，不使用会丢失无客户拿货的内连接。
- 拿货 / 退拿货登记业务金额，**进入对账并入与账款抵扣**，有打印、回收站与当天历史；拿货 **不学习客户专属价**（拿货单价是买卖双方的业务单价，与客户售价无关）。

### 5.2 状态转换

下表适用于业务单据；旧单据按第 3 节处理。

| 动作 | 首版规则 |
|---|---|
| 新建或编辑草稿 | 可改经济字段；已有编号与日期仍保留；草稿不预占可退数 |
| 草稿转正式或新建正式 | 校验所有行、客户/商品，一次事务提交 |
| 正式转草稿 | 禁止 |
| 正式/已打印重编辑 | 除「已作废」外均可编辑；审计并校验版本 |
| 打印/补打销售退货 | 仅有效正式/已打印单据进入客户打印；打印计数可变 |
| 作废 | 必须原因；状态、审计、账款回冲同事务 |
| 删除 | 草稿可进回收站；生效单据必须先作废 |
| 恢复 | 恢复草稿或作废记录的可见性，绝不从作废恢复到正式 |
| 永久删除/七天清理 | 只清理无生效历史、无引用的草稿；有生效历史的单据及明细、商品/客户关联保留 |

- 作废必须原因：作废是错单纠正，不是客户退货；它移除原业务日期的有效统计贡献，保留实际撤销时间的审计记录，不重写历史订单日期。
- 恢复只能恢复可见性，绝不从作废恢复到正式；原销售行 ID 在正式生效后永久稳定，不再执行“删除所有明细再插入”，历史追溯字段与来源 ID 不被普通备注修改覆盖。
- 商品或客户可以停用/隐藏以阻止新普通业务；有效原销售仍允许按来源退货，明确提示资料已停用。有历史流水/引用的资料不可物理删除或清空其外键。

### 5.3 原子性、幂等与并发

- 退货额度校验、编号分配、订单/明细、状态及关键审计同一事务提交。任何失败整单回滚，不遗留孤立客户、商品或部分明细。
- 正式保存请求使用幂等键与请求内容摘要：相同键同内容返回原单据；相同键不同内容返回冲突。响应丢失后重试不重学售价、不新增编号。
- 两个窗口同时销售或退货必须在写事务内重新校验，结合数据库唯一约束和版本校验，最多允许符合剩余量的请求成功。不能只依赖前端按钮禁用。
- 过期版本的编辑、作废和恢复请求明确冲突，提示刷新，不覆盖新状态。数据库忙/锁等待超时给出可重试反馈，不泄漏内部异常或绕过校验。

## 6. 客户退货与资金边界

- 来源必须是同一客户、有效的销售单；每个退货行关联其原销售行，行内数量不得超过原行数量减有效退货数量。重复提交与合法的多次部分退货分开处理。
- 同一原单多行相同商品仍分别关联，不能按商品名合并额度。退货草稿不占额度，正式保存时再次检查。
- 原销售已作废、原行不存在均阻止新退货。来源被软删除但仍有效的旧异常状态先按迁移规则处理，不自动修复。
- 退货订单总额是负数，客户应收随之减少；它不自动代表现金退款已发生。客户余额为负时表示预收/应退余额，不直接显示“已结清”。
- 账款仍按客户期初余额 + 有效销售/退货 + 有效调整 - 有效收款计算；本轮不引入订单级“部分结算/已结清”或付款分配。

## 7. 分析指标与筛选契约

### 7.1 金额符号与范围

| 指标 | 定义 |
|---|---|
| 原始订单金额 | 销售总额正、退货总额负；现有明细金额是非负值，不按类型对有符号总额重复改号 |
| 展示销售额/退货额 | 分别汇总有效销售及有效退货绝对金额，均为非负展示值 |
| 净销售额 | 展示销售额 - 展示退货额，也等于同范围有符号订单金额之和 |
| 拿货金额 | 独立业务金额指标，不进入净销售额 |

- 有效业务为正式保存/已打印、未作废、未软删除；拿货无打印状态要求。草稿和被撤销业务不计有效发生额。
- 退货使用退货单业务日期参与区间统计，不回写原销售日期。跨期退货可以导致区间净额为负，这是结果，不归零。
- 旧采购统计继续不扣退货；工作台新增经营指标统一标“净销售额”，不能把旧销售额标签悄悄改成另一口径。

### 7.2 筛选与展示

- 日期区间含起止两天，以本地日历为准；本周从周一开始。本月/本季/本年快捷范围截止当天。非法日期或倒序明确提示，不交换、不默认变成全量。
- 首版商品名称单选或“全部”（2026-10-13 起型号并入名称，型号筛选已删除）。商品筛选按稳定商品 ID 集合解析，不把历史名称文本当唯一身份。
- 客户筛选为唯一客户 ID，不以模糊文本自动归属；不存在/不唯一明确提示。客户筛选启用时拿货金额显示“不适用”，不伪造成该客户采购成本。
- 净销售热力图固定销售+客户退货，不提供会破坏净值定义的单据类型切换。拿货类型筛选只用于拿货清单；对账可以单独筛销售/退货/全部。
- 热力图金额默认净销售金额；净数量只能在同一单位范围启用。全商品多单位范围禁用净数量汇总并提示按商品或单位一致范围筛选，不新增单位换算。
- 热力图零值/无交易分别标识；正值沿用现有色阶，负值增加负号与明确负值提示，不能按正值色阶截成零；悬停/详情展示完整销售、退货、净值。仅做必要语义增补，不重做配色体系。
- 热销/低销量按同单位的净数量分组排序；低销量定义为期间有有效销售且净数量大于零的升序结果。净数量小于等于零者单列“退货抵销/净退货”，不算未销售。
- 未销售为期末前已建档、当前未删除/停用且区间没有有效销售的商品；有销售又全部退回不算未销售。其他历史销售明细保留已停用商品，不静默丢单。
- 数量排行按单位分组；金额跨单位可比较。首屏排行每组前 10 项，可查看完整分页结果；并列按 product_id 稳定排序。
- 同一聚合服务提供图、表、汇总及下钻，分页不改变汇总范围。超过一年的日期范围按年度切换热力图展示，汇总仍使用完整选区，界面标明图的当前年度，不静默截断全部统计。

## 8. 客户对账与打印

- 首版必须选一个客户，按完整订单选择，不提供明细行部分勾选。商品筛选不作用于对账，避免打印部分商品却计整单金额；需要按商品的分析去分析页。
- 默认选中当前客户、日期、单据类型条件下所有有效销售/退货单，包含其他分页；页面同时显示“已选数/符合条件总数”，全选/取消全选均针对完整结果集。
- 服务端保存或签发该次结果集合与版本信息，以选中 ID/排除 ID 表达选择，不只使用当前页 DOM。翻页保留选择；改变客户/日期/类型重新查询并重置全选，给出提示。
- 查询后新增单据不悄悄加入已选快照；打印前服务端重新验证客户、有效状态、版本和金额。发现选中单据变化则阻止并要求刷新确认；伪造其他客户 ID、失效 ID、空选择一律拒绝，不静默漏单。
- 对账合计是选中有效订单的有符号总额之和；同一单据多条明细不能重复累计订单总额。允许仅选择退货得到负合计。
- **对账单是单段式往来核对清单（2026-10-15 用户决策，收缩 2026-10-14 的两段式；原打印账款流水 PDF 已合并）**：① 业务单据明细——四类单据按完整单据分组，「整单交易总额」为独立竖列、整列加深、只在单据抬头行印一次；② 表格下方汇总——四类各一个矩形框（上侧类型、下方该类型金额）+ 居中三行文字（资金流水合计、流水总额、汇总）。资金不参与快照指纹，按打印时点实时计算；逐笔资金明细与期初/区间两端欠款不再上纸。打印不写收款、结算或退款；账款保持客户余额层面，不新增逐单核销。签字件向对方披露资金合计属有意决策。
- 客户打印数据白名单：客户、日期、编号、类型、商品名称/单位/数量、销售单价（退货展示原销售单价）、销售或退货业务金额、整单交易总额、四类汇总金额、资金流水合计、客户备注和签字区；现有公司抬头、页码及打印配置文案继续按已确认模板保留。退货最终金额不得用显示单价乘数量覆盖已确认的累计分摊结果。**逐笔收款/调整行（方式、备注、原因、余额影响）自 2026-10-15 起不再上纸，对应字段仍留在服务层投影中但不得进入打印上下文。** 成本、拿货价、利润、库存、货源、内部备注、作废原因不能进入模板上下文或 PDF。
- 客户备注是明确对外的白名单字段，保留既有销售/退货打印用途；客户备注与内部备注分开，不得自动复制内部备注或把货源写入客户备注。对账只输出其允许的客户业务备注，不拼接商品内部备注。PDF 不加入商品图片和其他内部附件。
- 从首次引入内部字段起即运行打印数据白名单及敏感哨兵值测试，覆盖销售、退货、对账、历史汇总和桌面预览入口；数据边界断言与 PDF 文本检查同时进行，不只找“成本”标题。
- 保持 A4 竖版、现有销售/退货偏移适用范围；新对账遵循汇总类不受销售偏移影响的规则。对外字段增补不得改变已确认版式；预览、尺寸、偏移、原生保存、实打分别验收。
