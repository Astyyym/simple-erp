## 1. 需求（用户 2026-11-21 原话）

> 「客户B的手机端根据客户A的手机端进行更新。B 今天没有去上班，但是 A 去了，
> A 的手机端的数据是最新的，在同一 WiFi 下，B 根据 A 进行更新。」

口径确认：**同一套账、B 只看**，明文快照可接受，两端都装 APK。

## 2. 判断：不做手机之间联网同步

手机端是**纯只读**：`app/erp/routes/mobile_api.py` 里除 `/pair` 是 POST，其余全是 GET，
连库用 `mode=ro`。这条约束（架构文档 §4 约束 3/9）决定了一件关键的事：

> **A 手机里没有「B 缺的数据」。它只是店里那台电脑某一刻的镜像。**

所以不存在数据合并、冲突消解、操作日志这一整套东西 —— 只需要把那份镜像搬到 B 上。
联网互传反而要多一整套东西（A 手机起 HTTP 服务、前台服务保活、IP 发现、
同 WiFi 的信任边界），对一个低频场景不划算。

### 被否的方案

| 方案 | 否掉的理由 |
|---|---|
| A 手机起 HTTP 服务，B 连 A 拉 | 前台服务 + 后台被杀 + IP 发现 + 同 WiFi 任人可拉；工程量大，收益一样 |
| 家里 B 直连店里 PC（内网穿透） | 违反 `AGENTS.md`「不得把服务暴露到局域网/公网」，需用户改规则 |
| 双向同步 / 操作日志 | 等于推翻只读架构，另一个量级 |

## 3. 数据包格式

一个 JSON 文件，由 A 通过系统分享面板发出（微信 / 蓝牙 / 文件管理器）：

```json
{
  "kind": "simple-erp-peer-pack",
  "packVersion": 1,
  "apiSchema": 1,
  "appVersion": "1.4.13",
  "shopName": "某某消防",
  "baseUrl": "http://192.168.10.5:5001",
  "syncedAt": 1763700000000,
  "syncMonths": 2,
  "syncFrom": "2026-10-01",
  "syncTo": "2026-11-21",
  "backup_key": "/m/api/orders?...",
  "entries": { "规范化路径": "响应体" }
}
```

- **不含**设备 token / cookie。`baseUrl` 只用于「B 从没配置过地址」时兜底，B 已有地址不覆盖。
- `entries` 的键是服务端 `_canonical_path` 算好的规范化 path，客户端只照抄。
- 文件名用**数据截止时间**（`简单ERP同伴数据_20261121_1730.json`），不是生成时间 ——
  用户在微信里挑文件时靠它分辨新旧。

## 4. 三个必须一起处理的坑

| 坑 | 不处理会怎样 | 处理位置 |
|---|---|---|
| 精确键缓存（`ResponseCache`）优先级高于快照 | 导入后 B 打开过的页面仍亮自己的旧版本，离线时刻新旧混显 | `importPack` 里 `cache.clear()` |
| `syncMonths/syncFrom/syncTo/backupKey` 与 `entries` 是一套 | 只换快照不换区间，断网本地筛选按旧区间把导入数据筛掉 | 一起覆盖 |
| 新手机没地址时停在 `SetupScreen`，够不到设置页 | B 永远导入不了 | `SetupScreen` 加「没有电脑？导入同伴的数据包」 |

## 5. 连上电脑之后怎么更新（不需要新逻辑）

1. `AppViewModel.load()` 先把缓存亮出来（导入数据，`fromCache=true`）；
2. 网络请求成功 → `ApiClient.loadWithCache` 的 `cache.put()` 覆盖精确键，变在线数据；
3. 点「立即同步」→ `runSync` 的 `snapshot.save()` 整份替换，导入数据被彻底顶掉，
   同时清掉 `peer_imported_at`，界面文案从「数据来自同伴」回到「离线数据」。

## 6. 显示口径

- `peer_imported_at` / `peer_source_shop`：设置页显示「当前数据来自同伴（店名），截至 X」。
- **本机自己同步成功一次后自动清除** —— 数据已经是自己拉的了，不该再标"同伴的"。
- 导入的包比本机旧时，提示里加一句「这份比这台手机原来的旧，原来截至 X」。

## 7. 边界与已知缺口

- **只在 APK 上有效**。浏览器端没有 `filesDir`，做不了。
- **明文**：数据包含客户欠款金额，会落在微信 / 文件管理器里。用户 2026-11-21 明确接受。
- **不加密、不签名**：谁拿到文件谁都能读，也能改（改完导入照样成功，只要 schema 对上）。
- **一台手机只能有一份快照**：导入是整份替换，不是合并。
- **验证状态（2026-11-21）**：双机模拟器全链路已验 —— 同一 AVD `-read-only` 多开两台，
  A 配对后同步 255 项并导出，文件搬到 B 的 `Download/`，B 全新安装后从首次配置页导入成功；
  停掉电脑端重启 B，B 独立可见 A 的数据，客户欠款列表与 A 逐行一致，设置页标注「来自同伴」，
  而同步过的 A 机没有这个标记。
  **仍缺**「微信这个通道」的真机确认（微信把文件存到哪、该目录能否被 SAF 选到），
  属微信自身行为，不是本仓库代码。见 `docs/当前遗留问题与效果待验收清单.md` ERP-MOBILE-05。
