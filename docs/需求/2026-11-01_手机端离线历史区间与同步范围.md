# 手机端离线历史区间与同步范围 · 决策记录

> 决策日期：2026-11-01<br>
> 状态：**已实现并发布**（桌面端 `v4.7.1` / APK `1.4.12`；GitHub Release `v4.7.1`，tag `v4.7.1` / 提交 `bd4fd0c`）<br>
> 关联：`2026-10-17_安卓只读端架构决策.md`（§1.3.2「轻量缓存」的后续）、`CHANGELOG.md` 的 v4.7.1 条目

## 1. 问题（用户 2026-11-01 报）

> 原话大意：「上次不是说好扩大缓存范围吗？怎么今天才 11 月 1 号，查 10 月就查不到，刚才查 10/31 也查不到。」

用户报的是**跨月后断网看不到上个月**。现场排查发现是两层叠在一起，必须分开看：

| 层 | 现象 | 是不是缺陷 |
|---|---|---|
| 网络 | 手机显示「连不上电脑」 | **不是**。当场电脑上的「简单ERP」根本没开（5000/5001 都没监听）；打开程序+同一 WiFi 后在线能查 10 月 |
| 缓存 | 断网翻不到 10 月 / 10/31 | **是**。见 §2 |

## 2. 根因（对着源码）

**v4.7.0 里说的「扩大缓存范围」，被实现成了「每页存多少条」，而不是「缓存哪些时间段」。**

- v4.7.0 只把 `SNAPSHOT_ORDER_DETAILS` 120→400、客户详情 40→1000、商品详情 60→300 —— **全是条数**，没有新增任何时间档。
- `/m/api/snapshot` 固定只缓存这么几档单据列表：**全部 / 今天（两种形态）/ 本周 / 本月 / 本年**（`app/erp/routes/mobile_api.py` 的 `snapshot()`）。
- 而手机「按月 / 按日自定义」发的是 `date_mode=custom&start_date=…&end_date=…`（`native/.../ui/screens/OrdersScreen.kt` 的 `TimeFilterSheet`），**快照里从来没有这种键**。

于是：

1. 「本月」这一档只在**当前月**有效。11 月 1 号零点一过，「本月」滚成 11 月，10 月那份唯一的月份缓存就失效；
2. 用户按「10 月 / 10/31 / 8–10 月」查的是 `custom` 区间，缓存里根本不存在对应键 → 断网必报「连不上电脑」。

> 这正是本项目反复踩的那类坑：**在线能看、离线查不到**（见 `memory/pitfalls.md`）。只是这次不是「键两端拼错」，而是「该有的键压根没生成」。

## 3. 决策（结论）

1. **同步范围可配置**：默认 **2 个月（本月 + 上月）**，设置页可选 **近 2 / 3 / 6 / 12 个月**。用户 2026-11-01 明确「默认两个月、自己可以选更长」。
2. **快照多缓存一份「备份单据列表」**：按 `?months=N` 计算同步区间 `[sync_from, sync_to]`，起点对齐**上个月 1 号**（让「上月」是完整自然月，10/31 不会滑出边界），并以较大上限取全（`SNAPSHOT_BACKUP_LIMIT = 5000`）。单据详情**优先从这份备份收集**，保证区间内（尤其上月）点开有明细。
3. **客户端本地兜底筛选**：断网且当前区间没有精确缓存时，拿备份列表在本地按「起止区间 + 类型 + 客户」过滤（纯函数 `OfflineOrderFilter`）。任意区间都能翻，不必为每个区间单独缓存。
4. **只对「显式起止区间」兜底**：周 / 月 / 年这些「具体是哪几天」交给服务端 `resolve_mobile_range` 算，客户端不复制日期换算规则，保持口径只有一份。

## 4. 为什么这样做（含被否方案）

- **被推翻的判断**：「扩大缓存范围 = 存更多条」（v4.7.0）。真正对用户有意义的「范围」是**时间覆盖**——能翻多久以前的数据。条数只决定单页深度，不解决「查不到这个月」。
- **被否：只预存最近 N 个月作为固定档**。改动虽小，但只覆盖固定的、由服务端算出的月份档；用户手机里「按月/按日自定义」走的是 `custom` 键，固定档对不上；而且任意单日、跨月区间仍然缺。
- **选「备份列表 + 本地过滤」**：一份覆盖整个同步区间的底座列表，就能覆盖区间内**任意**时间段的查询，不需要穷举每个可能区间。代价是「超出同步范围」仍看不到，用设置页把范围选大即可。

## 6. 边界与已知缺口

- **超出同步范围看不到**：只同步了最近 N 个月，更早的单需联网，或在设置页把范围选大再同步一次。
- **备份列表上限 5000 张**：超过则 `orders_truncated=true`，页面提示「更早请联网或缩小范围」。对普通消防器材门店，2 个月远少于 5000。
- **单据详情上限仍是 400（最近优先）**：区间内更早的单据离线只显示摘要，明细需联网（沿用既有降级策略）。
- **缓存未加密**：沿用架构文档 §8.3 的已知缺口，手机丢失已落盘内容无法远程抹除。
- **桌面端与 APK 必须一起升级**：`/m/api/snapshot` 由桌面端提供，只换 APK 拿不到备份列表。
