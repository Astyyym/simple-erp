## 一、结论先行

1. **启动慢不是打包问题，是导入问题。** 冻结后的空 Python 启动只需 0.12s，而现状从进程启动到窗口可见要 **3.05–3.99s**，其中 **约 3.4s 花在 `import erp`**（占整个启动 ~82%）。
2. **根因是一个结构性设计**：`app/erp/__init__.py` 导入时无条件 import 全部 9 个路由蓝图，而这些路由模块在**模块顶层**就 import 了 `weasyprint`（PDF）、`openpyxl`（Excel）、`pypinyin`（拼音）、`PIL`（图片）。于是「启动 Flask」必须先付完整个重依赖栈。
3. **两个可叠加的优化，实测把窗口可见时间从 ~3.4s 压到 ~1.7s（≈ −50%）**：
   - **惰性导入重依赖**：冻结版 `import erp` 从 3.707s → 0.906s
   - **Splash 先行**：让 WebView2 冷启动（~1.5s）与 Flask 启动并行，而非串行
4. **一条必须遵守的红线**：惰性导入不能写成函数内 `from x import y`——会打断测试的 `monkeypatch.setattr(pdf, "HTML", ...)` 注入点（实测 9–10 个测试失败）。正确写法分两张面孔：**`pdf.py` 等只被 `setattr` 的文件用「模块级 `HTML = None` + 首次使用解析」**；**`purchase_pdf.py` 因为测试会"读"`purchase_pdf.HTML` 当真实类用，必须改用 PEP 562 模块 `__getattr__`**（`None` 声明在这里单独跑会 `TypeError: 'NoneType' object is not callable`）。两种写法合并后全量 **789 passed**。

## 二、测量方法

**指标定义**

| 指标 | 定义 | 取法 |
|---|---|---|
| 端口就绪 | 进程启动 → `127.0.0.1:5000` 可连接 | `socket.connect_ex` 轮询 |
| 窗口可见 | 进程启动 → 该 PID 出现可见顶层窗口 | `EnumWindows` + `IsWindowVisible` + `GetWindowThreadProcessId` |
| 首页可用 | 进程启动 → `/` 返回 200 且含业务标记 | HTTP 轮询 |
| 阶段耗时 | 各阶段在进程内的相对时刻 | 插桩 shell + 插桩 spec 重建对照包 |

**隔离与安全**

- 每轮独立 `ERP_DATA_ROOT` + `ERP_LOCATION_FILE`，指向 scratch。
- 轮次之间强制等端口释放，避免端口冲突产生假值。
- 正式 `Documents/简单ERP数据/data/erp.db` 全程 mtime 未变（已核对）。
- 源码模式归因用 `-X importtime` 与**打桩实验**（把重包替换成轻量 stub，再测 `import erp`）。

### 4.5 UPX 是空转

`简单ERP.spec` 里 `upx=True`，但本机 PATH 上**没有 upx**；实测产物 `简单ERP.exe` / `libcrypto-3-x64.dll` / `libgtk-3-0.dll` / `python311.dll` 均**无 UPX 签名**。即使装上，UPX 也只减体积、**反而拖慢冷启动**（多一层解压），不该用来提速。

`dist/local-v3.3.0/简单ERP` = **116MB**，`_internal` = 104MB / **659 文件**：

| 项 | 大小 |

| `PIL` | 11MB |

## 五、优化方案

### 档位 1：惰性导入重依赖（收益最大，风险可控）

把 4.3 表中 6 处顶层重依赖改成首次使用时解析，**必须保留模块级 seam**：

```python
# erp/utils/pdf.py
HTML = None          # 模块级声明：保留 monkeypatch.setattr(pdf, "HTML", ...) 注入点

def _html_class():
    global HTML
    if HTML is None:
        from weasyprint import HTML as _HTML
        HTML = _HTML
    return HTML

# 调用点
_html_class()(string=html, base_url=str(runtime_root())).write_pdf(out)
```

**为什么不能写成函数内 `from weasyprint import HTML`**：实测该版本（lazyapp2/3）**9–10 个测试失败**，全部是
`AttributeError: module 'erp.utils.pdf' has no attribute 'HTML'`
——测试靠 monkeypatch 替换模块属性来捕获 HTML 并伪造 `%PDF`（`test_phase4_print_isolation.py:45`、`test_purchase_printing.py:300/343`）。保留模块级 `None` 声明后，**全量 789 passed**。

> ⚠️ **`purchase_pdf.py` 是例外，不能用 `None` 声明**：`tests/test_purchase_printing.py:295` / `:334` 会 **读取** `purchase_pdf.HTML` 当真实类用（`original_html = purchase_pdf.HTML`）。`None` 声明会让这次读取拿到 `None`，单独跑这 3 个测试即 `TypeError: 'NoneType' object is not callable`（实测 `3 failed`）；整文件一起跑之所以"看起来绿"，只是因为靠前的测试先渲染过一次、把属性解析出来了——**测试顺序假阳性**。该文件必须改用 **PEP 562 模块 `__getattr__`**：
>
> ```python
> def __getattr__(name):
>     if name in ("CSS", "HTML"):
>         from weasyprint import CSS as _CSS, HTML as _HTML
>         return {"CSS": _CSS, "HTML": _HTML}[name]
>     raise AttributeError(f"module {__name__!r} has no attribute {name!r}")
> ```
>
> 合并两种写法（`lazyapp5`）单独跑 3 passed、全量 789 passed、启动四库全不加载。

**实测收益（源码模式，`import erp` + `create_app`）**

| | `import erp` | 合计 |
|---|---|---|
| 现状 | 1.85–3.28s | 1.90–3.36s |
| 惰性版 | **0.42–0.60s** | **0.46–0.65s** |

**代价（必须知情）**——成本被推到首次调用：

| 首次操作 | 实测额外耗时 |
|---|---|
| 生成 PDF | **+1.63–1.80s** |
| 导出/导入 Excel | 付 `openpyxl`（~0.19s 量级） |
| 上传商品图片 | 付 `PIL` |
| 商品建档/导入 | 付 `pypinyin`（~0.24s 量级） |

对门店真实用法（开店启动一次、之后连续开单打印）这是**净赚**：启动省 1.5–2.8s，首次打印慢 1.7s。

**配套要求**：`简单ERP.spec` 的 `hiddenimports` 必须继续列出 `weasyprint / pydyf / pypinyin`（现已列出 ✓），否则 PyInstaller 静态分析看不到函数内导入会漏打包。

### 档位 2：Splash 先行，并行 WebView2 冷启动

现状**串行**：等服务监听 → 建窗口 → `webview.start()` → 再等 WebView2。
改为**并行**：立刻用内联 HTML splash 建窗口并 `webview.start()`；另起线程等服务就绪后 `window.load_url(APP_URL)`。

**实测 A/B（源码模式，隔离 splash 效果，两边都 eager import）**

| 变体 | 窗口可见 | 首页加载完成 |
|---|---|---|
| A 现状串行 | 4.47–6.37s | 5.54–9.73s |
| B splash 并行 | **1.41–2.38s** | **3.82–4.91s** |

**实测 A/B（源码模式，隔离惰性效果，两边都有 splash）**

| | 首页加载完成 |
|---|---|
| 现状导入 | 4.47–4.92s |
| 惰性导入 | **2.72–3.62s** |

**一个必须知道的边界**：splash 先行后，**窗口可见时间下限被 WebView2 冷启动锁死在 ~1.5s**——再优化 Python 也压不下去。这是本档天花板。

### 档位 3：冻结版 A/B 总效果（决定性证据）

在 scratch 重建对照包：**A = 正式 v3.3.0**；**B = 惰性导入 + splash 先行**（同名 spec、同 GTK DLL、同 UPX 设置，仅这两个改动）。

| 指标 | A 现状（n=5） | B 优化后（n=5） | 变化 |
|---|---|---|---|
| 端口就绪 | 1.97–2.54s | **0.85–1.14s** | **≈ −1.1s** |
| 窗口可见 | 3.05–3.99s | **1.54–1.77s** | **≈ −1.7s（−50%）** |

**冻结版插桩对照**

| 阶段 | 现状 | 懒加载 |
|---|---|---|
| `import erp` | 3.707s | **0.906s** |
| 端口监听 | 4.160s | **1.072s** |
| 窗口创建 | 4.232s | **0.501s** |

**功能验证（B 包）**：`/health` `version=v3.3.0`、`auth=disabled`、data_root 指向隔离根；`/` 200、56,629 bytes、含品牌、无登录 UI；`index_ms` 14ms；窗口标题切换 1.541s。

### 档位 4（备选，未实测）：PyInstaller 原生 `--splash`

官方 `--splash`（实验性，Tcl/Tk 实现，约 1.5MB）在**解压/导入之前**就显示图片，可用 `pyi_splash.update_text()` 更新文案、`pyi_splash.close()` 关闭。对 onefile 收益明显；本项目是 onefolder（无解压阶段），收益有限，但**能比 Python 代码更早显示东西**。

### 档位 5（备选，未实测）：减小体积

- 排除 `pyphen`（6.1MB 词典，只为 CSS 连字符）——需先确认打印模板未用 `hyphens: auto`
- GTK DLL 按需裁剪（70MB → 或可砍半）
- `pdfjs` 5.4MB 按需懒加载
- **这些不直接提速**，但能降低杀软首扫与冷缓存代价，对「首次启动慢」有帮助

## 七、被证伪 / 作废的尝试（留痕）

| 尝试 | 结果 | 判定 |
|---|---|---|
| lazyapp2：函数内 `from weasyprint import HTML` | **9 failed** / 766 passed / 14 skipped | **证伪**：打断 monkeypatch 注入点 |
| lazyapp3：同上（另加 PIL/importing 处理） | **10 failed** / 765 passed / 14 skipped | **证伪**：同源 |
| lazyapp4：模块级 `None` + 首次解析（**全文件整体跑**） | 789 passed | **假阳性**：`purchase_pdf.py` 单独跑 3 failed（测试顺序运气），见下 |
| **lazyapp5：`pdf.py` 型用 `None` + `purchase_pdf.py` 型用 `__getattr__`** | **789 passed + 单独跑 3 passed** | **成立**（唯一经"整跑 + 隔离单跑"双重验证的写法） |
| 调 `private_mode` | private 2.71/2.36 vs normal 2.41/2.35 | **作废**：无可用差异 |
| 靠 UPX 提速 | 本机无 upx，产物无 UPX 签名 | **作废**：空转，且方向相反 |

**`lazyapp4` 假阳性的取证**（2026-10-09 复验）：拿 lazyapp4 单独跑
`test_purchase_printing.py::test_purchase_calibration_and_ui_zoom_do_not_change_pdf_geometry[False/True]`
与 `::test_purchase_real_pdf_keeps_twelve_mm_margins_on_every_fragment` → **3 failed**，
报错 `TypeError: 'NoneType' object is not callable`（`original_html = purchase_pdf.HTML` 得到 `None`）；
而同一文件整体跑却 `34 passed`。差别纯在**测试顺序**。因此 `purchase_pdf.py` 改用 `__getattr__`（lazyapp5），单独跑 **3 passed**。已落进真实源码。

lazyapp2 与 lazyapp3 的失败集合几乎一致，差异仅 1 项（lazyapp3 多挂 `test_account_ledger_period_balance.py::test_pdf_contains_two_end_balances_and_dynamic_title`），同源跑批波动。
