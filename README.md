# 简单ERP

面向本地单机门店的轻量进销存/开单系统，当前覆盖销售与退货开单、客户和商品资料、账款、采购统计、打印及本地数据管理。

- 当前源码版本：以根目录 [`VERSION`](./VERSION) 为准；`v3.6.0` 在 v3.5.0 之上新增 **Windows 安装包形态**：用户拿到单个 `simple-erp-setup-v3.6.0.exe` 双击安装，开始菜单/桌面有图标、可在「设置 → 应用」卸载；**per-user 安装**（`%LOCALAPPDATA%\Programs\简单ERP`，全程不需要管理员），升级不覆盖店铺 `config.json`、卸载不删业务数据。绿色包（one-folder + ZIP）继续保留。v3.5.0 交付的「筛选无刷新、侧栏导航归属、动作标签统一与数据分析图型收口」见下条历史。
- GitHub 仓库：`Astyyym/simple-erp`；[Releases 页面](https://github.com/Astyyym/simple-erp/releases)。README 不代表远端最新 Release/安装包已经核实。
- 当前权威需求和实现边界：[`docs/需求/消防器材店ERP系统-需求文档.md`](./docs/需求/消防器材店ERP系统-需求文档.md)。全部文档入口见 [`docs/README.md`](./docs/README.md)。

## 当前功能

### 开单与单据管理

- 销售单、退货单共用录入流程；商品可按客户价或常规价取价；新建默认保留一行明细，清空后恢复一行。
- 关闭浏览器对开单字段的历史自动填充，同时保留系统自身的客户/商品联想。
- 单号格式：`MD` + 八位日期 + 四位流水；销售单和退货单共用当天流水。新建日期可改，改单保留原日期和单号。
- 按客户、日期和单据类型筛选；日期支持按年、跨年按月区间及日期范围。
- 客户采购统计提供按日销售统计、日期热力图和商品排行；退货不计入采购统计。
- 货款汇总表支持 PDF 预览；销售单、退货单明细可导出 Excel。

### 客户、商品和账款

- 客户、商品基础资料维护、模糊查询、Excel 导出。
- 客户和商品支持 `.xlsx` / `.csv` 模板下载及批量导入；同名记录按当前导入规则跳过。
- 账款按客户汇总，涵盖期初余额、有效单据、收款和账务调整；流水区分全历史当前余额与筛选区间净变动，并可导出同口径 A4 竖版流水 PDF。
- 收款和调整支持带原因作废并保留审计记录；作废流水可追溯但不计入余额。
- 退货单在单据列表中与销售单区分显示；统计范围按各模块的当前业务口径计算。

### 库存、双向往来与数据分析

- 按商品名称＋型号管理库存、期初、安全库存和移动成本；显示启用状态与当前库存状况，未知成本不冒充零成本。
- 拿货/退拿货使用统一往来对象，销售与客户退货保存历史成本快照；退拿货关联原单原行并控制部分退额度，库存成本按精确微元守恒。
- 四类交易对账支持完整跨页选择和A4白名单打印；交易核对不自动登记收款、付款或结算，不替代客户欠款余额。
- 正式分析提供热力图、完整产品排行和成本诊断三页签，跨年展示、分页/排序/筛选保持，数量按同单位比较。

### 工作台与高频流程

- 工作台展示今日有效销售/退货净额与笔数，并列出最近 5 笔有效单据。
- 单据管理支持每页 50 条服务端分页、总数/范围提示和筛选条件保留。
- 客户/商品联想可用键盘选择，建议内容按文本安全显示；订单状态使用中文业务文案；退货重编辑保留负数金额，订单明细金额在建立新客户前校验。

### 设置、打印与桌面版

- 设置公司名称、主题（浅色/深色/跟随系统）、界面缩放、字体粗细（标准/稍粗/加粗）、打印文案、打印位置校准和数据根目录。
- 销售单、退货单、客户货款汇总 PDF 和设置页样张默认使用 A4 竖版（210×297mm）；销售/退货内容正向适配竖版，旧 241×140mm 单据版心不再沿用。
- 打印驱动建议选择 A4 纵向、实际大小/100%，关闭“适合页面/缩放”。横纵偏移与缩放作用于销售/客户退货、拿货/退拿货单及设置样张，不作用于账款汇总和往来交易对账。
- 目标打印机尚未实打验收；PDF 页框为 A4 竖版不等于纸面位置已确认。历史 `NantianPR-LQ` 驱动选项仍须在目标设备核对。
- 新建销售/退货单保存成功后，右侧同页显示当前单据的真实 PDF；可关闭、重新打开、缩放屏幕显示、保存 PDF 和打印。屏幕缩放不改变 A4 PDF 排版；保存失败不会打开预览。
- Windows 桌面版为 PyInstaller one-folder 程序；业务数据目录与程序文件分开，升级时不要覆盖用户数据。
- 提供两种分发形态：**安装包**（`simple-erp-setup-vX.Y.Z.exe`，per-user 安装到 `%LOCALAPPDATA%\Programs\简单ERP`，带开始菜单/桌面图标与卸载入口，升级不覆盖 `config.json`、卸载不删数据）和**绿色包**（解压即用）。

## 重要安全边界

当前版本**永久免登录**。程序面向本机单机使用，默认仅监听 `127.0.0.1`；任何能访问服务端口的人都可操作业务数据。带有 `Origin` 或 `Sec-Fetch-Site` 的浏览器写请求执行同源检查，但这不是身份认证。不要把服务绑定到 `0.0.0.0`、开放到局域网或公网。`/health` 为公开健康检查端点，返回 `auth: disabled`。

## Windows 开发与测试

在项目根目录运行：

```bat
setup.bat
```

该脚本准备源码虚拟环境 `.venv`。源码开发启动入口：

```bat
启动系统.bat
```

运行完整测试：

```bat
.venv\Scripts\python.exe -m pytest tests\ -q
```

- 打包环境 `.venv-win` 与源码环境分开；`v3.6.0` 安装包与 one-folder 构建证据见 [`v3.6.0 安装包交付计划`](./开发短计划/2026-10-10_v3.6.0安装包交付_执行计划.md)，`v3.5.0` 及更早的构建/发布证据见 [`v3.5.0 成品打包计划`](./开发短计划/2026-10-10_v3.5.0成品打包_执行计划.md)。旧 v2.0.0 / V1.1.0 验收保留为历史记录，目标打印机未实打。

## 可选 WSL 交叉测试

可选 WSL 交叉测试应在同一仓库的 `/mnt/d/` 映射目录内进行，并确认该仓库的 `.venv` 已准备。源码预览端口使用 `5001`，服务数据根必须设为临时目录，避免碰到项目根目录的正式/开发库；具体启动方法见 [`docs/开发说明.md`](./docs/开发说明.md)。Windows 仍是桌面流程和打包环境。

## Windows 桌面版打包

一条命令出齐三种交付产物：

```bat
打包Windows安装包.bat
```

| 形态 | 产物 | 用途 |
|---|---|---|
| 绿色版目录 | `dist\local-v3.6.0\简单ERP\` | 本机/U 盘直接跑（双击 `简单ERP.exe`，**不需要安装**） |
| **安装包** | `dist\simple-erp-setup-v3.6.0.exe` | 门店用户双击安装，带开始菜单/桌面快捷方式与卸载项；per-user，不需要管理员 |
| 交付 ZIP | `dist\simple-erp-windows-v3.6.0.zip` | 发给别人，解压即用 |

三者是同一份程序，只差投递方式。安装包装到 `%LOCALAPPDATA%\Programs\简单ERP`（向导里可改路径），业务数据在「文档\简单ERP数据」，安装/升级/卸载都不动它。

**认名字**：安装包带 `setup` 字样；`简单ERP.exe` 是绿色版主程序，双击直接开、不走向导——这是设计如此。

源码及健康/UI/Windows产品版本均为 `v3.6.0`，Windows数字文件版本为 `3.6.0.0`。包内含通用配置，不含业务或演示数据库。

旧版打包脚本 `打包Windows桌面版.bat` 只出绿色版目录（不发版用）；发版请用上面的脚本。

常规脚本的常见产物：

```text
dist\简单ERP\简单ERP.exe
dist\simple-erp-setup-vX.Y.Z.exe
dist\简单ERP-Windows桌面版-vX.Y.Z.zip
dist\simple-erp-windows-vX.Y.Z.zip
```

详细步骤、数据目录和升级边界见 [`docs/Windows桌面版打包说明.md`](./docs/Windows桌面版打包说明.md)。本地 `dist/` 文件存在或源码测试通过，都不能单独证明 GitHub Release 已上传或桌面 EXE 已通过实机验收。

## 升级时的数据保护

1. 退出程序并备份当前设置页显示的整个数据目录，保留原程序配置 `config.json`。
2. 更新程序文件；不要用安装包中的空库覆盖正在使用的 `data\erp.db`。
3. 若旧安装仍把数据放在程序旁的 `data\`，尤其不要整目录覆盖。
4. 启动后检查版本和历史单据是否仍在。
5. `v3.6.0` 首次连接旧库会执行内置结构升级；不要升级后直接用旧程序打开新库。旧历史成本/库存不自动补造，正式期初启用需独立确认。本地打包验收不等于已经迁移正式数据。

用安装包升级时不需要先卸载：直接运行新版本安装包即可，它会覆盖程序文件、保留 `config.json` 和业务数据。卸载程序同样不会删除数据目录。
