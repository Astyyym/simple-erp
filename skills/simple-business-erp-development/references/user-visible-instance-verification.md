# ERP开发中的“已完成”与用户可见实例验证

## 适用场景

在WSL中修改Flask ERP，而用户通过Windows浏览器、桌面EXE或其他入口预览时，用于避免“代码已写入，但用户页面仍是旧版”的错误交付判断。

## 核心原则

**工作区出现代码 ≠ 功能已完成 ≠ 用户正在看的实例已加载。**

只有同时满足以下条件，才能告诉用户“已经添加完成，可以查看”：

1. 实现任务已经结束，不再有子代理继续写同一工作区；
2. 新功能专项测试通过；
3. 原有全量测试通过，且测试数据库与真实业务数据库隔离；
4. 服务在代码写入后重新启动，或已确认开发重载生效；
5. 从用户实际使用的入口打开页面，确认控件和行为真实可见；
6. 若用户提供截图，以截图为最高优先级证据，不用自己访问到的另一个实例反驳截图。

## 正确验证顺序

1. **确认实现状态**
   - 检查是否还有后台子代理、测试或写代码任务未结束；
   - 检查工作区是否仍处于半成品状态；
   - 未完成时只说“正在开发”，不要引导用户预览。

2. **完成测试**
   - 先跑新增功能专项测试；
   - 再运行全量测试。当前 `tests/conftest.py` 的 autouse fixture 会将数据库和运行文件路由到 pytest 临时目录；确认隔离生效，不要移动、覆盖或恢复正式 `data/erp.db*`。

3. **确认服务实例**
   - 检查监听端口、PID、进程启动时间和工作目录；
   - Flask非Debug模式下，Python路由修改后必须重启；
   - 模板可能即时变化、Python路由却仍为旧代码，不能仅凭看到一个新按钮判断整体已加载。

4. **按用户入口验证**
   - WSL Web：验证用户浏览器实际访问的地址；
   - Windows EXE：必须验证EXE实例，不能拿WSL源码服务代替；
   - 若Windows localhost可能通过WSL relay转发，也要确认没有另一个旧服务或旧窗口混淆。

5. **使用可复现样例**
   - 给出一个真实存在的客户、日期和完整URL；
   - 同时说明功能的显示前提，例如“统计区仅在完整匹配一个现有客户后出现”；
   - 在报告前亲自打开该URL并确认页面内容。

## 截图冲突处理

当用户截图与工具访问结果不一致时：

1. 先直接承认截图里确实没有目标控件；
2. 不说“你可能没刷新”“你可能停留在首页”，除非已有证据；
3. 将问题定义为“实例/入口不一致”，继续查PID、工作目录、服务启动时间与页面版本；
4. 在原因未查清前，不反复要求用户重启、强刷或寻找按钮；
5. 不把半成品称为正式交付。

## 并行子代理注意事项

- 多个子代理若被明确指向同一个绝对项目路径，实际上可能同时写共享工作区；不要假设一定文件隔离。
- 只有修改文件集合真正互不重叠时才能并行。
- 子代理运行期间，不要自行跑“全量测试”并把另一代理刚写下的RED测试当作当前产品故障；应分别记录RED证据，等实现任务结束后再统一集成。
- 用户中途追加需求时，应更新任务说明；若无法向正在运行的代理追加上下文，则在其完成后补一个独立TDD任务。

## 禁止事项

- 禁止在后台实现仍运行时说“功能已经加载出来”。
- 禁止以自己访问到的新页面否定用户截图中的旧页面。
- 禁止把找不到控件归因于用户不会找，除非已验证同一实例、同一路由、同一版本。
- 禁止让用户承担半成品的验证成本。
