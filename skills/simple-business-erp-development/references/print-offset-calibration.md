## 当前规则

- A4 竖版页面为 **210×297mm**；销售/退货页左右各留 12mm，版心宽 186mm，正向阅读。客户货款汇总 PDF 和设置页样张也使用 A4 竖版。
- `order_pdf_page_width_mm` / `order_pdf_page_height_mm` 与 `printer_paper_width_mm` / `printer_paper_height_mm` 的默认值均为 210 / 297。
- 驱动选择 A4 纵向、实际大小/100%，关闭“适合页面/缩放”。目标设备当前具体选项和纸面位置仍须实机验证。
- X/Y 偏移与缩放作用于单张销售/客户退货、拿货/退拿货 PDF 和设置页样张；不作用于账款汇总或往来交易对账 PDF。偏移默认 0、缩放默认 1.0；单张采购复用单据校准，交易对账固定A4且独立于销售偏移/缩放。
- 旧连续纸尺寸与 `.sheet` 版心只在历史 reference 中保留，不得通过 offset 或自定义纸型恢复旧布局。

## 三层不要混

### 账款流水商品明细

- 先确认打印路径：账款流水 `/accounts/ledger_pdf` 与数据分析交易对账PDF不是同一报表。摘要展开不改变余额计算或另一报表口径。
- 打印按原单商品快照白名单读取名称/型号/数量/单位/单价/明细金额，不读内部成本/毛利。按单位格式化数量、金额两位；整单合计用原单金额，只计一次，不重新从显示舍入值累计。
- 一单多行合并单据元数据时，每单用独立tbody和分页keep-together，表头跨页重复；收款/调整使用资金行，不能因跨表整数ID相同误带商品。作废留原金额与原因，但不计有效余额。
- **整单一块，不要按固定行数切块**：按行数（如 12 行）硬切会让「一页放得下」的单据也被切出假分段（实测 32 行单据被切成 3 段，用户明确要求改掉）。正确做法是整单一个 `tbody`，**让排版引擎自然跨页**；代价是续页不重复单头，所以要把**单据金额写在每一行**（而非只写首行），续页明细仍能看出属于哪张单。
- **单据金额要按业务方向取号**：库中 `orders.total_amount_cents` 退货为负、销售为正，但 `purchase_orders.total_amount_cents` **恒为正**；直接打印会得到「拿货显示成 +」的错误符号。必须另算 `doc_amount_cents`：销售 +、退货 −、**拿货 −**、退拿货 +（只有拿货需要翻转）。账务口径 `balance_delta_cents` 才是权威方向。
- **不要用 `rowspan` 合并单头**：WeasyPrint 在「`rowspan` + 分块 `tbody`」下直接抛 `AttributeError: 'TableCellBox' object has no attribute 'border_top_left_radius'`。
- **单元格底色的坑在 `<col>`，不在 `td`**：实测对照（90 行跨页表格）——`td { background }` **可用**、`.amt span { background }` **可用**、**`col.amtcol { background }` 崩溃**（同一个 `layout_backgrounds` / `border_top_left_radius` 报错）。所以写列底色时必须把选择器限定到 `td.class` / `th.class`；写成 `.class{background}` 会同时命中 `<colgroup>` 里的 `<col class>` 而崩。
- 实际生成PDF后检查A4页框、逐页表头、文字/数值边界与多商品版式；原生保存和目标打印机实打单独验收。账款流水不接销售偏移设置，也不拿源码HTML截图冒充PDF版式。

| 层 | 是什么 | 不能当什么 |
|----|--------|------------|
| 设置预览 | Chromium HTML `/settings/print-preview` | 不能当针式实打证据；大屏像空白 |
| 订单 PDF | WeasyPrint → `/orders/<id>/pdf` | 仍可能被驱动缩放 |
| 物理打印 | 驱动边距 / 适合页面 / 连续纸 | 最终验收 |

页脚左右不齐 → `footer-grid`（主 skill Printing）。<br>
**整页偏** → 先纸张 mm + 绝对对称版心 + 驱动；**最后**才 offset。

## 配置键（机差 1–3mm）

```css
transform: translate(Xmm, Ymm) scale(S);
transform-origin: top left;
```

| 键 | 含义 |
|----|------|
| `print_offset_x_mm` | 正=右，负=左 |
| `print_offset_y_mm` | 正=下，负=上 |
| `print_scale` | 默认 1.0；约 0.80～1.20 |

设置页可暴露三字段。`/settings/save` 仅在表单提交了这些字段时写回，避免旧 POST 把 live 偏移清 0。<br>
**默认保持 0。** 禁止用 x=+8/y=-10 一类大偏移掩盖页高错误（2026-07-14 试过，用户要求恢复 0）。

## 打印机对话框

- 纸张选择 **A4 纵向**，缩放选 **实际大小/100%**。
- **关**「适合页面 / fit-to-page / 缩小过大页面」。
- 修改后重新打开新 PDF；目标设备的页边距、驱动与进纸方向须分别实测。
- 汇总 PDF 页面方向与设置样张一致，但不使用销售/退货的 X/Y 偏移设置。

## 当前免登录边界

当前产品永久免登录，不维护或修改默认账号/密码。`local_access_*` 是历史兼容字段；若未来安全边界改变，必须先确认新需求与风险，再更新产品基线和测试。


## 测试

- 检查销售、客户退货、拿货、退拿货、交易对账、账款汇总及设置样张的实际 PDF **每一页**为 A4 竖版（210×297mm），同时核查分页表头与文字/数值边界；首个MediaBox不能代表所有页面。
- 解压PDF对象流时保留完整压缩字节，不能用 `rstrip(b'\r\n')` 去掉所谓行尾：合法zlib校验尾字节也可能为CR/LF，会把正常PDF误报为没有页框。优先使用已核实可用的PDF解析库逐页取尺寸/文字；测试helper不代替实际PDF视觉与实打验证。
- 检查 `/settings/print-preview` 的竖版版心、样张 PDF 页框和非零 offset 的 CSS 行为。
- 使用隔离临时数据库；自动化测试不等于目标打印机实打通过。
- **PDF 页框与可见墨迹边界的验证优先于 offset 调整**。

## 勿做

- 只调 HTML 预览就宣称打印修好
- 页尺寸未定时用大 offset 当主修复
- 左 20 / 右 10 却自称居中（左右须等宽）
- 写了 `padding: 6mm 20mm` 却不量 PDF 墨迹就宣称居中（表格仍可能右溢裁切）
- 用户贴图问「这居中吗？」时辩解；先认错 → 量 L/R → 改绝对 `.sheet`
- 用大 offset「把偏右拉回来」代替对称版心
- `.maker-sign { translateX }` 修整页
- 未确认 5001 vs 5000 EXE 就下结论
- 只丢 preview URL 不给 Windows PDF 路径（用户：「链接我看不出来」）
- 把页脚 `absolute; bottom:0` 贴页底当“专业排版”（用户要页脚紧贴表格）
