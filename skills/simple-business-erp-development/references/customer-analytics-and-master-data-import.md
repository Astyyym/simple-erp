# 客户采购统计与基础资料导入

## 客户采购统计

在“单据查询”页复用筛选与列表，不新建重复的订单明细页面。点「筛选」后应自动出统计（满足下方作用域时），不要依赖手填完整客户名的特殊链接。

### 出图作用域（2026-07-12 用户确认）

| scope | 条件 | 行为 |
|-------|------|------|
| `customer` | 精确命中 1 名，或模糊命中 **唯一** 1 名未删除客户 | 出该客户采购统计；标题用完整客户名 |
| `none` | 模糊命中 **多个** 客户 | **只列表 + 旁侧中文提示**，**不出图** |
| `none` | 输入了客户但 0 命中 | 不出客户画像；可提示未匹配 |
| `all` | 客户框为空，仅靠日期/类型等 | **全店拿货统计**：热力=全店有效销售总金额（按天）；排行=全店商品数量前5/前10 |

- 输入过程中用 datalist/`/orders/api/customers` 自动建议库内完整客户名。
- 列表查询仍可用 `LIKE` 模糊；统计区判定与列表模糊分开。
- JSON 载荷须含 `scope`、`customer`、`date_mode`、`start_date`、`end_date`、`days`、`ranking`、`order_type`。

### 时间模式（三选一）

`date_mode`: `year` | `month` | `range`（默认 `range` 兼容旧链接）。

- **按年**：自然年 `YYYY-01-01`～`YYYY-12-31`。
- **按月**：该月首尾；年+月控件。
- **按日到日**：起止 date；非法回退到 bounds 或当天；起>止归一；超大跨度约 366 天上限（自然年整年允许）。
- 切换模式只显示对应控件；列表与热力共用解析后的有效起止。

### 口径、交互与布局

- 热力/排行 SQL：`order_type='sale'`、`status IN ('saved','printed')`、`deleted_at IS NULL`。退货/草稿/作废/删除不进拿货。
- 颜色只由当天金额决定；档位按当前统计范围动态分级。排行按累计**数量**降序（全店同）；金额并列展示。
- 悬停：日期、总额、次数、货物前几种 + `另有X种`。单击/拖选复用 `/orders/`；跳转可落到 `date_mode=range` 并保留 `order_type` 与客户。
- 离线 Canvas 柱+折线；无 Chart.js/ECharts CDN。`quantity` 文本安全转数值。
- **只画当前筛选时段**；**不要** GitHub 密铺年视图。按自然月分块（`month-calendar`）并留间隙；宽屏约 6 月/行，窄屏仅左侧热力自适应 4/3/2 列；右侧排行栏不折行打碎。
- **宽屏条形图右侧大空白（2026-07-12）**：右列 `fr` 过大 + canvas 未 `width:100%`（默认约 300px）。修：右列限宽、canvas 跟容器 `clientWidth` 重绘、`resize`/二次 rAF；少商品时限制 step。用户截图指空白=显示器适配未做，以截图为准改布局。
- 单据查询订单类型可组合：`全部` / `只看销售单` / `只看退货单`；切换时保留客户与日期模式参数。

## 商品和客户批量导入

- 商品管理和客户管理分别提供上传入口及 Excel 模板下载。
- 支持 `.xlsx` 与 `.csv`；CSV优先兼容 UTF-8 BOM，并可回退常见中文编码。
- 模板列（2026-10-15 现状）：商品 = `商品名称 / 品牌 / 单位 / 期初数量 / 期初成本（元） / 备注`；客户 = `客户名称 / 电话 / 地址 / 期初余额（元） / 备注`。旧表头（商品 2 列 `商品名称,价格`、5/6 列无品牌、**含「默认价」列的旧模板**；客户 1 列 `客户名称`）仍可导入，单位回落「个」——**默认价下线后该列只是不再被读取**（档案已无售价字段），其余列照常落库。表头按**整行精确匹配**，所以**模板第一行必须是纯表头**：加一行说明会被当成数据行或直接报「表头错误」——说明只能放进第二个 sheet「填写说明」（`excel_template(headers, filename, notes)`）。**新增模板表头时必须同步加进 `PRODUCT_HEADERS` 白名单**，否则下载的模板自己导不回来（2026-10-15 实测踩过：无「默认价」列的新表头一开始不在白名单里，整表报 400 表头错误）。
- **字段不完整照样导入，但要提醒「待补全」**（2026-10-14 用户要求；2026-10-15 起口径收窄到品牌）：商品**缺品牌**，客户缺电话与地址，都不再拦行。提醒必须**三处齐**：① 预检页黄色提醒条给出条数 + 每行「说明」列写明缺什么；② 导入结果摘要报同一条数；③ 列表带「待补全」徽标且能被「待补全」筛选命中（chip 计数与列表条数一致）。补齐字段后三处同时消失。
- **「待补全」口径唯一真源 = `services/master_data_quality.py`**：来源 `order`（开单攒出）或 `import`（批量导入），`manual`（手工建档）**不算**（缺什么是用户自己的选择）；**商品缺品牌**（2026-10-15 默认价下线后只剩这一项），客户电话与地址**都**为空。SQL 侧必须用导出的 `COMPLETION_ORIGINS_SQL` 拼条件，不要另写一套（历史上列表筛选/徽标/编辑页提示各写一遍导致过漂移）。新增字段判定时用 `*_missing_fields()` 拿人话，`*_needs_completion()` / `*_completion_hint()` 都是它的派生。
- 更新行（同名「更新」策略）**不报**待补全条数：预检阶段拿不到目标档案的来源（可能是手工建档，那就不该标），只对新增行下结论——宁可少报，不误报。
- 从旧系统导出的脏客户/商品表：先总览再分档清洗，不覆盖原件；流程与消防门店脏数据模式见 `references/master-data-cleaning-before-import.md`。
- 金额进入数据库前转换为整数分；拒绝负数与非数字。**商品档案已无售价字段**（2026-10-15 默认价下线），导入文件里带「默认价/价格」列时该列不再解析也不再校验。
- 数据库现有同名、软删除同名、文件内部重复名称全部跳过：不覆盖价格、不恢复旧记录、不创建重复客户。
- 导入前/导入时校验表头、文件类型、空文件、空名称和价格格式。常见业务错误必须返回中文提示，不能成为500页。
- 结果至少展示：新增数、跳过数、错误数；错误项带源文件行号和原因。不要把无界错误列表塞进重定向查询字符串；优先直接渲染结果、使用短期session/flash，或限制展示条数并提供下载。成功路径用 POST 后直接渲染后，删除 GET query 解析导入结果的休眠代码。
- 导入校验失败（错误后缀/表头/空文件/超大）返回中文错误时，页面仍应带上当前商品/客户列表和导入控件，不能渲染成空列表让人以为资料被清空。
- 上传文件可在内存解析，不保留包含业务资料的临时副本；设置合理文件大小限制。
- 半成品续作：先对照表（保留/修补/重写）再改代码；`orders` 列表相关文件串行；可用项目内 `开发短计划/` 跟踪阶段。Windows 探针优先认 ASCII 稳定标记与 Server 头，开发预览默认 5001。
- **写导入相关断言时的坑**：预检页的 `preview_json` 隐藏域里含着整份行数据，`html.split("<tr>")` 会先命中那段 JSON —— 要限定在 `<div class="table-responsive">` 之后取行；另外名称单元格可能带「待补全」徽标，按单元格原文当行键会取不到（测试解析器要先把徽标去掉）。

## 测试与审核

1. 严格TDD：先写路由/聚合/导入失败测试并确认RED，再实现GREEN。
2. 统计测试覆盖：销售与退货、日期边界、空数据、文本数量、重复商品汇总、精确客户、**唯一模糊/多客户提示/空客户全店**、`date_mode=year|month|range` 起止、月历容器标记，以及单击/拖选交互。
3. 测试读取模板内嵌 JSON 时，应定位专用 `<script type="application/json">` 节点并解析真实载荷；不要只断言中文标题存在。图表离线性应针对 Chart.js/ECharts 等图表依赖断言，不要笼统禁止页面全部 CDN，因为基础 CSS 可能已有独立加载策略。
4. 导入测试覆盖xlsx、CSV、BOM、重复名称、软删除同名、错误表头、非法价格和空文件。
5. 最后依次做需求符合性审核、代码质量审核、全量测试和真实页面交互检查。
6. 当前 `tests/conftest.py` 的 autouse fixture 会把数据库路径切到每个测试的临时 SQLite 文件；运行前可确认该 fixture 已生效，不要为测试手工移动或恢复正式库。若发现有历史运行绕过了 fixture，再停止测试并按数据恢复流程处理，不得先扫描/改写正式库。
7. 日期跨度上限要覆盖极端边界（如 `0001-01-01` 到 `9999-12-31`），并避免在最大日期上执行 `+ timedelta(days=1)` 引发溢出；达到结束日时先退出循环。
