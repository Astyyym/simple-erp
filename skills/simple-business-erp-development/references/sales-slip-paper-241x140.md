|----|-----|------|

| 实体纸一联高 | **140mm** | 撕开后打一单 |

（`printer_paper_*` 是汇总类 A4 用的，**不要**拿来表达连续纸）。

## 包装 vs 尺子

用户曾：盒标 241×288、手量约 14×24cm（=140×240）、后确认二联连在一起≈280。

| 说法 | 含义 |
|------|------|
| 手量 24×14 cm | 一联宽×高 → **PDF 页** |
| 两联未撕 ≈280 | 140×2；旧代码错把这当单页 |
| 盒标 288/280 | 标称/连张，**不当** `@page` 高 |

**原则：以撕开一联尺子为准。** 问用户时要：宽（含孔）、高（撕口到撕口）、左孔到正文、是否二联/三联叠打。

## 为何预览对、实打偏

1. PDF/`@page` 若按 **280** 画，物理纸只有 **140** → 驱动缩放/裁切 → 靠下靠左。
2. 流式 padding + 忽略孔边 → 版心漂。
3. **不是**优先 offset 问题。用户明确：恢复 offset 0，按版面重做。

## 居中失败（用户连纠两次）

| 错误 | 正确 |
|------|------|
| 左 20 / 右 10 | 左右必须对称 20 |
| 仅 `padding: 6mm 20mm` 就说居中 | WeasyPrint 下表格仍可能挤出右缘；用户会贴图问「这居中吗？」 |
| 标题 `text-align:center` + `letter-spacing` | 字距会视觉右偏；公司名 `letter-spacing:0` |
| 名称规格 `<col>` 无宽度吞整行 | 列宽合计 **= 201mm**（约 12/78/18/24/32/37） |
| 只丢 `/settings/print-preview` URL | 大屏白底矮条像空白；给 **Windows PDF 路径** |

用户原话：量了左边孔距后，右边也应等宽；「这居中吗？」时先认错再量，勿辩。

### 当前落地（认居中前必过）

页框放在 **`@page` 外边距** 上，而不是 `.page` 的 padding —— 这是长单自动进下一联时
**每一联都有同样左右版心** 的关键（padding 只作用于首/末片段）。

```css
@page { size: 215.9mm 139.7mm; margin: 6mm 7.3mm; }
.page { width: 100%; padding: 0; transform: translate(offsetXmm, offsetYmm) scale(S); }
.sheet { width: 100%; }          /* 不再 max-width:186mm，不居中留白 */
table.items { width: 100%; table-layout: fixed; }
/* 列宽用 mm 定死，合计正好 201.3mm，不溢出右缘 */
col: 13 / 76.3 / 16 / 24 / 34 / 38 mm
```

页脚 `footer-sign` 固定 **38mm**；offset 默认 0。

### 字号不得再退回（2026-10-11 修复）

| 元素 | 值 | 实测字框高 |
|---|---|---|
| h1 公司名 | 24px | 8.381mm |
| .subtitle 单据名 | 16px | 5.587mm |
| .total-row 合计 | 15px | 5.238mm |
| table.items 表头+正文 | 14px | 4.889mm |
| .bottom / footer-grid / footer-sign | 13px | 4.540mm |
| .legal-note 备注 | 12px | 4.190mm |
| 单元格内边距 | 0.9mm 1.2mm | 文字不贴框线；为单联 10 行而压（原 1.6mm） |

原先是 11px（正文 3.84mm）/9.5px（备注 3.32mm），实拍对比旧软件小约 1/4、看不清。
**可读性优先于行数**：长单由用户拆单打印，自动跨页只是兜底。
版心有富余，必要时正文可再上调至 15px。

### 单联容量与跨联（2026-10-11 更新：8 → 10 行）

- **单联可容 10 行**（第 11 行起自动进下一联）。实测：1/9/10 行 → 1 联；11/20 → 2 联；21 → 3 联；31 → 4 联。
- 容量靠**压单元格内边距 `1.6mm → 0.9mm`** 换来，**字号层级一律不动**（可读性优先结论继续有效）。
  行高实测 7.91mm → **6.51mm**，10 行仍留余量（约 6.0mm）。
- 明细按 `items | batch(10)` 分块，**每块自成一张 `<table class="items">`**（各带 `colgroup`/`thead`/`tbody`），
  块后接合计行；非末块追加 `.slip-notice` 提示行并跟一个 `.slip-break`（`break-after: page`）强制换联。
- **合计口径（用户选「每页都合计」）**：非末块印 **本张合计**（该张 10 行小计之和），
  末块印 **本单合计**（整单总额）。**不做**每张都印整单总额——那会让第 1 张的合计与它上面 10 行对不上。
- **续打提示行**：非末块末尾跨 6 列、浅灰底、13px，文案
  `本张已满 10 行；因行数限制，以下内容续打在第 N 张`（N = 当前张序号 + 1）。
- **页脚（订货电话/地址/签字/备注）只出现在最后一联**：修掉旧版「9~11 行时第 2 联只剩页脚」的缺陷。
- 序号跨联连续（1..10 / 11..20 / 21..31）；跨联时每联左右版心恒 **7.30mm**，表头重复。
- 列宽按新版心重算并合计 **201.3mm**：`13 / 74.3 / 16 / 24 / 35 / 39`（原 `13/76.3/16/24/34/38`）。

**已知边界**：商品名超过约 **18 字**会折两行，那时 10 行会溢到第 2 张（实测 20 字即折行）。
门店常见品名约 13 字，安全。这是排版物理限制，不作为缺陷。

### 页脚贴表，不贴页底（用户 2026-07-14）

140mm 矮页若把 `.bottom` 设成 `position:absolute; bottom:0`，电话/地址/签字会贴在纸最下，中间大片空白——用户明确不要。

正确：

```css
.bottom {
  /* 紧贴表格下方，不贴页面底边 */
  margin-top: 2.5mm;
  /* 禁止 absolute + bottom:0 */
}
```

文档流：标题 → 明细表 → 页脚紧跟。短内容时下半页留白可以。验收时量「表格底到订货电话」≈2–4mm，不是「订货电话贴页底」。

### 墨迹边距测量（验收门）

1. WeasyPrint 写 `temp_pdf/*.pdf`
2. `pypdfium2` 渲 PNG（scale≥2）
3. 灰度墨迹 bbox → 左右边距 mm
4. 目标：L≈R≈**7.3**、|L−R|<1mm、右缘不裁、小计完整

实测（2026-10-11 修后）：逻辑页 215.9×139.7mm，L=7.23 R=6.97 差 **0.26mm**。
底部墨迹边距可远大于 6mm（内容短时留白正常，**不是**缺陷）。

## 修法顺序

1. 尺子：一联宽×高、孔边到正文。
2. 改 `@page` = 逻辑页 215.9×139.7mm + 外边距 `6mm 7.3mm`。
3. **版心占满 + 列宽合计 = 201.3mm**（用 mm，不用 %）。
4. 驱动：A4 横向、实际大小/100%、居中；关适合页面。
5. offset 仅 1–3mm 机差；默认 0。
6. 交付：PDF 路径 + 可选 PNG；重启 5001。
