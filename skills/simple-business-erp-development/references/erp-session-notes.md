# ERP 历史会话经验（已脱敏）

> 本文只保留可复用的工作流与交互经验，不保存企业名称、地址、电话、员工姓名、真实客户清单或账户凭据。当前业务事实以源码和 `docs/需求/` 为准。

## 项目与交付约定

- 唯一权威源码目录为 `本地 Windows 仓库根目录`；WSL 通过 `/mnt/d` 访问同一目录，不并行维护另一套长期主仓库。
- 项目变更需先对齐范围、验收门和交付分级；Agent 可启动预览，但必须先验证进程、端口、工作目录和浏览器实际响应。
- 业务数据与程序分离；升级前备份数据根，只替换程序文件。
- Git 推送、Windows EXE/ZIP、GitHub Release 分开核对。

## 业务数据整理经验

- 客户名称可能混有电话、门牌、项目地点、备注或近似姓名；门牌客户和同一客户的不同项目不自动合并。
- 商品名称可能有全角/半角规格、不同连接符、混合括号、品牌备注和规格顺序差异；先做轻量字符规范化，再由用户决定是否拆字段。
- 不从单据汇总表猜商品单价；只有含商品明细及数量/单价或金额的资料才适合回填价格。
- 原始导入文件只读保留，清洗结果单独输出；疑似重复先生成待确认表，不代替用户合并。
- 文档和测试使用虚构示例；不要把真实客户、员工或联系信息写入仓库。

## UI 与开单经验

- 删除行后不能让操作按钮漂移；单行删除避免无必要整页刷新。
- 避免嵌套表单；客户商品联想来自 ERP 资料，不依赖浏览器历史。
- 开单保留一行默认明细、客户价/常规价切换与清空后恢复一行等已确认交互。
- 账款汇总应保留可追溯的单据明细顺序，不要误把相同商品跨单合并。
- WeasyPrint 页脚优先稳定表格布局；HTML 预览正常不代表 PDF/纸面一定对齐。
